# V2-07 hybrid orchestration contract (HY-r1)

## Public configuration and compatibility

Extend the existing optional `PostgresRetriever` constructor with trusted configuration: Python keyword arguments `mode='lexical', embedder=None, allow_degraded=False, identifiers=True`; Node optional object with those same fields. Strictly validate option types/unknown keys. Modes are lexical, dense and hybrid. Lexical defaults retain V1 behavior exactly and reject a supplied embedder or enabled allow_degraded. Dense requires an injected EmbeddingAdapter and rejects allow_degraded. Hybrid requires the adapter and may explicitly enable fallback. No implicit adapter creation or live configuration. Only the provisioned FAKE_PROFILE is supported for dense/hybrid; another valid profile fails with EmbeddingProfileMismatch before provider/DB work. Snapshot the adapter profile at request entry and revalidate its returned batch; no mutable request configuration shared between calls.

No public wire-schema or DDL change. Request/scope parsing, output profile checks, source reauthorization, whole-chunk packing, unknown coverage and existing result ceilings remain V1 behavior. Modes are trusted constructor configuration, never agent-editable query fields.

## Selection and resource policy

A dense/hybrid retrieval performs one original-query embedding before acquiring any DB lease and under the minimum caller/request deadline measured at call entry. No retries, rewrites or parallel database operations. Require max_provider_calls>=1 before invoking the adapter; otherwise InvalidRequest before provider/lease. Fake profile has known zero model spend and never authorizes external model calls. Respect adapter input/response limits and the shared deadline/cancellation. Each invocation reserves one boundary call including failure; usage documents that convention, never claims observed transport dispatch for a predispatch failure.

One original facet/query, one attempt. Dense selects one dense list. Hybrid selects dense and lexical plus an identifier list if identifiers=true and extraction yields a token. Use only the first IF-r1 token in canonical order, not unbounded identifier fan-out. All branches use the same parsed request/scope and one read-only repeatable-read transaction. Logical branches execute serially on one runtime connection. Embedding and source release use no held candidate transaction.

Let cap=min(request.max_candidates,200), n=number of planned branch families. Require cap>=n before embedding or leasing. Allocate quotient/remainder of cap to families in dense,lexical,identifier order, each capped at40. Failed/skipped families do not donate budgets to retries. Sum candidate ceilings<=cap, so IF-r1 union never exceeds the shared ceiling. Dense uses min(cap,40). Query embedding failure still reserves the planned dense budget. No extra query is dispatched when the provider-call limit is exhausted.

Each database branch runs under a fixed-name SAVEPOINT on the same outer snapshot. The handle exposes internal candidate_branch(operation) to run one trusted branch callback serially, reject nested/concurrent branch wrappers, release on success, and rollback-to/release on exception before rethrowing. Cleanup failures propagate; a broken connection never causes a fresh-snapshot fallback. Existing task/context/busy/expiry guards and shared deadline/cancellation apply. A branch callback is internal orchestration code, not retrieved/caller query data.

## Explicit failure policy

Default: every embedding/branch failure raises. For hybrid with allow_degraded=true, only ProviderUnavailable or UnsupportedCapability from the embedding/individual branch may be recovered. Transaction/schema/scope initialization errors, InvalidRequest, UnauthorizedScope, IntegrityViolation, EmbeddingProfileMismatch, deadline and cancellation remain fatal. Source-release/packing errors always remain fatal. Roll back a failed SQL branch to its savepoint before another branch runs; never relax scope/filters or reconnect to obtain a new candidate snapshot.

An embedding failure disables dense and records unknown input-token usage; lexical/identifier still run with their original budgets. Preserve one successful list even when empty as successful execution. If no branch succeeds, raise the first recoverable error instead of returning missing evidence. Recoverable failures require execution=degraded plus degraded_search limitation; status remains partial/insufficient with coverage_unknown, never sufficient. Include fixed redacted branch diagnostics in stage_durations: embedding_complete / embedding_failed_<code>, dense_complete / dense_failed_<code>, lexical_complete / lexical_failed_<code>, identifier_complete / identifier_failed_<code>. No query/source/error text in diagnostics. Durations use monotonic milliseconds and must fit the existing schema; operation timeouts remain fatal.

## Fusion, source and output

Feed successful lists (including empty ones) to IF-r1 using list_id=family, facet_id=original, family, weight=1.0. Failed families contribute no list; explicit degraded diagnostics identify the missing path. Retain validated candidate metadata then select at most65 fused candidates; source fetch processes at most64 in a fresh transaction with the existing 16 MiB loaded-source bound. A larger fused union marks truncated_evidence. Reconstruct the chosen candidate's exact branch model in Python before source fetch; Node validates the original branch object. Preserve required filters in every candidate and source query.

Usage: attempt_count1; provider_calls1 for dense/hybrid boundary invocation (even if it fails), provider_input_tokens from successful batch.usage.prompt_tokens or null, provider_output_tokens0 (embeddings emit no text tokens); cost_usd0/cost_kind known only because this profile is synthetic. A malformed batch/usage fails, never fabricates missing accounting. Validate prompt/total nonnegative safe integers or null, total>=prompt when both present; cost must be finite known zero for synthetic, provider_calls exactly1 and synthetic true; vectors/profile use E-r1 plus dense-query validation. Lexical keeps V1 zero provider use. Context counting stays estimated and tokenizer=null; no hard model token claim.

Dense/hybrid versions: engine/policy stay existing defaults; model=fake_embedding_model_v1; index=dense_fake.v1 or hybrid_rrf.v1. Stage diagnostics declare actual selected mode/branch successes or failures. Renderer and coverage policy are unchanged. Return immutable validated output and recheck cancellation/deadline after packing.
