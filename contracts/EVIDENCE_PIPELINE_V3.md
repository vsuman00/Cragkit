# EP-r1: Post-packing assessment and optional PostgreSQL integration

Example: packing can keep the retry-limit quote while omitting its required delay quote. The emitted result must remain partial. One configured rebalance can try a different span order, but cannot recurse.

## Standalone orchestration

`pack_and_assess(query, evidence, sources, ...)` combines PK-r1 and AS-r1. Arguments use PK-r1's keyword/options bounds except `facet_evidence` (priority is computed internally), plus trusted `policy` (default null/None) and boolean `rebalance` (default false). First assess original seeds to obtain required-facet priority references. Pack, then assess only emitted evidence. If rebalance is enabled, a policy exists and required facets remain unresolved with available original references, perform at most one additional pack: prioritize unresolved facets before the others. Reassess that candidate using only its emitted evidence.

Compare candidates by required supported count, then fewer required conflicts, then emitted item count; keep the original unless the candidate strictly improves this tuple. Return the selected packed fields plus `facets`, `status`, `policy` and `rebalance_count` (attempted extra packs, zero or one). No retrieval/model retry is introduced. A dropped supporting seed or alias is not evidence: containment in emitted text is required. Validate arguments before effects and check cancellation/deadline around synchronous assessment and packing. No source normalization or database call occurs in this helper.

## Trusted retrieval configuration

PostgresRetriever adds optional constructor `evidence_options`. Absent/null keeps the previous V1/V2 behavior. A present object explicitly selects EP-r1 and has only optional fields `policy`, `counter`, `rebalance`, `surrounding_bytes`, `reranker`, `rerank_fallback`, `rerank_limit`. Defaults are no policy/counter/reranker, false rebalance/fallback, 256 surrounding bytes and rerank_limit 40 (integer 1-40). Copy trusted policy data; retain caller-owned adapter/counter resources. Malformed configuration raises InvalidRequest. Validate the query-bound assessment policy and declared output profile before a database lease or provider dispatch.

EP-r1 requires request renderer `cragkit.context.v2`. Estimated mode requires null tokenizer; strict mode requires `cl100k_base` and a supported issued counter. Counter availability and mandatory-envelope fit are checked before search. The existing request/schema/tool fields remain unchanged; constructor configuration cannot alter bound scope or required filters.

## Authorization and reranking order

Use existing bounded lexical/dense/hybrid candidate selection. A configured RerankingAdapter caps selection at the trusted rerank_limit (default 40) candidates; without it the existing 64 emitted seed cap applies. Preserve explicit truncation diagnostics. Fetch source spans with opt-in snapshots using fresh scoped authorization and verify digests before any source text is disclosed to a reranker. Close that transaction before model work. After reranking, fetch fresh authorized source spans/snapshots again in returned order, so a committed revocation/tombstone during the model call prevents release. Without reranking only one fresh source round is necessary.

All source reads share a 16,777,216-byte request ceiling, including both rounds and repeated revision fetches. Exhaustion is visible and cannot release unchecked text. Unavailable sources become stale-evidence limitations; corruption, authorization-context errors, timeout, cancellation and cleanup failures remain fatal. No scope/filter broadening or source-failure fallback is permitted. Capture retains whole seeds only while their exact serialized Evidence array fits 262,144 bytes; before reranking the aggregate query plus declared inference views must also fit 262,144 bytes. Seeds omitted by these internal input caps produce visible truncation/budget limitations, and their reads remain charged. Packing and final assessment run outside the source transaction on captured verified immutable text.

Reserve provider calls before dispatch: dense/hybrid consumes its existing one embedding invocation; optional reranking needs one remaining call. No reranker invocation occurs for empty input. Use the shared request deadline and native cancellation, including bounded invocation if an application overrides an adapter method. Validate returned reranker identity mapping and accounting before use. Optional recognized adapter fallback is explicit `execution: degraded` with `degraded_search`; preserve visible input truncation. Scores remain raw adapter scores and are not facet probabilities. This wire revision exposes model identity/stage diagnostics; full raw score mappings remain available at the standalone adapter boundary.

## Accounting and result

Provider calls include embedding and actually dispatched reranking boundary invocations, including visible fallback. Synthetic fake work costs known zero. Reranking has no processed-token accounting contract, so dispatched reranker input/output token totals remain unknown rather than zero; live cost also remains unknown. A strict spend ceiling with a live reranker raises UnsupportedCapability before any model/database operation because an enforceable upper-bound accounting interface is unavailable. It cannot silently treat a configured estimate as a hard limit.

Return the existing typed RetrievalResult with selected exact evidence/context, post-packing facets/status, declared context count/mode/tokenizer and assessed policy version. Budget/structural omissions, stale evidence, unknown/incomplete required facets and degraded execution have matching existing limitations. Add bounded stage durations for reranking and the combined pack/assessment helper: `packing_complete`, or `packing_rebalance_complete` when one rebalance was attempted. The latter measures the whole helper, not a fabricated separate rebalance duration. Model identity uses the reranker profile ID when configured; index identity continues to describe lexical/dense/hybrid selection. No public schema migration or recursive correction loop occurs.

The application still owns policy applicability, provider disclosure and final answers. Curated anchor assessment does not detect unannotated contradictions or establish truth. Final release checks cannot prevent every authorization change after the database snapshot; they prevent reuse of a pre-model snapshot as final authorization.
