# Qdrant publication and managed repair

Revision `QW-r1`, the V5-04 execution boundary. This extends [QD-r1](QDRANT_V5.md), [QC-r1](QDRANT_CANDIDATES_V5.md) and [QS-r1](QDRANT_SOURCES_V5.md). The [publication scenarios](fixtures/qdrant_publication.json) and [native fault matrix](../docs/qdrant-publication-acceptance.md) specify acceptance. [ADR 0004](../docs/decisions/0004-qdrant-managed-writes.md) records the restricted recovery profile.

For example, a writer can commit its dispatch record and pause before sending an upsert. A replacement cannot clear that record after a lease expires: the old writer might resume. Recovery must make its old credential unusable and finish replay of the stopped server's durable operations before a replacement writes.

## Status and supported boundary

V5-04A defines behavior; it does not implement or demonstrate publication. Dependent runtime, migration and native fault children must pass before a store advertises QD-r1 compatibility. The existing candidate and source stores retain their narrower capabilities.

The first write profile is one managed Qdrant 1.20.0 process, one durable storage directory, replication and write consistency one, server Cosine named `dense`, and optional explicit fake-profile named `sparse`. PostgreSQL 17 provides authority in the separate optional `cragkit_qdrant` schema. No pgvector, FTS, model invocation, remote model runtime or required Python service is introduced. Full QC-r1 configuration and E-r1 descriptor checks apply; real OpenAI vectors are supplied as already-computed bound E-r1 batches, dense-only.

All writers to this physical Qdrant instance participate in this protocol and use supervisor-issued immutable credential generations. Trusted out-of-band administrators are outside the concurrency model. An independently hosted endpoint, uncontrolled writer, unsupported server configuration or missing recovery controller fails `UnsupportedCapability`; configuration alone cannot assert safe write exclusion.

`optimizer_config.prevent_unoptimized` must be explicitly false and verified against the running supported configuration. A restart health response is insufficient. In pinned Qdrant 1.20.0, local shard loading calls WAL replay; the false configuration requires the full replay and synchronous flush path before load finishes. The true setting permits an asynchronous replay tail and is unsupported. Initialization and recovery verify the selected configuration and collection profile, then perform bounded exact readback before reopening writes. [Pinned shard loading and replay](https://github.com/qdrant/qdrant/blob/v1.20.0/lib/collection/src/shards/local_shard/mod.rs).

## Public manager boundary

Native Python and Node expose equivalent optional manager modules. Construction is `QdrantPublicationManager(authority, transport, config, supervisor, authorize_write)`. All dependencies are explicit and borrowed; the manager closes its own work and capabilities, never the caller's pool, transport or supervisor. Constructors and imports perform no I/O. The trusted QC-r1 five-field config is unchanged.

### Native manager dependency profile

The optional modules are `cragkit.qdrant_publication` and `cragkit/qdrant-publication`. The full in-process profile uses an explicit `PostgresQdrantPublicationAuthority(writer, recovery)` and `ManagedQdrantPublicationTransport(supervisor)`, followed by the five-argument manager constructor above. The authority borrows the actual native writer and recovery coordinator; the transport borrows the same actual initialized supervisor. There is no implicit privileged pool, writer shorthand, server startup or dependency discovery. Original constructor bindings and the recovery coordinator's exact original reconciliation verifier must match the complete configuration before initialization. Pool resources remain explicit through the existing optional PostgreSQL API. Native dependency classes may be imported from this optional module; private proof/receipt accessors are not public exports.

A publish reference is exactly `{collection, document_id, intent_id}`. Its tenant comes only from the separately bound trusted scope. The manager generates or resumes private owner capabilities; callers cannot submit or receive an owner token. Stage input is the complete native B2 `prepare_stage` shape, including original vector inputs or bound E-r1 batches. The closed result fields are `intent_id`, `operation`, `state`, `revision_id`, `generation_id`, `authority_committed`, `replica_complete`, `published` and `purge_complete`. A historical published outcome is distinct from the current active pointer and must not republish an old generation.

Each admitted public operation reserves at most one logical ledger attempt. Storage HTTP does not charge model calls or candidate reservations. Local bounded counters, journal sequence and byte ceilings still constrain storage work. All callbacks, source leases, dispatches, verification and finalization inherit the minimum of the supplied and ledger deadlines. Native cancellation propagates. Cleanup may use a small independent drain allowance, but cannot dispatch, settle or publish new work under an extended operational deadline.

The ordinary dispatcher selects the last settled dispatch of its complete write sequence for F1 verification. Its selected attempt binding is retained in the durable journal. A same-epoch prepared retry reads bounded original preparation and selected-dispatch metadata, resumes the recorded owner, issues a fresh opaque ordinary capability with the same binding, and requires fresh complete readback to reproduce the stored deterministic witness digest. It does not rewrite points, replace preparation, invent an intent or rebase a fence. A preparation from a retired epoch or credential binding remains operationally unavailable until the separately specified managed repair attestation path completes. Metadata lookup alone is not proof of completion.

After all HTTP handles close, hold the actual supervisor's exclusive `control_session` through final receipt/capability validation, fresh authorization, authority validation and preparation/publication SQL, including commit-outcome reconciliation. No lifecycle facade method is invoked in this finalization session. Obtain the session before any SQL lease and keep callbacks outside SQL. This excludes raw lifecycle and competing recovery changes until final SQL work unwinds; do not hold an SQL lease while performing HTTP or controller communication. The later native worker profile requires an explicit parent-owned equivalent, not a serialized permit or proof.

A possible HTTP send without a validated completed acknowledgment remains unresolved. A lost SQL acknowledgment may be reconciled only through the same immutable intent/dispatch identity and actual retained acknowledgment, using the original deadline. Never resend HTTP to resolve a lost SQL settlement response. A private completed-acknowledgment object and private current readback receipt cannot be replaced by a caller digest, response flag or serialized object.

This profile specifies F2a behavior. Implemented acceptance remains in the tracker. Host-assisted worker channels, cross-epoch preparation attestations, security convergence and purge remain separate dependent children.

### Native ordinary worker profile

Revision `ordinary-worker-r1` adds an optional `ManagedQdrantPublicationWorkerHost(actual_supervisor, authorize_write)`. Constructors/imports remain inert. `publish(job, ledger, deadline, cancellation, observer)` launches exactly one owned child running the fixed installed native package entry, invokes the actual public manager on an already durable stage, drains its owned resources and waits for its exit before returning the existing closed publication result. Python launches Python and Node launches Node. One active job, no queue, reconnect, adoption, arbitrary executable/module/code/SQL/HTTP executor, automatic supervisor takeover or required service is introduced. `close()` rejects new work and bounds owned-worker cleanup without closing the borrowed supervisor.

The exact job fields are `writer_pool`, `config`, `scope`, `reference`, `limits`. The writer pool is the existing validated restricted PoolConfig expressed as JSON with CA/passfile paths, never a password, DSN, driver object or supervisor-role pool. The config and scope use the unchanged full QC/trusted-scope contracts; reference is exactly collection/document/intent. The actual parent derives physical identity and captures epoch plus credential generation. The parent snapshots all inputs, enforces the original ledger's deadline, reserves and dispatches one logical attempt before the child can begin, reconciles success and abandons failure honestly. The child's ledger enforces the supplied job limits locally; it is a mirror of the same admitted operation, not an additional parent attempt or a way to renew the parent's budget. No provider or candidate charges arise. Parent ledger exhaustion prevents spawning. Relative child budgets never extend the parent deadline or assume shared monotonic-clock origins.

Use a private inherited duplex descriptor/channel and the exact owned spawn handle; no named listener or credential file. Launch only the current executable and installed package entry under a small explicit environment allowlist. Exclude Python startup/import overrides, Node startup options, PG variables, proxies and executable/argument/environment overrides. Close unused descriptors and reject attaching another process. Child output is discarded or strictly capped and never forwarded as raw errors. Source-development and installed-artifact launch are separate acceptance evidence.

The child owns a restricted writer pool, actual native writer, local ordinary controller and actual publication manager. A null-recovery authority bundle is admitted only with this privately registered controller. It initializes writer catalog/history/role checks and validates the already registered backend through the existing manager snapshot; it neither registers a backend nor discovers a supervisor pool. Recovery, physical fencing and E2 proof issuance stay exclusively with the actual parent supervisor. Existing E2 constructors remain unchanged and reject child controllers.

The fixed runtime privately registers its original controller/channel/binding; structural copies, subclasses and lookalikes are invalid. The manager, ordinary transport and F1 verifier accept only the exact actual-supervisor/registered-worker-controller union through narrow dispatch helpers. Profile and attempt freshness become awaited operations where IPC is involved. The parent retains genuine ordinary attempts and calls actual `attempt_binding` on every validation. The child creates its own opaque local attempt only after the corresponding private reply. Wire IDs route requests solely within that channel; they are neither serialized parent capabilities nor physical proof. Obtain a key only once per attempt via actual `deliver_worker_credential`. All child HTTP handles reuse that captured immutable key and are limited to the configured collection and existing bounded publication/readback routes. HTTP goes directly from child to Qdrant, without parent forwarding, redirects, implicit retries, proxy discovery or credential refresh.

F1 validates current attempt identity before readback and again after fresh SQL validation. Add an asynchronous private receipt validator and use it at every manager receipt consumption. The old synchronous accessor remains actual-supervisor-only and rejects worker receipts. Expected projections, completion capabilities, readback receipts, source/vector/SQL bodies, physical proofs and recovery keys never cross the channel. A metadata digest or diagnostic event cannot settle SQL or authorize publication.

Frames contain a four-byte unsigned big-endian length and strict UTF-8 JSON, bounded to 1..65,536 bytes before allocation. Reject duplicate keys, nonfinite values, extra fields, replay, unknown operations, trailing values and incorrect IDs. Child requests are exactly `{v,id,op,remaining_ms,data}`; replies echo the exact pending ID as `{v,id,ok,data}` or `{v,id,ok,error}` with closed redacted error codes. One pending child request, IDs start at one and increase exactly. Version is one. No retries or reconnect cache. Bootstrap alone may be chunked to preserve the existing grants scope ceiling: exact declared total/digest, up to six ordered base64 chunks of at most 48,000 decoded bytes, total at most 262,144 bytes, path strings at most 4,096 UTF-8 bytes, exact offsets and final digest checked before job decode. Other operations are not chunkable. Bound each direction to 1 MiB including bootstrap, 128 requests, eight attempts, eight write barriers/observations and one finalization interval per job.

The closed requests are `authorize`, `profile`, `issue`, `validate`, `before_write`, `write_observed`, `finalize_begin`, `finalize_end` and `done`. Authorization compares the pinned job/scope/reference and invokes only the parent's original application callback on its original snapshot, requiring an actual boolean. Profile and validation call the actual parent supervisor. Issue retains the real parent attempt and returns its binding plus the one-time private credential. Before-write carries only attempt/dispatch/sequence/request-digest metadata. Write-observed carries actual HTTP status and immutable dispatch identity, without response body or headers. Finalize messages carry only the selected attempt identity and control-interval state. Done carries only a closed public result or safe error/cleanup outcome and is invalid before child cleanup or while finalization is held. Unknown fields are rejected.

The `F2b-wire1` payloads are: profile `{config_sha256}` returning the actual nine-field identity; authorize `{reference,scope_sha256}` returning `{allowed}`; issue `{intent_id,owner_token,epoch,dispatch_id}` returning `{attempt_id,binding,endpoint,api_key}`; validate `{attempt_id}` returning `{binding}`; before-write `{attempt_id,dispatch_id,sequence,request_sha256}`; write-observed `{attempt_id,dispatch_id,status}`; finalize-begin `{attempt_id}`; finalize-end `{}`. Barrier/observation/finalization replies contain `{}`. Done is exactly `{result,error,cleanup}` with one non-null result/error and a closed-code cleanup array; success requires empty cleanup. The observer event is exactly kind plus its barrier/observation payload. Bootstrap is `{v,job,identity,remaining_ms}`; its frames are `{v,op,total,sha256}`, `{v,op,offset,data}` and `{v,op}` for boot_begin/chunk/end. Scope/config/bootstrap equality digests hash recursively key-sorted objects in compact UTF-8 JSON; their purpose is equality, never permission or physical proof.

The optional observer receives a closed before-write or write-observed event and a privately registered `OwnedPublicationWorker` for that exact child. Its only operations are bounded pause/resume/terminate, never a caller PID/signal or generic process executor. Pause confirms the owned child is stopped; terminate reaps it before reporting success. The before-write event occurs after the actual durable dispatched marker is acknowledged/reconciled and before sending HTTP. The observer runs before its acknowledgment is queued. After consuming that acknowledgment the child sends its retained request/key with no intervening authorization/profile/validation/key-fetch RPC. This permits the real paused-old-worker fencing experiment. Local deadline/cancellation checks remain. An actual old-key HTTP 401 must be observed; stopping before a send proves less.

Channels are permanently pinned to their starting epoch and credential generation. Recovery cannot refresh an old channel, even after same-epoch physical refencing. New authorization/profile/issuance/validation/finalization fail after retirement. An already admitted before-write acknowledgment and subsequent closed write-observed/done/cleanup messages may still complete; they grant no new authority. The parent does not kill an old paused writer merely because generation changes, since the native fault test must allow its already admitted send to demonstrate actual credential rejection.

Finalization acquires the actual parent supervisor's exclusive `control_session` and validates the real selected attempt before acknowledging begin. The parent keeps that session while servicing allowed validation/authorization/end messages. Normal end follows actual child finalization unwind and callback drain. On EOF, protocol failure, timeout or cancellation, kill and reap the exact child before releasing that session. If kill/reap or callback drain cannot be established, poison the host and retain session ownership; never release a live child's publication exclusion through a generic finally/garbage-collection path. Child death alone does not prove SQL rollback or HTTP nonarrival. Preserve dispatch uncertainty and let later E2 order recovery against durable authority.

Native acceptance requires actual child manager publication and reaping, committed dispatch followed by child termination, same-supervisor recovery, paused old child actual 401, parent/channel loss refusal and no credential refresh. Fake protocol tests alone cannot complete F2b/H. Cross-epoch preparation repair remains G0/G, and the full fault matrix remains H.

`initialize(deadline, cancellation)` explicitly checks authority history/catalog/role, Qdrant version/configuration, controller capability and durable instance identity. Operations before initialization fail `IndexNotReady`. There is one active operation per manager, no queue, one deadline inherited through every callback, SQL transaction, HTTP request, verification page and cleanup. A caller retry does not reset an existing request's budget or make an uncertain mutation disappear.

The public operations are:

| Operation | Immutable input and behavior |
| --- | --- |
| `stage(change, scope, ledger, deadline, cancellation)` | Validate and snapshot one complete source/generation/member/vector change; bind a stable intent and immutable manifest; stage authority and reserve all physical identities. No Qdrant mutation. |
| `publish(intent_id, scope, ledger, deadline, cancellation)` | Resolve the existing intent; acquire document ownership; dispatch complete point writes; verify exact completeness; atomically prepare/publish under the original expected fences. |
| `repair(intent_id, scope, ledger, deadline, cancellation)` | Resolve and reconcile the same durable operation. Never invent a replacement generation, broaden scope, refresh a stale worker's credential or silently rebase expected active. Unknown dispatch requires managed recovery. |
| `update_authorization(change, scope, ledger, deadline, cancellation)` | Commit the expected current ACL/metadata replacement and changed authorization revision/epoch first; queue exact current replica convergence as durable work. It may return authority committed with replica pending. |
| `tombstone(change, scope, ledger, deadline, cancellation)` | Atomically deny all source release and advance security fences first. Vector cleanup may remain pending. This operation never waits for Qdrant before authoritative denial. |
| `purge(intent_id, scope, ledger, deadline, cancellation)` | Resolve a tombstone-bound cleanup intent; settle all old writers, delete only globally claimed exact physical IDs, and verify scoped absence. Preserve required retained claims and the security tombstone. |

Every change contains a stable caller-supplied `intent_id`, full tenant/collection/document target, action kind and expected `authorization_revision`/`mutation_epoch`. Stage additionally binds `expected_active_generation_id` (including explicit null for first publication), immutable revision/generation IDs, canonical bytes/locator/parser, chunker identity, full profiles and every member/span/vector. Its required `initial_authorization` field is null for an existing document, or a complete trusted initial authorization/metadata value for creation. That initial value is bound to the stage intent, never inferred from source text. Creation must atomically require document absence or reconcile a document created by the identical recorded intent. A changed initial ACL is a changed intent payload, even though later current replicas remain mutable. A null initial value requires an existing document; stage never replaces its authorization. Missing versus null is validated explicitly; unknown fields are rejected.

The application binds the existing `authorize_write(scope, collection, document_id)` async callback outside agent-editable input. Its result must be an actual boolean. Pass a freshly validated trusted scope and the immutable scoped target, preserving the existing indexer callback signature. Call it before initial authority admission and again before each new external mutation and publication CAS. Await it outside an SQL transaction; the following transaction must compare the authority fences observed for that attempt. A true callback does not override RLS, a tombstone or a changed fence. False is `UnauthorizedScope`; malformed results are `InvalidRequest`; unknown callback failures are redacted `ProviderUnavailable`.

Stable intent lookup is fully scoped. Reusing an intent ID with a different action or immutable payload digest is `IntegrityViolation`; do not allocate another revision or silently adopt the new input. A matching completed retry resolves its durable outcome after fresh write authorization. A lost SQL acknowledgment is reconciled by reading that same identity, not by assuming rollback or issuing an alternate operation.

Results contain the scoped intent ID, operation, durable state, revision/generation identity where relevant, and explicit `authority_committed`, `replica_complete`, `published` and `purge_complete` booleans. An authority change with replica pending is not reported as a failed revocation or a completed replica mutation. Do not expose source bytes, keys, owner capabilities, raw SQL/HTTP bodies or exception text. These are write diagnostics, not retrieval coverage estimates.

### G1a: Native managed repair

The public native manager adds `repair(reference, scope, ledger, deadline/options)`, with exactly the same `{collection, document_id, intent_id}` reference as publish and the existing closed result with `operation="repair"`. This initial repair profile requires the exact three-migration attestation authority and actual native recovery/controller pair. Worker controllers reject repair before callbacks or I/O. The consuming application supplies trusted scope as before; callers cannot supply recovery IDs, owners, credentials or proofs. One repair reserves one logical attempt and retains the original deadline/cancellation. Public publish behavior remains unchanged.

A private writer `preflight_repair(context, deadline/options)` checks the attestation profile, locks backend then owner then document using the established READ COMMITTED order, reads the original stage intent/fences and bounded graph, and returns exactly `{intent, owner, backend, pending}`. It preserves terminal history, persists current `denied`/`conflict` outcomes before dependent repair and never acquires/replaces an owner, advances an epoch, settles a dispatch or proves physical completion. It permits inspection while blocked or uncertain; that inspection does not permit an ordinary write. Normal writer permission checks still apply to every lease.

For an open settled staged/writing target, repair shares the existing private ordinary publication body without nesting public operations or reserving a second ledger attempt. After actual fencing, complete readback, retired settlement and reopening, an uncertain writing target may repeat that bounded ordinary complete-point sequence with the same owner and intent to establish a current durable dispatch binding. This verified idempotent replay is not sent before settlement. The no-point-resend guarantee applies to prepared/attestation/COMMIT retries. A prepared target preserves its recorded same-intent owner. Missing/foreign ownership is unavailable. For uncertainty, a blocked backend or a prepared owner behind the open epoch, use actual E2 recovery, advance only the recorded target owner, verify the full current target through the original reconciliation verifier when target uncertainty exists, settle only retired work, and reopen only through E2. Foreign uncertainty leaves the instance blocked; repair never invents another document's scope. A genuinely incomplete readback remains an error and blocked state until the separately implemented recovery-write dispatcher can complete it.

For a new recovery, the private stable identifier is `g1-` plus SHA-256 of compact UTF-8 JSON `["cragkit.qdrant.repair-recovery.v1", instance_id, String(starting_epoch)]`; a blocked backend always resumes its recorded recovery ID. For a missing current attestation, the verification identifier is `g1-` plus SHA-256 of `["cragkit.qdrant.repair-verification.v1", instance_id, intent_id, owner_token, String(current_epoch), credential_generation, manifest_sha256]`. An existing exact attestation reuses its verification identifier and requires its credential generation to remain current. A same-epoch refence cannot replace that immutable row or allocate another owner to evade it; this slice returns unavailable.

After recovery, prepared repair obtains actual current ordinary F1 readback under the same owner and original generation. Within actual controller finalization it reauthorizes, validates the fresh projection, appends or confirms the exact current attestation when required, and publishes under original fences. Same-epoch original preparation uses its existing selected binding and witness. No source, generation, preparation or expected pointer is replaced. Lost COMMIT acknowledgment uses exact durable confirmation without point resend. Interrupted repair preserves the previous active generation. This slice does not complete partial-write recovery, security replica convergence, tombstone/purge or the full fault matrix.

### G1b-B1: Session-owned recovery transport

The existing actual supervisor control facade gains only `issue_recovery_attempt(proof, binding, deadline/options)` and `recovery_transport_for(attempt)`. These are native supervisor operations, not worker IPC or public manager inputs. The facade admits only genuine current recovery proofs and attempts issued through that exact live facade; an earlier facade or raw recovery attempt cannot supply its transport. Existing raw controller mutation/attempt/transport APIs remain unavailable while a control session is held. Ordinary attempts cannot use this extension.

A facade transport retains its issued immutable key and private session token, checks the token and current proof/attempt before each new request, and becomes unusable after the facade expires. Route/body/response bounds and registered-collection checks remain unchanged. It grants no source scope or SQL settlement permission. At most eight facade handles may be live at once; closing a handle frees its slot.

Every started facade HTTP request participates in the actual controller session's drain tracking. On callback return, failure or cancellation, reject new work, drain started requests through actual unwind and close all facade-owned handles before releasing exclusion. Late inherited/unawaited work must fail on the expired token. Never release a still-running request solely because a deadline wrapper returned. Cleanup failure remains an error; borrowed unrelated handles are not adopted or closed. No credential delivery, generic callback executor, ordinary admission refresh or raw key accessor is added. SQL reservation/recovery publication remains a separate dependent implementation.

### G1b-B2a: Missing-only inspection and shared verification bytes

Recovery replay must not follow an undifferentiated `IntegrityViolation`. A bounded private missing-only inspection validates every present requested point's exact immutable identity, full profile, current payload and vector, then enumerates the complete scoped generation without ID/profile filters. It permits missing expected IDs only; unknown/duplicate points, wrong vectors/payloads, malformed or repeated offsets, inconsistent GET/scroll membership and missing EOF remain errors. The exact GET-present set must equal the enumeration-present set. A tombstoned target is unsupported by this stage-repair inspection. Its returned sorted missing IDs are diagnostic data, not a full readback receipt or permission to settle/reopen/publish.

The strict existing readback path retains its original behavior. Both paths share one bounded implementation where practical, with at most eight IDs per request, 64 expected members, nine enumeration pages, 17 calls per pass, one MiB per response and eight MiB aggregate verification bytes across all passes of a logical manager operation. Every pass receives the same internal `VerificationBudget` where the manager performs multiple verification phases. The budget has a fixed 8,388,608-byte ceiling, no configurable reset/extension and monotonically charges returned bytes before parsing. Each transport receives the smaller of its per-response maximum and the remaining shared bytes. A zero or exhausted allowance cannot become missing-only success. A malformed response still consumes its observed returned bytes.

The first child adds the budget and missing-only reader in each reconciliation module, with strict-path and shared-budget tests. A dependent child wires the same budget through ordinary F1, recovery verification and the public manager; until that wiring is verified, the existing multi-phase repair counter reset remains an open resource-bound finding. Neither child alone completes recovery mutation or G1b.

### G1b-B2b: Proof-bound recovery dispatch

`PostgresQdrantRecovery.dispatch_stage_recovery(proof, context, authorize, deadline/options, budget?)` is an internal native stage-repair operation. It charges no additional logical ledger attempt. The authorization callback has the existing async `(scope, collection, document_id) -> bool` shape, runs outside SQL, and is checked before each new mutation. Cancellation/deadline is latched after every business await; a callback cannot suppress cancellation and permit later work. In the direct Node helper, a bounded-out application callback is detached: its late result cannot resume dispatch, and late rejection is observed. This does not terminate application code or revoke independently held caller authority. Private plan lifetime is invalidated and the actual session still drains all admitted privileged work before releasing exclusion. Public-manager finalization drainage is unchanged. Python cancellation-suppressing application code can delay actual unwind; no cross-runtime hard termination guarantee is made.

Only exact advanced same-intent owners and writing/prepared stage intents are admitted. Check current blocked physical identity, recovery ID, epoch, original security/pointer fences and the bounded immutable graph. Use the B2a inspector through actual session-owned recovery handles before any new reservation. Missing-only IDs may be replayed; corruption, unexpected membership and GET/scroll drift remain errors with no recovery write. No missing IDs returns zero batches/points and creates no dispatch or receipt. Preserve global foreign uncertainty. An unsettled different intent on this same document is a conflicting operation and prevents recovery replay before any upsert; inspect only bounded metadata for the already authorized document and expose no foreign intent details. Other documents remain untouched and may keep global reopening blocked after target settlement.

An opaque authorization is issued only inside that actual coordinator session. Its private registry binds the original coordinator/writer/controller, exact proof and facade attempt, trusted context, sequence, deadline/signal and active lifetime. Python also binds the current task. Internal `recovery_dispatch_authorization(value, expected_writer, deadline/options)` returns only frozen context, physical binding, attempt binding and sequence after revalidation. It provides no public factory, SQL resource, facade, key or settlement permission. A copied/raw token, foreign issuer, stale proof/attempt, expired lifetime, extended deadline or lost original cancellation signal fails before dependent work.

The writer adds `project_recovery_dispatch(authorization, context, point_ids, deadline/options)` and `validate_recovery_dispatch(plan, authorization, deadline/options)`. They validate authorization outside SQL, then read fresh blocked backend, same owner, original document fences and full immutable graph in a short writer transaction. Each plan selects exactly 1..8 claimed members of the original generation. Extract/reuse the ordinary deterministic complete-point request builder, preserving original replay seals, full profiles and current ACL/metadata. Plans bind context, physical/attempt identity, sequence, manifest/revision/generation, original expected fences, sorted IDs and immutable request bytes/hash. A private registry/accessor `recovery_dispatch_plan_data(plan, authorization, expected_writer, deadline/options)` rejects copied or wrong-issuer plans. Plans never mutate a journal or mint physical proof.

Supervisor SQL alone reserves recovery rows, using its unchanged literal role checks and READ COMMITTED wrapper. Lock backend then owner, reread fresh identity, compare all sealed plan facts and exact claims, then INSERT `recovery=true`, `operation='complete_point_upsert'`, current actual credential, next sequence, bytes/hash and all dispatch points in one transaction. Supervisor confirmation reads only permitted metadata/hash/membership, never historical request bytes, source or replay vectors. Preflight at most 257 journal rows/2049 memberships, 64 generation members, eight IDs per batch and sequence 256. Require enough sequence slots for the chosen missing batches and the subsequently required ordinary publication replay before the first recovery mutation.

Reauthorize and freshly validate the plan before committing its exact dispatched marker and before sending. No callback, controller RPC or HTTP spans a SQL lease. Send only through the bound actual facade transport. A private acknowledgment admitted from that exact completed response permits only this new dispatched recovery row to become settled with its observed digest. It cannot settle unknown current-generation rows or any other dispatch. Lost HTTP acknowledgment/cancellation preserves reserved/dispatched/unknown uncertainty. A later same-identity physical refence is required before retired settlement. Never infer that a durable reservation was unsent.

Only an actual lost COMMIT acknowledgment may enter exact-key confirmation. An absent confirmed row permits at most one same-key SQL retry; a body failure, deadline or cancellation cannot trigger blind replay. Never resend HTTP during SQL confirmation. Return only `{batches, points}` after acknowledged batches; this is not a publication, full-generation receipt, settlement of old journals or reopening. The caller must subsequently obtain actual full E2 readback, settle retired uncertainty and reopen through existing E2 before ordinary F1/preparation/publication.

Writer document reads and supervisor journal mutations remain sequential short leases under the actual session. A security change may race a send as in ordinary publication; authoritative denial stays immediate and fresh final fences prevent publication. No schema/grant expansion, raw key access, generic callback executor, old preparation replacement or owner/generation reallocation is introduced.

## Immutable source, vector and manifest admission

Snapshot native inputs before the first await. Reject custom/proxy/accessor containers at the runtime boundary; freeze nested models after validation. Preserve canonical UTF-8 bytes, including BOM, CRLF and NUL. Strict-decode the complete source, enforce its SHA-256, and verify every exact nonempty UTF-8 excerpt at its byte span before staging. QS-r1 source, locator, identity and profile limits remain in force.

An immutable generation has 1 to 64 members, with unique chunk IDs and QC-r1 UUIDs. Every member names the same fully scoped revision/generation, profiles and physical incarnation. Input vectors must be finite, correctly dimensioned and valid under their declared profile; matching dimensions alone never establish identity. Sparse indices are sorted unique uint32, at most 16, with positive finite float32-representable values. No automatic sparse encoder, BM25, provider call or normalization hidden behind a profile ID is permitted.

### B1: float32 codec and seal

Internal pure helpers are `encode_dense(vector, profile)`, `encode_sparse(indices, values, profile)`, `verify_dense_readback(expected, observed)` and `verify_sparse_readback(expected, observed_indices, observed_values)`. Encoders return immutable canonical components, sealed bytes and `input_sha256`; verifiers return no value on success and raise `IntegrityViolation` on failure. They perform no I/O, provider work, ledger mutation or public package export. The manager's manifest admission decides whether an original real-profile input is a correctly bound E-r1 batch; the codec does not turn raw real arrays into a public ingestion route.

Expected codec objects have private process-local provenance. Deserializing their fields does not recreate that provenance. Durable intents must preserve the original admitted numeric inputs together with their canonical seals; B2 freezes their portable replay serialization. After restart, revalidate and encode the original input, then compare the recorded canonical seal before using the newly issued expected object. Do not re-admit only the rounded values: an accepted original component such as `1.00099999` can round beyond the original E-r1 norm boundary. This rule does not add a public restore bypass.

First validate the ORIGINAL dense input using existing full E-r1 profile, dimension, finite-number and norm rules (including 0.001 tolerance). Validate original sparse input using the exact QC-r1 fake sparse profile. Reject booleans, numeric strings and malformed containers. Round each component once to IEEE-754 binary32, nearest with ties to even. Reject conversion overflow/nonfinite output and a nonzero original value that rounds to zero. Preserve representable subnormals; canonicalize either signed zero to positive zero. Do not perform another 0.001 norm check after rounding or silently change E-r1 adapters.

At this native codec boundary, dimensions and sparse indices use semantic integer values: finite integral Python floats and integers have the same meaning as an integral Node number within the declared range. Booleans are rejected. Canonical indices are unsigned integers, including positive zero. This does not change the protected QC-r1 search-input parser.

`U32(n)` is exactly four unsigned little-endian bytes. `F32(x)` is exactly four binary32 little-endian bytes after the conversion above. `FRAME(b)` is `U32(len(b)) || b`; lengths count bytes. `UTF8(s)` is strict UTF-8 without BOM or normalization. `||` means byte concatenation. Names are exactly ASCII `dense` and `sparse`.

The exact dense profile field order is `profile_id`, `provider`, `model`, `dimensions`, `tokenizer`, `normalization`. The exact sparse order is `profile_id`, `encoder`, `model`, `revision`, `vocabulary`, `preprocessing`, `weighting`, `corpus_statistics_revision`. No extra fields are admitted. Encode each profile value as its existing string, except dimensions as canonical unsigned decimal ASCII. `PROFILE(p)` is `U32(field_count)` followed in that order by `FRAME(UTF8(key)) || FRAME(UTF8(value))` for every field.

The dense seal bytes are exactly:

```text
ASCII("cragkit.qdrant.vector.v1") || 00
|| FRAME(ASCII("dense")) || FRAME(ASCII("dense"))
|| PROFILE(dense_profile) || U32(dimensions)
|| F32(x[0]) || ... || F32(x[dimensions-1])
```

The sparse seal bytes are exactly:

```text
ASCII("cragkit.qdrant.vector.v1") || 00
|| FRAME(ASCII("sparse")) || FRAME(ASCII("sparse"))
|| PROFILE(sparse_profile) || U32(nonzero_count)
|| U32(index[0]) || ... || U32(index[nonzero_count-1])
|| F32(value[0]) || ... || F32(value[nonzero_count-1])
```

The two framed strings distinguish vector kind and physical vector name, even though they match in this reference profile. `input_sha256` is lowercase SHA-256 of these complete bytes. It binds the canonical submitted content, including full profile and named branch. It is not a hash of arbitrary JSON or a promise that Cosine stores those same bytes. Absent sparse has no seal, represented as null in manifests; do not hash an invented empty sparse vector. Bound each profile string before copying/encoding to at most 1,024 characters and 1,024 UTF-8 bytes, and keys to 256 characters/bytes. The supported full descriptors are much smaller. Dense dimensions are exactly 1,536; sparse has 1 to 16 entries with sorted unique uint32 indices and positive float32 values.

For dense readback let `x` be canonical submitted binary32 components converted exactly to binary64. Compute `s` with an explicit loop initialized to positive binary64 zero, performing `s += x[i]*x[i]` in ascending component order, then `u[i] = x[i]/sqrt(s)`. Do not use Python built-in `sum`, `math.fsum`, SIMD, dot-product helpers or reassociation. Canonicalize observed components to binary32 with the same finite/underflow/zero rules, producing `y`. Require the exact dimension and name; then require all three bounds with fixed `T = 0.0002 - 0.000000000002`:

```text
for every i: abs(y[i] - u[i]) <= T*abs(u[i]) + 2**(-126)
abs(sqrt(ascending_binary64_sum(y[i]*y[i])) - 1) <= T
sqrt(ascending_binary64_sum((y[i]-u[i])*(y[i]-u[i]))) <= T
```

Every sum above uses the same explicit index-ordered binary64 loop. The fixed guard is part of the rule; implementations must not loosen it. This intentionally admits only a bounded equivalence class around normalized expected content, rather than exact dense stored-bit identity. Differences inside that class are accepted; wrong vectors outside it fail, even at matching dimensions/profile. The component bound prevents a norm-only substitute. Signed zero is semantically canonical. Sparse readback requires identical sorted indices and exact canonical float32 value bits. Malformed input is `InvalidRequest`, an input full-profile contradiction is `EmbeddingProfileMismatch`, and any malformed/mismatching readback is `IntegrityViolation`.

## Ownership, dispatch and publication

Intent states are `staged`, `writing`, `prepared`, `published`, `conflict`, `denied`. Security/cleanup actions also retain their explicit durable pending/complete outcome. `conflict` and `denied` cannot be rebased in place into a publication of different data. Dispatch states are `reserved`, `dispatched`, `settled`, `unknown`.

1. Validate/snapshot the full request; authorize; bind or reconcile intent, immutable source/members and every global claim. Incomplete staging remains unpublished. A same-ID revision/member mismatch is corruption, not a repair opportunity.
2. Acquire the per-document owner token with a short CAS. Verify backend admission open, current epoch, expected active, current authorization fences and no tombstone. A successor cannot acquire while any predecessor dispatch is unresolved, regardless of lease expiry or process timeout.
3. Reauthorize outside SQL; open a short transaction that checks owner/epoch/fences and commits a `reserved` dispatch before every Qdrant side effect. Bind the complete request digest and exact claimed IDs to an immutable credential generation. Only after commit acknowledgment is reconciled may the HTTP request begin. A later `dispatched` marker is informative; the crash gap means reserved is uncertain too.
4. Send a bounded complete point upsert, never a partial named-vector replay. Include exact immutable QC-r1 payload plus current authority ACL/metadata. Require `wait=true`, a strictly validated completed acknowledgment and exact readback. Accepted/queued responses, readback without known completion, canceled requests and unknown acknowledgments cannot settle a dispatch. No implicit SDK retry or redirect is admitted.
5. Verify the full generation with bounded scoped readback, all named vectors and full payload. Match exact member IDs, profiles, digests, spans and current replicas, reject duplicates/unexpected members and reach end of enumeration. Counts alone are insufficient. A mismatch never adopts the backend's values into the intent. If a current fence changes during verification, stop without publication.
6. Commit preparation only under the same owner, backend epoch and document/security fences, with no unresolved journal entry. Preparation remains invisible to new source fetches.
7. In one short final transaction, compare the original expected active pointer, owner token, epoch, authorization revision/mutation epoch, tombstone=false and verified preparation; atomically set new active/published facts and the intent's publication outcome. Clear the prior generation's current published flag while retaining its ever-published fact. Make no Qdrant call in this transaction. A stale CAS becomes `conflict` or `denied`, never overwrites a newer active generation.

On a failed/lost CAS acknowledgment, read the same durable intent and pointer. A committed outcome resolves success without a second publication. A read-only verification cannot prove a paused old request will not arrive later; uncertain dispatch remains blocked until the managed recovery protocol settles it.

## Managed recovery and controller ownership

The application supplies a borrowed exclusive supervisor that outlives all writer/coordinator processes. It alone owns server lifecycle, durable directory identity and write-key rotation. Its implementation is native or application-injected in each runtime; npm does not depend on a Python HTTP server. It issues opaque per-attempt capabilities bound to instance, recovery ID and epoch, with private identity validation. A dictionary, boolean, PID supplied by an untrusted caller, serialized token or `drained=true` is not a capability.

The supervisor is a trusted safety boundary. A paused predecessor controller must not retain authority to stop/restart the successor's process. There is no automatic supervisor takeover based on SQL lease expiry. If the supervisor dies or its exclusive ownership cannot be established, admission remains blocked until explicit out-of-band recovery establishes that old controller execution cannot resume. This reference profile recovers writer/coordinator crashes while the supervisor survives; it makes no automatic supervisor-crash recovery claim.

Recovery is instance-wide:

1. Atomically enter `recovery_blocked`, advance the admission epoch and quarantine all old-epoch document owners and unresolved dispatches. No new vector mutation may dispatch anywhere on that instance. Revocation and tombstone authority transactions remain available.
2. The supervisor retires old writer capabilities and stops/drains managed writer executions. Old transports retain their old key forever; they cannot fetch the new key through a retry, shared mutable transport or credential-refresh callback. A paused old caller after its last epoch check is explicitly included.
3. Stop the exact owned Qdrant process and observe its exit. Close old connections. Rotate the write credential in private configuration, restart the same durable directory under a new process identity and supported `prevent_unoptimized=false`, and establish completed load/WAL replay, not just a successful health probe.
4. Probe an actual mutation endpoint with the old key and require denial; the probe cannot mutate a foreign point. The fresh key is available only through current supervisor-issued capabilities. In the pinned single-key profile, the retired key is invalid and must receive HTTP 401; it must not silently retry with the fresh key. Qdrant 1.20 maps an invalid API key to `Unauthorized`, while a recognized credential lacking permission can receive 403. The E1 native run observed the retired key's 401. [Pinned credential validation](https://github.com/qdrant/qdrant/blob/v1.20.0/src/common/auth/mod.rs), [HTTP status mapping](https://github.com/qdrant/qdrant/blob/v1.20.0/src/actix/auth.rs).
5. With the gate still closed, reconcile every quarantined intent/claim/dispatch against exact current stored points. Unknown old effects may have completed and replayed; never rewrite history as a proven unsent request. Reconstruct desired complete points from immutable manifests and current authority, or delete only exact owned tombstoned debris. Journal any recovery mutation before dispatch under the new attempt capability.
6. Verify exact repaired sets, current payloads and purge absence as applicable. Conditional authority settlement records the supervisor attempt, old/new epochs, reconciled manifests and outcome. Reopen admission only after all instance-wide uncertainty is resolved. A failed deadline, controller step or reconciliation leaves the instance blocked and resumable under the same durable recovery identity.

The supervisor's private completion capability is an in-process authority object, not a reusable public proof. Native acceptance must verify actual process/key/storage behavior and manager-crash resumption. No fixed sleep, heartbeat expiry or operator assertion replaces those observations.

Each request passes the smaller of the per-response ceiling and remaining aggregate allowance into the streaming reader; reaching zero prevents another dispatch.

### E2b: durable recovery and private admission

The internal `PostgresQdrantRecovery(resource, config, supervisor, verifier)` borrows a restricted supervisor pool, the actual native controller and its constructor-bound verifier/authority. Explicit `initialize` checks the exact authority profile and registers or verifies the actual instance/storage/supervisor identity. Every lease checks the fixed supervisor role and literal effective table/column/helper grants. Supervisor SQL can read operational metadata; it cannot read source, replay vectors, intent bytes or historical request bodies. It never invents trusted document scopes.

`recover(recovery_id, deadline)` closes ordinary issuance, commits the instance gate before native fencing, and reuses an already blocked recovery identity and epoch. `advance_owner(proof, context, deadline)` advances only the exact existing owner token/intent to the proven epoch. `settle_retired(proof, receipt, deadline)` revalidates the private E2a projection before taking the supervisor lease, preflights every unsettled target-stage dispatch and its complete claimed membership, then settles only retired credential generations. An unknown request using the current generation is operationally unavailable even after exact readback. Another physical fence under the same durable recovery identity retires that generation without advancing the blocked SQL epoch. A fully settled retry returns zero; no partial preflight failure commits settlement.

Each whole coordinator operation holds a supervisor-owned exclusive control session across SQL, native work and handoff. Its private facade carries an expiring token for gate/lifecycle calls. Nested or competing coordinators cannot join; raw mutations in the owner callback or inherited sibling context, and expired facades, are rejected. Admission also rejects a preexisting native lifecycle operation. Started asynchronous facade work drains before token release, and native timeout/cancellation retains ownership through actual unwind. This local sequencing permission proves neither physical fencing nor SQL settlement. It does not replace either private proof.

`reopen(proof, deadline)` seals recovery issuance and closes host transports before SQL checks that no unsettled journal remains anywhere in the instance. It commits the open state under the backend lock, then uses a single-use controller/barrier-bound SQL settlement capability to reopen native ordinary admission. Unknown commit acknowledgment leaves native admission sealed until an exact same-identity read confirms the committed state; no blind mutation retry is allowed. A sealed same-proof barrier supports that retry. Copied SQL completion tokens are `UnsupportedCapability`. Close the coordinator before its borrowed pools/controller; an external controller close cannot race a held session.

Recovery does not publish a stage, complete a later security intent, clear current-credential uncertainty by assertion or adopt a dead supervisor's directory. Unavailable document scopes and unsettled foreign/current-generation work keep admission closed. Existing public controller operations remain usable outside a held control session, within their established E1 profile.

## Resource and error contract

Profile ceilings are 64 members per generation, eight points per write/readback page, 256 dispatch attempts per intent, 1,048,576 response bytes per HTTP request and 8,388,608 aggregate verification response bytes per operation. Shared ledger admission may make these smaller. Enumeration must reserve enough to detect an unexpected 65th member and require EOF; an exhausted page/byte budget cannot become complete. Offsets, repeated offsets, duplicate points, malformed JSON and depth/node bounds are validated before release. Source/excerpt ceilings remain 16,777,216/32,768 bytes. There are no background repair loops, unbounded retries or new provider charges.

The existing execution ledger has provider calls, candidates, attempts, tokens and spend; it has no storage-HTTP call or byte allowance. Storage HTTP never consumes `provider_calls` or search `candidates`. Charge at most one shared logical attempt for an admitted public manager operation, and only when the outer caller has not already reserved that same logical attempt. Individual HTTP dispatches and verification pages consume separate local bounded counters and durable journal slots, not extra logical attempts. Reconcile actual model usage only if a genuine model operation exists; this manager makes none. An already-computed E-r1 batch adds no provider usage. Local storage counters charge dispatched requests/observed bytes honestly even on partial or canceled I/O; only undispatched local admissions can be abandoned. Admission failure before dispatch creates no HTTP side effect; after dispatch it preserves durable uncertainty. The original shared deadline governs both kinds of accounting.

| Failure | Required result |
| --- | --- |
| Malformed native shape, IDs, span input or unsupported operation option | `InvalidRequest`, before I/O where locally decidable. |
| Unsupported server, control capability, profile or authority history/catalog/role | `UnsupportedCapability`; never downgrade the write profile. |
| E-r1 batch/profile contradiction at admission | `EmbeddingProfileMismatch`; response/authority immutable contradiction is `IntegrityViolation`. |
| Claim collision, same-intent changed payload, full-set/vector/payload mismatch | `IntegrityViolation`; no adoption or publication. |
| Fresh authorization false or revoked scope | `UnauthorizedScope`/durable `denied` as appropriate; authoritative denial remains committed. |
| Changed expected active or nonsecurity fence | Durable `conflict`; no automatic rebase. |
| Shared deadline/caller cancellation | `DeadlineExceeded`/native cancellation; preserve unknown dispatch and bounded cleanup. |
| Authority, transport, controller or cleanup operational failure | Redacted `ProviderUnavailable` or established cleanup failure; no ordinary empty success. |

Known errors are recreated with fixed safe messages; unknown subclasses and raw chains cannot leak source, credentials or SQL. Close rejects new work, bounds cancel/drain, preserves unresolved durable work and never reports a canceled external write as undone. One failure to test is cancellation after dispatch followed by tombstone: source access stays denied while cleanup remains pending until the old credential and server effects are settled.
