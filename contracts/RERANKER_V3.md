# V3-01 reranker boundary (RK-r1)

Status: documented contract for the next adapter slice; no runtime implementation or real model selection. See the [policy and shortlist](../docs/decisions/0002-reranker-policy.md), [V3 plan](../tasks/versions/V3-evidence-quality.md) and [recorded fixtures](fixtures/reranking.json).

For example, scores `-2.5` and `1.25` from a higher-is-better profile order the second candidate first. Neither number measures source truth. A rank orders candidates; a logit is an uncalibrated model output; a calibrated decision needs separately reviewed labels and a versioned policy. RK-r1 adds no relevance threshold or sufficient-coverage decision.

## Injection and identity

The first implementation target is an optional injected fake/recorded reranker in each native runtime. Construction/import must not discover credentials, download assets, import a required model runtime, contact a provider or start a Python service. The application owns any transport, worker and model assets. Real local/API adapters require explicit configuration, model selection and disclosure policy; this contract authorizes none of those actions.

Snapshot trusted immutable configuration at request entry. Record `profile_id`, `provider`, `model`, `model_revision`, `score_kind`, `score_direction`, `preprocessing_revision` and `truncation_policy`. Require each identity/configuration string to be a nonblank scalar string of at most 256 UTF-8 bytes and `score_direction` exactly `higher_is_better` or `lower_is_better`. Scores are raw finite real numbers, excluding booleans, strings, NaN and infinity. Do not sigmoid, normalize, round for sorting or rename scores as truth probabilities. A hosted mutable alias uses `model_revision=mutable_alias:<identifier>`; it cannot claim an immutable weight revision. The revision field remains nonblank, so absent immutable identity is explicit rather than invented. Concrete profiles must declare their tokenization, prompt/template and revision identity before use.

The development profile is `fake_reranker_v1`, provider `fake`, model `synthetic-recorded-reranker`, revision `synthetic-r1`, score kind `synthetic_raw_logit`, preprocessing `utf8-prefix-r1`. It has known zero model spend because no inference or network call occurs. Its responses are hand-authored illustrative records, not observations from any shortlisted model.

## Bounded inputs and source ownership

Use the original question and one ordered, already authorized candidate list. RK-r1 has no facet expansion, retry, query rewrite or multi-hop behavior. Required filters/scope and candidate source metadata are orchestration-owned and cannot be edited by provider output. Release the candidate database transaction before reranking. Before any model disclosure, obtain inference text through an authorized immutable source fetch and verify its digest and spans; metadata-only candidate authorization does not authorize disclosure of unchecked text. Release that source-fetch lease before invoking the reranker. Reauthorize and verify immutable source digests/spans again at final source fetch as before.

Trusted development limits are: at most 40 candidates; query at most 8,192 UTF-8 bytes; each candidate inference view at most 16,384 UTF-8 bytes; total query plus candidate inference text at most 262,144 UTF-8 bytes; candidate ID at most 512 UTF-8 bytes; response at most 65,536 bytes. Empty candidate lists return an empty ordering without invoking the provider. Reject duplicate/empty candidate IDs, malformed UTF-8 and invalid configuration before dispatch. IDs are opaque strings. Runtime field/schema names remain for V3-02 to specify; this document does not change the public result schema.

A caller must select at most 40 candidates in their existing fused order before this boundary; the adapter rejects oversized batches rather than silently dropping candidates. Record original, selected and omitted counts when the upstream union exceeds the cap. The total byte ceiling includes every inference text and query; exceeding it fails before dispatch. Count actual provider serialization separately if a concrete transport adds overhead; these text-byte caps do not claim a model-token ceiling.

Default `truncation_policy=reject`: an oversized query or passage fails. Explicit `utf8_prefix` may shorten only the inference view of a candidate, ending at the largest complete UTF-8 code point within its per-candidate limit. It never truncates the question, bypasses the total cap, changes stored source text or edits returned excerpts. Record each affected ID, original/view byte counts, policy/revision and any provider-reported token truncation. Preserve those diagnostics even when ranking succeeds. Concrete adapters must disable hidden tokenizer/provider truncation or expose and validate it; unknown truncation behavior is unsupported. A source's negation may lie after the inference prefix, so truncation is a limitation, not evidence of equivalence.

## Complete mapping and deterministic ordering

A response contains exactly one `{candidate_id, raw_score}` for every submitted candidate, in any order. Reject missing, duplicate, invented or malformed IDs and malformed/nonfinite scores before using any result. Partial top-N responses are unsupported: request complete scores or reject that provider configuration. Bound response bytes before parsing, reject unknown boundary fields, and revalidate injected/constructed objects rather than trusting nominal types.

Sort by raw score in the declared direction. For exactly equal scores, preserve submitted candidate order; do not use response arrival order or locale-dependent collation. Preserve the original rank and raw retrieval scores separately. Sorting must not mutate candidate identity, immutable revision, digest, offsets or excerpt bytes. Source fidelity and relevance remain separate checks. Cross-runtime fake fixtures require exact output ordering; real-model tolerance and quality evaluation remain separate work.

## Deadline, usage and failure

Use the minimum caller/request monotonic deadline across queueing, preprocessing, transport/worker execution, response validation and sorting. Check cancellation/deadline before dispatch and after awaited work, and stop new work on expiry. CPU inference must use a bounded nonblocking worker with bounded admission and cleanup; hard worker termination and responsiveness need actual V3-02 tests. A cancelled HTTP call may still incur charges. Do not turn timeout/cancellation into empty evidence.

Reserve one shared provider-call slot before each boundary invocation, including a failed invocation. The existing embedding invocation consumes the same request allowance; reject exhausted allowance before work. RK-r1 permits one rerank invocation and no internal retries. Count input/output tokens and cost as known only when the selected profile supplies valid accounting; unknown is null/unknown, never zero. A strict spend/token budget rejects a profile without a computable upper bound. Recorded synthetic use is labelled synthetic with known zero model spend; it does not establish actual provider billing or token usage.

Default failure propagates a typed error. Explicit trusted unreranked fallback may handle only unavailable/unsupported reranker capability, retaining the bounded pre-rerank order with `execution=degraded` and a visible reranker-fallback limitation. Validation, integrity, authorization, invalid mapping, exhausted budget, deadline and cancellation failures remain fatal. No failure may relax permissions or become a missing-evidence claim. Fallback does not improve coverage, and unknown coverage cannot become sufficient. Exact integration error/diagnostic identifiers are a V3-02 contract decision; public wire changes require their own reviewed slice.

## Recorded compatibility evidence and remaining work

The fixture records synthetic inputs, complete score responses and expected mechanical outcomes. It covers raw negative scores, both directions, ties, reordered response rows, empty input, missing/duplicate/unknown IDs, invalid score types, and opt-in UTF-8 inference-prefix truncation. Nonfinite JSON values are described as rejection cases rather than encoded as invalid JSON. Cap, deadline, cancellation, worker, serialization and fallback cases are declared requirements for executable V3-02 tests, not passed runtime results.

A fixture inspection can establish coherent data and expected ordering only. It cannot establish model quality, tokenizer compatibility, latency, peak memory, live API behavior, runtime parity or cancellation behavior. No held-out labels or private text belong in this development sample. The final integrator records actual commands and compatibility/resource observations in the task report. Next: implement the smallest native fake/recorded boundary and its shared mapping tests before any explicitly authorized live comparison.


## RK-r2 executable boundary refinement

V3-02 freezes the first native interface before runtime consumers. Python `RerankingAdapter(transport, *, profile=FAKE_RERANK_PROFILE, allow_live=False)` and Node `new RerankingAdapter(transport, {profile, allow_live})` accept caller-owned asynchronous transports. Truncation policy is part of the profile. The profile is the eight-field identity record above. Both expose `rank(query, candidates, ...)` with caller monotonic `deadline`, `max_provider_calls=1` and `allow_fallback=False`; Node additionally accepts `signal`. Each original passage is bounded to 262,144 UTF-8 bytes even when inference-prefix truncation is enabled. Allowance is an integer 0..1000. Query/configuration text is nonblank under the shared ASCII whitespace rule; candidate IDs are opaque nonempty strings. Inputs are strict candidate records with only `candidate_id` and `text`.

Transport request JSON contains `profile`, `query`, `candidates`; response JSON is the complete score-row array. Python transport receives bytes and keyword `deadline`, `max_response_bytes`; Node receives Uint8Array and options containing those plus an AbortSignal. It returns response bytes, bounded before decoding. Adapters do not select destinations or discover credentials. A nonfake profile requires explicit `allow_live=True`; denial is fatal before dispatch. This permission flag alone does not configure disclosure, accounting or an endpoint.

Return a frozen/snapshotted JSON-compatible result with exactly `profile`, `order` (candidate IDs), `scores` (validated raw rows in input order), `truncations` (candidate_id, original_bytes, view_bytes), `degraded`, `provider_calls`, `synthetic`. Empty input returns zero calls. A successful nonempty invocation or a recovered transport failure reports one reserved boundary call. Synthetic results imply no model charge; real token usage and cost remain unknown until a separately validated transport accounts for them.

Use InvalidRequest for configuration/input/exhausted allowance/concurrent adapter admission. Use IntegrityViolation for malformed provider mappings or response encoding. Only transport ProviderUnavailable/UnsupportedCapability can recover with explicit fallback; return unchanged IDs, empty scores and degraded=true. No silent fallback for validation/deadline/cancellation. An uncooperative transport can outlive the caller's deadline: the caller stops waiting and admission stays occupied until that transport settles, preventing unbounded detached work. This does not claim that arbitrary synchronous transport code or CPU inference becomes nonblocking; a CPU model requires an explicitly bounded worker path and its own verification.
