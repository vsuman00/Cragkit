# V4 execution contract

Engine identifiers in this frozen contract describe its reference fixture. Current
native release identities are defined in [Results](RESULTS.md#release-identities);
schema `0.1` and historical fixture values remain unchanged.

## EL-r1: request-local execution ledger

A ledger binds validated Limits and one effective monotonic deadline at construction. It has synchronous atomic reservation transitions with no await/dispatch inside a transition. Native event-loop concurrency is supported; Python thread sharing and cross-process quotas are not. Every provider transport attempt, including a configured retry, needs its own reservation before dispatch. SDK retries must be disabled unless each underlying attempt uses this boundary.

Public API in optional native execution modules: ExecutionLedger(limits, deadline=...), reserve(provider_calls=0, candidates=0, attempts=0, cost_upper_usd=None), dispatch(reservation), reconcile(reservation, input_tokens=None, output_tokens=None, cost_usd=None), abandon(reservation), snapshot(). Node uses new ExecutionLedger({limits, deadline}), reserve(options), dispatch(token), reconcile(token, actual), abandon(token). Constructor deadline is required; the effective value is the minimum of it and the request duration. Reconcile/abandon remain available after expiry for honest cleanup. Reservations are opaque, ledger-bound objects, returned by reserve. Snapshot keys are provider_calls, candidates, attempts, input_tokens, output_tokens, cost_usd, cost_kind, pending. Python uses asyncio loop monotonic time; Node uses performance.now()/1000. All snapshots are detached/read-only. close() is idempotent and revokes reserve/dispatch with InvalidRequest while permitting late reconciliation/abandon. Coordinators close in finally, including success, so cancellation-ignoring callbacks cannot obtain later dispatch authorization. ledger.deadline is a read-only effective monotonic deadline; provider adapters use min(call deadline, ledger.deadline). Limits use the existing request schema.

Zero resource reservations are invalid. Requested nonnegative integer counts use safe JSON integer bounds; booleans are invalid. Reservations increment cumulative admitted work before dispatch. A private module BudgetExhausted exception stops admission when max_provider_calls, max_candidates or max_attempts would be exceeded. The coordinator translates it into a visible bounded result. deadline expiry raises DeadlineExceeded; cancellation uses native cancellation. A pre-dispatch abandon refunds the reservation; dispatched work can never be refunded. reserve/dispatch/reconcile/abandon check token ownership and exactly-once state. Unknown tokens, repeated completion and impossible actual accounting fail with InvalidRequest or IntegrityViolation as appropriate.

With max_spend_usd configured, any provider-call reservation needs a finite nonnegative cost_upper_usd and cannot exceed remaining reserved spend. Without that capability, fail UnsupportedCapability before dispatch. Actual nonnegative finite costs cannot exceed the declared bound. A breach poisons further admission and raises IntegrityViolation; never silently admit more work after the breach. Known completed costs reconcile reservations; pending/dispatched unreconciled costs stay unknown. Dispatched cancellation/abandon retains call/work counts and unknown usage/cost. Candidate-only/attempt-only reservations consume no provider usage. An initially empty ledger reports known zero usage/cost. Unknown provider input/output tokens remain null after aggregation; do not convert unknown to zero. Tokens/counts/costs obey existing finite safe-number rules. Snapshot does not report reserved estimates as actual billed usage.

Verification: a shared deterministic transition fixture, final-slot task race, wrong-ledger tokens, abort-before/after-dispatch, nested transport retry reservations, cost unknown/strict rejection/overrun, deadline and native parity. Runtime tests use fake providers; no paid calls establish this contract.

## QP-r1: optional structured planning

Application-approved variants are a list (at most 16) of exact objects {facet_id, variant_id, query}; IDs obey identity rules, query obeys input Query rules. Variant IDs are unique globally. Every variant must preserve the original query's exact identifier_ascii_v1 tokens (set inclusion using the existing extractor). Variants are trusted hypotheses, not additional facts; assessment always uses the original question/policy. They never contain or replace scope, collection, filters, limits or profiles. Unknown fields are rejected. The original query runs first and counts toward max_subqueries.

validate_plan(value, query=..., variants=..., missing_facets=..., max_subqueries=...) returns a detached list of approved variant objects. value is an exact object {queries:[{facet_id,variant_id}]}; empty queries are allowed, selection length <= min(16,max_subqueries-1), no duplicates, only missing facet IDs may be selected. Every selected pair must match an approved variant. Strings, malformed JSON-as-string, forged scope/limits/queries, invented facet/variant IDs, identifier-removing variants and oversized plans fail InvalidRequest. The planner cannot invent semantic intent because it selects only preapproved variants. missing_facets is a unique list of at most 32 valid identity strings; max_subqueries is 1..16. Trusted configuration is validated even if no queries are selected.

PlannerAdapter(transport, sdk_retries=0, cost_upper_usd=None, allow_fallback=False) has async plan(query, variants, missing_facets, max_subqueries, ledger, deadline [Node signal]). Python uses keyword arguments; Node constructor and plan use option objects. transport receives a detached JSON-compatible object {query, variants, missing_facets, max_subqueries} and deadline (Node options also signal); it returns an object {plan,usage}, with usage exactly {input_tokens,output_tokens,cost_usd}, each nullable and nonnegative safe/finite. No SDK retry is allowed. Limit total serialized provider output to 16 KiB and native JSON complexity before inspecting it. Every transport dispatch reserves one provider call from EL-r1 and reconciles validated usage. On cancellation/failure abandon dispatched work as unknown. Timeout raises DeadlineExceeded and cancellation retains native semantics. Bound the outer await, even if transport ignores its deadline. Python transport is an async callable(payload, deadline=...); Node transport(payload,{deadline,signal}).

Malformed output raises IntegrityViolation; declared ProviderUnavailable propagates as retryable; other arbitrary transport exceptions become redacted ProviderUnavailable. Configured fallback handles only ProviderUnavailable or malformed plan output, returns {queries:[],fallback:true}; it does not hide deadline, cancellation, budget, integrity accounting breaches, unsupported strict cost or unsafe trusted configuration. Success returns {queries:[approved variants],fallback:false}. Empty variants/missing facets or max_subqueries=1 return empty success without a call after configuration validation. No provider/model is imported or called by core import. Routine validation uses injected fakes.

## CR-r1: corrective orchestration and trusted backend

CorrectiveRetriever(backend, policy=None, variants=[], planner=None, counter=None, batch_size=16, max_retries=0, backoff_ms=0, no_progress_limit=1). Node uses new CorrectiveRetriever({backend,...}). Backend is trusted caller-supplied code, not planner/model input. Configuration is snapshotted before await and validated; policy is AS-r1 bound to the original question, variants are QP-r1, batch_size 1..64, max_retries 0..2, backoff_ms 0..1000, no_progress_limit 1..3. Counters use existing context contract. No required provider/framework/DB import in this module.

retrieve(request, scope=..., deadline=...) [Node retrieve(request,{scope,deadline,signal})] validates/snapshots request and trusted scope, binds one EL-r1 effective deadline, requires cragkit.context.v2 output and preserves original request/filters/limits/profiles. Search attempts copy only query; assessment always uses the original question. The original query runs first. Plan only after an unresolved initial assessment, selects approved variants once, then search missing facets in selected order. Re-check current unresolved facet before each variant. Max_subqueries includes original unique queries; every search attempt (including transient retries) reserves one attempt and a candidate-work upper bound before backend dispatch. Each backend provider attempt independently reserves/reconciles ledger calls; disabled hidden SDK retries are a backend requirement. Shared deadline bounds search/capture/packing/planning/backoff even for ignoring callbacks; cancellation remains native, no background work may dispatch another call after termination.

Trusted backend methods (both async):

- search(request, scope=..., deadline=..., limit=..., ledger=...) -> {candidates:[candidate objects],degraded:boolean}. Node second argument is an options object and includes signal. Candidate objects follow existing LexicalCandidate, DenseCandidate or IdentifierCandidate shape. Reject malformed/nonfinite/oversized results, duplicate identity within a batch and tenant/collection mismatches with IntegrityViolation. Identity key: tenant_id,collection,document_id,revision_id,generation_id,chunk_id. Keep immutable first candidate per key; never add repeated candidate votes. Admission charges the upper bound for branch candidate work, not only surviving hits. Store must enforce scope and required filters on every branch; it never receives planner-modifiable authorization.
- capture(candidates, request=original, scope=..., deadline=..., max_source_bytes=..., ledger=...) -> {evidence:[Evidence],sources:[PK-r1 source snapshots],source_bytes:integer,stale:boolean,budget_exhausted:boolean}. Node options include signal. Every capture freshly reauthorizes candidate/source release and returns only authorized evidence/full sources, never cached earlier excerpts. Source_bytes reports actual loaded source bytes and is checked against a cumulative 16 MiB request ceiling across all captures. Validate returned evidence and source membership against candidate identities/collection; cap 64 retained candidates and evidence items. Exact PK-r1 source/hash/span checks and AS-r1 assessment follow capture. If a backend runs reranking, authorize before disclosure, charge EL-r1, release DB lease during model work, and capture again after the model before returning. Trust is explicit: a malicious custom backend can defeat authorization, just as a forged application scope can.

Return {result: standard RetrievalResult JSON,diagnostics:{stop_reason,queries_executed,candidate_work,planning_fallback,ledger}}. Query/source text is excluded from diagnostics. Result uses the original request_id; context is exact packed serialization, facets/limitations/status are post-pack AS-r1, usage from ledger and actual context counting, versions policy/model/index identities remain honest (actual packed AS policy identity (or unassessed.v0), engine 1.0.0-rc.1 and null model/index for unknown generic backends; no fictitious live-model name). Attempt_count from ledger; candidate work in diagnostics, not billed tokens. Merge ordinary coverage/stale/budget/degraded limitations without hiding complete vs degraded. Output profile strict tokenizer must be supported before backend work.

V4-03: retain bounded useful candidates, fresh capture/reassessment after every search, one optional packing rebalance, unchanged scope/filters, complete original/targeted synthetic recovery. Initial sufficient stops without planning. No planner/approved selections -> no_plan or coverage_unknown. Budget admission exhaustion -> budget_exhausted, return best freshly authorized current evidence with visible budget limitation. Never return an earlier pre-correction result without fresh authorization.

V4-04: ASCII lowercase + whitespace-collapse keys stop repeated queries before dispatch. Identical candidate sets or configured consecutive rounds without increased supported required facets stop repeated_candidates/no_progress after the recovery round's fresh capture. Stop reasons also sufficient, attempts_exhausted, subqueries_exhausted, plan_complete and budget_exhausted. ProviderUnavailable only may retry, up to max_retries, consuming new attempt/candidate/call slots; declared permanent InvalidRequest/IntegrityViolation/UnauthorizedScope/etc never retry. Deadline/cancellation throw, not an insufficient result. Exhausted transient retries throw ProviderUnavailable; recovery never silently reports a search failure as missing evidence. Backoff is bounded by the shared deadline. If budget runs out after a transient failure, propagate the operational error; do not convert it to absence. Detached immutable snapshots prevent mutation during callbacks.

The built-in optional PostgresCorrectiveBackend(resource,mode='lexical',embedder=None,reranker=None) [Node constructor options object] implements this contract with existing session/select/source boundaries. Lexical needs no model call. Dense/hybrid use current compatible synthetic profile and existing branch budgets/fusion; one embedding call per search gets an EL reservation before select, with zero known cost only for the synthetic profile. Reranking is optional, at most 40 authorized candidates, no lease during rank, call charged before dispatch, fresh source fetch afterward, synthetic usage known zero and hosted usage unknown (strict unsupported cost fails before dispatch). SDK retries disabled by the injected transport contract. Use default fail-closed branches; no implicit degradation. Both built-in backends parse and snapshot inputs, bound source sums and close owned task resources; the application owns the reusable pool. The backend itself never creates a pool/service or applies a migration.

## EV-r1: bounded privacy-controlled events

EventSink(exporter=None, capacity=32, timeout_ms=25) [Node options object] owns a bounded in-memory queue; capacity 1..128 and exporter timeout 1..100 ms. emit is synchronous, validates only fixed structured fields and never invokes an exporter. Applications explicitly flush outside retrieval; retrieval never waits on exporter work. Async exporter callbacks must yield; synchronous/blocking callbacks are unsupported. Arbitrary caller code cannot be made nonblocking by a promise/async signature alone.

new_trace() returns a UUID; emit(stage, trace_id=..., attempt=..., elapsed_ms=..., candidate_count=0, provider_calls=0, stop_reason=None) returns boolean. Node emit(stage,{...}) uses the same fields. Only allow stages start, search, capture, planning, retry, stop, error, cancelled. Trace IDs must be UUID strings generated per retrieval, never request/query/source IDs. event_id is trace_id plus a monotonic sink ordinal. attempt 0..10, elapsed_ms finite nonnegative <=300000, counts nonnegative safe integers. Stop reasons are the CR-r1 fixed enum (including sufficient, repeated_query, repeated_candidates, no_progress, no_plan, coverage_unknown, attempts_exhausted, subqueries_exhausted, plan_complete, budget_exhausted); errors use only the fixed typed error code (not messages) as stop_reason for error stage; native cancellation uses cancelled. Invalid fields/raw query/source/DSN/secret input are rejected. No full/raw replay mode is implemented. Events contain no raw text, digest or evidence/source relationship IDs.

snapshot() returns detached/read-only {queued,dropped,exported}; dropped includes queue overflow, exporter exceptions/timeouts and events removed without export; exported only completed deliveries. drain() synchronously returns and removes detached queued events for application-controlled inspection (not counted as exported). flush(deadline) [Node flush({deadline,signal})] processes at most the queue-size snapshot and never exceeds min(deadline,now+timeout_ms) per exporter; stop at overall deadline, drop remaining bounded events, catch exporter errors and consume task exceptions. No automatic background worker, persistent process, unbounded pending tasks or required SDK/network. A cancellation-ignoring exporter is cancelled/observed and remaining queue dropped; do not start additional exporter tasks while one remains unsettled. close() is idempotent, drops queued events and rejects later emits; cleanup remains bounded. Sink reuse across requests is allowed but caller-owned; per-retrieval trace IDs isolate association. In-process diagnostics are not a durable audit log.

CorrectiveRetriever adds optional trusted event_sink (exact EventSink type) constructor option. It creates a fresh trace per retrieve, queues start/search/capture/planning/retry/stop/error/cancelled events with elapsed time, attempt/candidate/call counts and fixed reason. emit failures/overflow never affect retrieval outcome. Diagnostic events metadata appears only when event_sink is configured as diagnostics.events {trace_id,queued,dropped,exported}; default results remain unchanged. Do not flush or close caller-owned sink during retrieval. On failure/cancellation emit terminal event then close ledger. No query/source/scope/provider output is passed to events. Exact event ordering/counts use shared deterministic sink fixtures, while runtime trace UUID/timing is excluded from result parity.

CR-r1 terminal capture admission: if fresh capture raises private BudgetExhausted before returning a validated capture, discard prior packed evidence and pack/assess empty evidence and sources under the original policy. Stop budget_exhausted with a visible budget limitation; never call capture again or start further backend/provider work. Preserve admitted charges and unknown usage. Empty output sources are not a claim that no source bytes were read. The trusted failed capture must respect its supplied remaining byte allowance, and this path is terminal, preserving the cumulative ceiling. Do not convert ProviderUnavailable, deadline, cancellation, unsupported strict accounting or integrity failures into results; an existing transient operational failure still takes precedence. This is not an unreranked fallback because no evidence is released. When candidate-work capacity is zero or 64 candidates are retained, stop synchronously before planning; the latest fresh result remains valid without an intervening provider call.

## AD-r1: optional LangChain Core tools

Select LangChain Core, pinned Python 1.7.0 and Node 1.3.0, in separate optional packages. Core manifests/imports stay framework-free. No model, agent, server or tracing service is required. Framework installation and execution are verified separately from core checks.

Factories create native StructuredTool / DynamicStructuredTool subclasses with the existing narrow ToolRequest schema. Trusted engine, collection, required filters, limits, output profile, scope and final serializer are bound outside tool arguments and snapshotted before awaits. Tool arguments cannot change them. Wrong collections and unknown scope/limit/config fields fail with redacted InvalidRequest before engine dispatch. Validate native JSON rather than silently stripping fields. Only asynchronous execution is supported. Plain arguments return a content string; native ToolCall arguments return an actual SDK ToolMessage with the validated actual name and call ID. Content is compact JSON of the validated engine result, preserving statuses, limits, evidence/citations and limitations; corrective execution diagnostics are not model content.

A required trusted final_serializer(actual SDK string or ToolMessage) returns the exact string the application will expose to its model. Recount this string after constructing the actual SDK message, including the actual name, call ID, escaping and wrapper. Strict mode requires the existing issued Cl100kCounter and cl100k_base profile. Add the bound envelope reserve and reject ContextBudgetTooSmall before returning if the configured ceiling cannot fit. Estimated mode uses the existing explicit UTF-8 byte estimate and makes no hard-token claim. Bound serialized output to 262144 UTF-8 bytes. A serializer is application-owned: generic SDK message dumps are not universal provider wire formats. Changing the model wrapper requires a matching serializer; external prompt/history tokens are outside this tool budget.

Owned invocation paths bypass framework callback dispatch and ambient configuration, establish disabled scoped tracing, and do not mutate global environment/debug flags. Reject nonempty caller callback/configuration except Node's native signal. All supported invoke/run paths funnel the same guarded boundary; internal raw callback methods and synchronous Python paths reject UnsupportedCapability. Inherited batch/stream paths must either use the guard or explicitly reject. Avoid a mutable per-request field on a shared tool. Forward native task cancellation / AbortSignal and derive each deadline from the bound request deadline_ms. Race uncooperative callbacks against the deadline, observe late failures, and do not turn operational failure into insufficient evidence. No background exporter or tracing flush is started. The host application's outer agent/callback tracing remains its own disclosure boundary.

Acceptance uses real pinned SDKs with fake engines: direct/tool result equivalence, sufficient/partial/insufficient/degraded results and typed operational failure; shared request rejection and forged scope; final serializer/oversized ToolCall wrapper; pre/postdispatch cancellation and deadline; concurrent request isolation; enabled tracing-environment secret canaries under network denial; alternate invocation paths; clean installed artifacts with source product imports excluded. No paid provider calls or model downloads establish these checks.

CR-r1 branch admission clarification: hybrid search requires at least one candidate-work slot for each mandatory branch (dense and lexical, plus identifier when the unchanged query contains an exact identifier). An originally configured total below that minimum remains InvalidRequest. A smaller dynamically admitted per-attempt allocation raises private BudgetExhausted before provider or database dispatch. Do not omit a branch to fit the allocation or charge a provider call that has not dispatched.
