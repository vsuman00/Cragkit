## Runtime packet and configuration

The exact packet fields are `revision: "EVX-r1"`, `documents`, `queries`. No labels, answerability, support spans, facets or policy enter the worker. Validate and snapshot the complete packet before database/model work. Documents (1..32) have exactly `tenant_id`, `collection`, `document_id`, `revision_id` (logical alias), `active` (boolean), `text`, `canonical_sha256`. Text is nonempty valid UTF-8, at most 65,536 bytes, and matches the digest. Each full document/logical-revision identity is unique. Each tenant/collection/document group has exactly one active revision. Queries (1..30) have exactly `question_id`, `tenant_id`, `collection`, `query`, `required_filters`. Validate with existing native request/scope boundaries; query text is at most 8,192 UTF-8 bytes and IDs are unique. Every query's tenant/collection occurs in the document packet. Cap total source/query UTF-8 bytes at 1 MiB. Unexpected fields fail before I/O.

Database configurations and tokenizer path are trusted arguments, separate from the packet. Use distinct reader/writer pools, each max_size=1; only two runtime clients. Load the caller-supplied pinned tokenizer without downloads. All scopes are application-built: the packet tenant, principal `v6-evaluation`, authorization revision `v6-auth-r1`, no grant IDs. The write authorizer permits only those packet document identities and matching scopes. Never keep a lease during model callbacks.

Python exports `async run_evaluation(packet, *, reader_config, writer_config, tokenizer_path, kind="mechanics", send=None)`. Kind is `mechanics` or `provider`. Mechanics requires no supplied sender and uses the exact fake embedding/rerank profiles. Provider requires an explicit caller-supplied Send; the parent must use a healthy verified live recorder or a validated genuine replay. Tests must never persist synthetic vectors under OpenAI identity. Node exports `async run_evaluation(packet, options)` with options `reader_config`, `writer_config`, `tokenizer_path`, `kind` (`mechanics` or `replay`) and optional `recordings`. The native exported Node function also accepts a trusted `signal: AbortSignal`; CLI JSON options must reject that field. Replay consumes the pure ordered provider replay helper, never HTTP. The production parent must verify live tape provenance before supplying it. Node CLI stdin is bounded JSON `{packet, options}`; errors are fixed redacted JSON, never connection data or text. Cap stdin at 64 MiB and worker execution at 900 seconds; the disposable synthetic acceptance parent uses a separate 180-second runtime bound. CLI SIGINT/SIGTERM cancels the internal controller; Python caller cancellation propagates.

For the predeclared same-shortlist comparison, Python also accepts trusted optional synchronous void `on_rerank_input`, as specified in [ECR-r1](EVALUATION_CANDIDATE_V6.md). It records only candidate IDs/text hashes and request context before rerank transport. The callback cannot alter retrieval candidates, add labels or enable HTTP; default execution and result fields remain unchanged.

## Ingestion and aliases

Sort documents by UTF-8 tenant, collection and document identity; inactive revisions precede the active revision within each group, then logical alias order. For each revision, compute SHA-256 of compact UTF-8 JSON `[tenant_id,collection,document_id,logical_revision_id]`. Intent ID is `eval-` plus that digest; locator is `evaluation:` plus it. Use canonical target_bytes=2048/max_chunk_bytes=4096 and the previous receipt's generation as the expected active pointer. Ingest through the actual native vector indexer with selected FAKE or OPENAI profile. Verify receipt canonical hash against the packet. Old inactive revisions stay immutable; only the declared active generation remains current. Close the writer pool before queries.

Receipt rows have exactly `tenant_id`, `collection`, `document_id`, `logical_revision_id`, `revision_id`, `generation_id`, `canonical_sha256`, `embedding_profile`, `active`, in ingestion order. Native revision aliases are one-to-one per document; do not rewrite the actual result wire. For query filter `revision_id` string equality/membership, translate known logical aliases to the union of matching native hashes in that tenant/collection, retaining unknown literals. Equality becomes `in`; inequality becomes `not(in)`; recurse through and/or/not. Other filters stay unchanged. This translation preserves the requested set and never drops a restriction. The separate scorer may map actual IDs back to declared aliases with the receipt table.

## Modes and results

Fixed order, per query: `lexical`, `dense`, `hybrid`, `reranked_hybrid`, `corrective`. Run all through actual native library APIs. Same request limits: deadline_ms=25000, candidates=15, attempts=3, subqueries=3, provider_calls=8, context_tokens=20000; strict `cragkit.context.v2`/`cl100k_base`, envelope reserve 256. Compute deadlines using each process's native clock; never forward another process's absolute clock value. No retries/degraded fallback. Use the same bound sources and filters in every mode. Direct modes enable evidence packing with the pinned counter; only reranked_hybrid adds the reranker. Corrective uses native hybrid backend with the same reranker, pinned counter, no label-derived policy, max_retries=0 and batch_size=15.

The rerank provider profile is `cohere_v5fast_evaluation_v1` / cohere / rerank-v5.0-fast / mutable_alias:rerank-v5.0-fast / relevance_score / higher_is_better / utf8-evaluation-r1 / reject. Provider mode uses existing OpenAI/Cohere mapping transports. Mechanics embeds unit e0 vectors with known-zero fake usage and fake rerank scores `1/(input_index+1)`, preserving input order. No fake result is live-quality evidence.

Query-only corrective variants: collapse ASCII whitespace if that changes the query (`variant_id=normalized`); add the identifier-only query when nonempty and different (`variant_id=identifiers`), using the existing identifier extractor. All use `facet_id=query-intent`; preserve every original identifier and at most two distinct variants. A deterministic local planner may select only approved variants for that missing facet and reports local known-zero work. With no applicable coverage policy, facets stay unknown and the corrective engine may stop without invoking the planner. Record this honestly; never invent support labels or sufficient coverage.

Return exact top-level fields `revision: "EVX-r1"`, `runtime`, `kind`, `receipts`, `rows`, `cleanup_verified`. Each row is exactly `question_id`, `mode`, `result`, `latency_ms`. Parse/validate the actual result wire before returning it. On an operational error, keep a row with `result: {operational_failure:true,error_code:<fixed native code>}` (unknown executor exceptions use `evaluation_execution_failed`) and continue remaining modes to preserve denominators; a frozen sender may deny further attempts without more HTTP. Do not substitute an insufficient result. A fully successful replay must consume the whole tape. If a mode fails, retain all failure rows rather than discarding their denominators because the tape remains unused; the parent must reject acceptance and cannot claim complete replay. Preserve caller cancellation. Close owned pools/counters on every path; return cleanup_verified only after successful closure. Native parent owns database cleanup. Root compares receipts and per-mode result wires after removing only stage durations; latency remains separately measured. No source text/configuration is printed in failure diagnostics.
