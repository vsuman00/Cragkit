# V2-06 identifier and fusion contract (IF-r1)

Internal adapters and pure ranking functions only. Public hybrid orchestration remains V2-07. No wire-schema, migration or setup changes.

## Exact identifier profile

`identifier_ascii_v1` extracts maximal matches of `[A-Za-z_][A-Za-z0-9_]*(?:[.:/-]+[A-Za-z0-9_]+)*(?:\+\+|#)?` from canonical chunk text. Keep a match only when it contains a digit, `_`, `.`, `:`, `/`, `-`, `+`, `#`, or an adjacent lowercase-to-uppercase transition. Case is preserved. Ordinary lowercase words and bare uppercase words are excluded. This is an ASCII code/symbol heuristic, not universal identifier recognition; punctuation can be ambiguous. Matches longer than 256 ASCII bytes are ignored as unsupported identifiers. Deduplicate and sort by UTF-8 bytes. Source/chunk size limits bound extraction; no new model calls.

Both lexical and vector ingestion populate the existing `chunk_lexical.identifier_tokens` array at initial insertion. Existing immutable generations and replay receipts remain unchanged: old empty arrays need a new ingestion intent/generation for identifier coverage. No automatic backfill or claim that historical generations are indexed. Explicit query input must be exactly one supported extracted identifier, at most 256 bytes; reject other values with `InvalidRequest` before SQL.

`ScopedSession.identifier_candidates(identifier, limit=100)` uses parameterized exact array containment, the same active ready generation, full composite joins, trusted scope, authorization revision, grants, tombstone and required filters as lexical selection before LIMIT. Clamp valid integer limits 1..1000 to request max_candidates. Return `IdentifierCandidate` with the lexical candidate base fields, `score=1.0`, `score_kind='exact_identifier'`, `score_direction='higher_is_better'`, `identifier_profile='identifier_ascii_v1'`. Stable ties use document/revision UTF-8 byte order, ordinal, chunk ID. Bound and validate returned rows, duplicate identities, scope and spans. Source fetch projects the base fields only after validating the identifier metadata. Identifier selection works without pgvector. Failed authorization never becomes an unrestricted query.

## Weighted reciprocal rank fusion

Native internal modules `_fusion.py` / `fusion.ts` expose `fuse(lists, *, k=60, max_candidates=200)` (Node options object). Accept JSON-compatible list arrays only (Python list, Node Array). Each strict list has `list_id`, `facet_id` (nonempty printable nonwhitespace ASCII identities, maximum 128 characters), `family` (`dense`, `lexical`, `identifier`), finite positive `weight` <=1e6, and `candidates` array of validated branch candidates. Empty lists are valid and still reserve their family weight. At most 36 lists, at most 1000 entries per list. List IDs must be unique. Candidate shape is exactly the corresponding scoped-session candidate, including branch metadata for dense/identifier. Reject malformed input with `InvalidRequest`; reject inconsistent immutable metadata for a shared candidate identity with `IntegrityViolation`.

Deduplicate each list by `(tenant_id,collection,document_id,revision_id,chunk_id)`, retaining its first entry. Rank the distinct entries from 1 without gaps. Candidates sharing that identity must agree on generation, byte span and digest; raw branch scores may differ. Never add raw scores. For each `(facet_id,family)`, repeated lists must declare the same weight; take each candidate's best rank across those lists, counting its vote once. Normalize each family's weight by the sum of distinct family weights within that facet. Sum `normalized_weight/(k+best_rank)` across facets/families. Missing entries contribute zero. Sum contributions in canonical facet/family byte order for reproducibility. Validate k as integer in 0..1e6 and max_candidates integer in 1..1000, rejecting booleans and nonfinite values.

The global unique union must fit max_candidates; overflow raises `InvalidRequest` rather than silently discarding evidence or weakening the ceiling. V2-07 will budget branch fan-out before invoking fusion. Input arrays and provenance are separately bounded as above. Rank by fused score descending, then canonical identity tuple in UTF-8 byte order. Reject a positive candidate vote that rounds to zero during normalization or division; do not silently lose a vote to floating-point underflow. Scores are ranking values, not confidence. Compare mathematical fixtures with absolute tolerance 1e-12.

Return a JSON-compatible array of `{candidate, score, contributions}`. Candidate uses the first occurrence's validated branch shape in canonical list-ID byte order. Contributions are ordered by facet/family and have `{facet_id,family,weight,rank,list_id,raw_score,score_direction,profile}`; weight is normalized, list_id identifies the best-rank list (canonical list ID breaks equal-rank ties), raw_score is retained unchanged. Lexical provenance has direction higher_is_better and profile native_fts.v1; other provenance uses validated candidate metadata. Snapshot caller inputs synchronously; do not mutate input. Pure fusion makes no network/database calls and authorizes no source release.

## Acceptance

Shared cases cover exact punctuation/case/repeated identifiers, ordinary words, bounded invalid inputs, hand-calculated fusion ranks, duplicates, missing/empty branches, ties, family replay, facet normalization and union overflow. Native checks cover actual populated arrays, scope/filter-before-limit, common snapshot and fresh source authorization in both runtimes. Serial local checkpoint covers regressions, typechecks, parity, seals and clean artifacts. Synthetic checks establish arithmetic and isolation, not model relevance.
