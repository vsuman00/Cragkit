# V4 native acceptance harness follow-ups

Administrative test tooling only. This contract does not change core retrieval APIs, applied migrations, access policy or released package dependencies. Production and release evidence stay separate from local acceptance.

## D-r1: bounded redacted cleanup diagnostics

Implement `tools/runtime_diagnostics.py` using the standard library only. `describe_error(error, *, operation, stage)` returns exactly operation, stage, category and sqlstate. Operation and stage use closed allowlists with `unknown` for unrecognized input. Category is one of cancelled, timeout, connection, database, validation or operation. SQLSTATE is either an exact five-character uppercase ASCII alphanumeric string or null; access to a malformed/error-raising sqlstate attribute must be safe. Do not call exception string/repr or copy exception args, diagnostics, query, DSN, resource names or arbitrary class names.

`CleanupFailure(failures, *, primary=None, stage='unknown')` takes a nonempty list/tuple of at most 16 pairs (operation, BaseException), snapshots sanitized records, and has fixed message cleanup_failed. `to_dict()` returns a detached native JSON object with exactly code=cleanup_failed, primary (sanitized operation=primary record or null) and cleanup (sanitized record list). Malformed constructor data fails with a fixed error, without interpolating input. No raw exception is retained in serialized output. Cancellation is recognized without converting it into a successful result.

Closed operations initially include primary, runtime_close, child_stop, admin_close, admin_connect, schema_restore, fixture_transaction, policy_drop, privilege_revoke, row_delete, role_drop, verify_inventory, lock_acquire, lock_release, journal_write, journal_read, journal_remove, cleanup_budget and unknown. Stages include configuration, admin_connect, lexical_fixture_locale, fixture_setup, hybrid_evaluation, dense_retrieval, vector_generations, python_ingestion, typescript_runtime, runtime_login, scope_filters, deadline_cancellation, schema_rejection, deadline_query_starting, deadline_query_observation, deadline_query_completion, deadline_query_fresh_scope_reuse, cancel_query_starting, cancel_query_observation, cancel_query_completion, cancel_query_fresh_scope_reuse, recovery and unknown.

The parent harness captures a pending original failure before cleanup. If cleanup also fails, CLI output carries the original and cleanup records separately. Successful cleanup preserves the original error/cancellation. A cleanup timeout and connection-close error must be recorded, not swallowed. Root owns parent integration, CLI regression tests, contracts and tracker. The module and independent tests have separate owners; they coordinate directly on this frozen interface.

Acceptance: classify timeout/cancellation/database failures; preserve simultaneous original and cleanup failure; reject malformed/unbounded diagnostic input; detached snapshots; secret/SQL/DSN/query canaries including malicious exception methods and sqlstate attributes. Test both module internals and CLI-visible output. No external model or database is needed for D-r1.
