# V6 independent metric definitions

For example, two adjacent verified byte spans can cover one reviewed support. A one-byte gap cannot. A genuine quote from another tenant earns no retrieval credit.

`V6-reviewed-span-r1` in [v6_metrics.py](../runners/v6_metrics.py) is a pure evaluator of prevalidated reviewed questions, parsed native results, manifest documents and canonical source snapshots. It imports no runtime assessor and opens no files. The caller records input/configuration digests, origin, mode and run identity. Compare lexical, dense, hybrid, reranked hybrid and corrective configurations separately; synthetic encoders and recorded replay do not establish live-model quality.

Call `score_question(question, result, manifest=manifest, sources=sources, k=5)`, then `aggregate(rows)` once per mode and runtime. Source keys are `(tenant_id, collection, document_id, revision_id)`. Native results carry `status`, `evidence`, `facets`, optional `execution` (default `complete`) and optional `usage`. An explicit operational failure uses `{'operational_failure': True}` without result fields. Failures count as zero end-to-end retrieval on eligible questions but are excluded from every coverage-status and abstention-quality denominator. Their separate count prevents interpreting provider failure as absent evidence. Missing or corrupt source snapshots raise an evaluation error rather than producing a score.

Ranking counts distinct emitted document/revision identities, retaining invalid evidence rank slots. Independent verification and scope checks determine which identities earn credit. Recall divides relevant identities retrieved at k by all reviewed relevant identities. Reciprocal rank is the reciprocal of the first relevant rank, or zero. Binary nDCG divides discounted relevant hits by the ideal order at k. Questions with no reviewed positive identities are undefined and excluded from macro means, with denominators reported. Invalid evidence earns no positive credit; its identity, authorization or fidelity violations remain visible.

Support recall checks continuous unions of exact canonical UTF-8 intervals from the first k identities. Supported facets accept any reviewed support; conflicting facets require every support. Empty-support facets have no support-recall denominator. Sufficiency uses all emitted verified evidence after packing, independently of the runtime's assessment. A sufficient result is false-sufficient unless every required reviewed facet is supported, every support requirement is covered, the question is answerable and no evidence violation occurred. Unknown, missing and conflicting facets cannot establish sufficiency.

Abstention means a returned result is partial or insufficient. Operational failures are excluded from false-sufficient, abstention, answerable-abstention, abstention precision/recall and conflict-classification denominators. Answerable abstention divides by reviewed answerable questions. Abstention precision (`abstention_correct`) divides correctly withheld nonanswerable/partially answerable questions by all abstentions. Abstention recall (`required_abstention`) divides abstentions on nonanswerable/partially answerable questions by those questions. These measure coverage decisions, not generated answers. A reviewed conflict reported unknown is a conservative abstention and a conflict miss. Conflict misses divide by reviewed conflict questions; all required conflicts must be reported conflicting.

Every binary diagnostic reports count, denominator, rate and a two-sided 95% Wilson interval. These intervals describe this small fixed suite; shared document families and synthetic selection limit population inference. Ranking/support macro means carry eligible denominators without a misleading independent-sample interval. An empty denominator yields null. Aggregation rejects mixed k/version and duplicate question IDs. Aggregate usage retains each original record, including null and unknown fields; it never imputes zero tokens or spend.

Identity counts cover unknown full manifest identities. Authorization counts cover fixture tenant/collection, declared equality filters and inactive revisions without an explicit revision filter. Fidelity counts cover exact byte bounds, UTF-8 boundaries, source digest, excerpt digest and excerpt bytes. The wire evidence omits tenant identity, so the evaluator binds that field to the trusted question tenant. This cannot prove database provenance or distinguish another tenant's identical bytes. Real RLS/application-grant tests remain separate. Reviewed labels and manifest/source snapshots require the existing corpus integrity and review gate; byte fidelity does not establish world truth, relevance beyond labels or downstream answer faithfulness.

No held-out label was read to implement these rules. [Protocol](../protocol.md) and [architecture section 13](../../docs/architecture/ARCHITECTURE.md#13-validation-and-release-evidence) govern freezing configurations and targets before held-out access. This metric implementation invents no numeric quality target and supplies no quality result. Its synthetic tests verify arithmetic and failure handling only.
