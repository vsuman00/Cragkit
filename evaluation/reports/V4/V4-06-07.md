# V4-06 / V4-07: optional framework tools

Both optional adapters passed local and isolated installed-artifact acceptance on 25 October 2026. [The guide](../../../docs/integrations/langchain.md) describes the application boundary and supported APIs. Whole-version database acceptance is recorded separately in the exit report.

## Selection and authority

LangChain Core 1.7.0 for Python and 1.3.0 for Node provide native tool/message types without adding an agent, model or server. Each integration has a separate package, manifest and lock. Default core installs remain framework-free. Python's resolved LangSmith is 0.14.12; Node pins 0.11.1 explicitly. SDK metadata compatibility was checked and then exercised with the actual installed versions.

The factory binds trusted engine, scope, filters, limits, collection, output profile and serializer outside the narrow ToolRequest schema. Plain calls return JSON content; native ToolCalls return real SDK ToolMessage objects. Only supported async entry points run retrieval. Raw callback, sync, batch and streaming paths reject explicitly.

The application supplies the final model-visible serializer. The adapter constructs the actual SDK message first, including its real name/call ID, then counts that representation plus the bound reserve. Strict mode uses the existing issued cl100k counter; estimated mode remains an explicit estimate. A closed Node counter is rejected immediately before engine work. Generic SDK message dumps are not universal provider wire formats, and external history/prompt tokens remain outside this tool budget.

## Privacy and faults

Owned invocation paths bypass SDK callback dispatch and disable scoped tracing without mutating global settings. Nonempty invocation config is rejected except Node's native signal. Application-owned outer agent/runnable tracing is a separate disclosure boundary.

An arbitrary engine error is redacted to ProviderUnavailable; malformed result data is IntegrityViolation. Typed operational errors and genuine caller cancellation retain their types. Final review caught a Node error whose name alone could impersonate cancellation and expose its message. The fix requires actual external cancellation, and matching regressions passed. Serializer misconfiguration uses a fixed error. Uncooperative work is bounded by the outer deadline and late failures are observed.

## Actual verification

`python3 tools/check_v4.py --artifacts-dir artifacts/V4/final-acceptance` passed all 34 serial stages after the final fixes:

- Core: 1,216 Python/tool tests, 878 Node tests, both typechecks/builds and all conformance/seal checks.
- Optional SDK: strict Python checking for its source; 72 Python and 69 Node tests, with Node typecheck/build.
- SDK tests include shared ToolRequest/result fixtures, actual corrective-engine targeted recovery, full result equality, authority/config injection, real model-facing schema conversion, exact final wrapper counting, secret canaries under enabled tracing/network denial, concurrency, deadline and cancellation.
- Core: four clean archives, three guarded default imports, 216 installed evidence cases and 44 installed V4 state-machine cases.
- Optional: Python wheel/source/rebuilt wheel plus npm tarball. Rebuilt Python wheel contents matched; all 72/69 SDK tests passed again against isolated installed products outside the checkout. Product import origins and all 12 production Node SDK lock versions/integrities were checked.

The checkout remains physically present; fixture/tokenizer inputs are explicit. This is isolated installed-import evidence, not proof that the original files were unavailable. Archives retain internal version 0.0.0 and are not published.

The Python artifact test environment occupied 34,351,727 logical bytes including core, SDK, pytest and tokenizer dependencies. The Node consumer included core, SDK and tokenizer dependencies; its final measured size is in the exit report. These are file totals, not runtime memory or incremental SDK costs. No model download, paid provider call, hosted CI job or production check ran.

Learning example: a valid evidence pack can still exceed budget once its ToolMessage wrapper is added. The adapter rejects that final message before returning it. Practice: change a test serializer's wrapper while keeping its content fixed and identify which token ceiling changes; this exercise remains optional and unassessed.
