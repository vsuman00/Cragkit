# V1-06 and V1-C2: Native ingestion parity

Status: COMPLETE, 21 October 2026. Python and native TypeScript can ingest and replay each other's immutable lexical generations against the same PostgreSQL schema. V1 retrieval and lifecycle work remains in progress.

## Implementation and integration

The Node `PostgresIndexer(resource, authorize_write)` mirrors the accepted Python ingestion contract: separately bound application write authorization, strict identity/metadata/options checks, stable intent/payload/revision/generation IDs, principal-only initial grants, unchanged existing ACLs, staging counts and atomic compare-and-swap publication. Node runs its own SQL through optional `pg`; it does not call a Python service. The constructor callback must return exact `true`. Inputs use Zod at the ingestion boundary and the existing trusted-scope validator. Mutable caller bytes, metadata and canonical options are captured before awaiting authorization.

Node promises are bounded by a monotonic absolute deadline and AbortSignal. A staged abort destroys that lease; the server rolls back its uncommitted transaction, and the pool can create a new connection. Python cancellation can roll back and reuse a healthy lease. Neither runtime claims a missing COMMIT acknowledgement means no commit. Application-owned asynchronous callbacks must bound their own external work; racing a JavaScript promise cannot stop arbitrary caller code. Subsequent SQL is blocked after abort/deadline.

Eight independently calculated identifier cases extend the eight TLV metadata cases in the shared ingestion fixture. Both runtimes match all expected hashes, including Unicode scope IDs, UTF-8 grant ordering/deduplication, negative zero, float formatting and expected-generation identity. These are separate from the sealed retrieval corpus.

Integration review corrected an earlier Python gap as well as the Node path: the staging-to-ready UPDATE must return exactly one row before advancing the document pointer. A restrictive UPDATE RLS policy can otherwise silently hide that row. Both implementations now raise IntegrityViolation and roll back; unit regressions and a real restrictive-policy PostgreSQL probe cover this behavior.
