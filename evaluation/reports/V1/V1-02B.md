## Scope

The connection layer builds on V1-02A's optional pool resources. A trusted application supplies scope separately from the request. The adapter opens read-only transactions, validates the schema and runtime role, binds transaction-local context and applies the remaining monotonic request budget to statements. It provides an internal published-document identifier probe, not ranked retrieval or source release.

The first filter capability is deliberately small: string identifiers (`document_id`, `revision_id`), equality, inequality, membership and boolean groups. Other valid request filters receive `UnsupportedCapability`; the adapter does not guess metadata mappings. The existing wire contract permits adapters to reject unsupported fields.

For example, two successive requests can use one physical connection for different tenants. Each transaction binds its own tenant, principal, authorization revision and grants; completion or failure must clear those local values before reuse. A missing grant or stale authorization revision excludes a document before the result limit.

## Integration findings

The first native runtime run reached the schema-rejection stage, then failed cleanup verification: Supabase's `postgres` administrator could create the temporary role but `DROP OWNED BY` returned SQLSTATE `42501`. Root isolated that statement, removed only the fixture's exact policies/data and table/domain/schema grants, and dropped the role. Separate queries verified no probe roles/policies/collections remained and the original column name was restored. The committed harness now uses those explicit revokes, with no privilege expansion. E69 records this regression.

A subsequent run reported a safe `ProviderUnavailable` during scoped checks and discarded a closed connection. Its `finally` cleanup completed: separate native queries found no probe roles, policies, collections or connections. The later traced and canonical runs passed; that transient failure's exact cause remains unproven.

Read-only peer diagnosis and inspection of the installed psycopg 3.3.6 source found that transaction exit can suppress rollback errors or return normally for a bad connection. Root added an explicit IDLE postcondition before reuse and a regression that simulates suppressed failure; a nonidle connection is closed and reports `ProviderUnavailable`. Rollback also clears prepared statements, which can add protocol work. The transient second-run cause was not established; it is not described as a proven network or credential failure. The unchanged-budget traced run and a canonical uninstrumented run subsequently passed before this final postcondition change; final-source acceptance is recorded below.
