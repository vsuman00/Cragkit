# V1-07: Scoped native lexical candidates

Status: COMPLETE, 21 October 2026. Both native adapters return scoped FTS candidate identities with stable ordering. Source-backed typed evidence results remain V1-08; V1 is still in progress.

## Behavior

`ScopedSession.lexical_candidates` runs inside the existing bounded read-only repeatable-read transaction. It uses PostgreSQL `websearch_to_tsquery` and `ts_rank_cd` with `pg_catalog.simple`, not BM25 or semantic similarity. Scores are native lexical ranks, not confidence or coverage estimates. Results contain tenant/collection/document/revision/generation/chunk IDs, byte offsets, text digest and rank. They contain no source excerpt.

The SQL joins the document's active generation to its matching chunks and lexical rows through full composite tenant keys. It requires a ready generation, non-tombstoned document, matching trusted authorization revision, and a current matching principal/grant. Supported required identifier filters apply before ranking/LIMIT. Unsupported filters fail through the existing capability boundary before SQL. Query strings, scope and filter values are parameters. Ties order by C-collated document/revision ID, chunk ordinal and C-collated chunk ID. The effective limit is bounded by the caller's candidate ceiling.

Both methods retain task/context ownership, handle expiration and shared statement/deadline behavior. Returned candidates are immutable and checked for scope, profile, offsets, digest syntax and finite nonnegative rank. Byte offsets from native `pg` bigint/domain columns arrive as decimal strings: Node converts only canonical nonnegative decimal strings, then validates exact safe integers. Fractional, negative, Boolean, null and unsafe values fail with IntegrityViolation. This conversion does not change stored source coordinates.
