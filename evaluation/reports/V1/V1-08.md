# V1-08: Authorized source spans and typed results

Status: COMPLETE, 21 October 2026. Both native runtimes verify authorized canonical source spans and assemble the existing typed RetrievalResult. V1 remains in progress; lifecycle work and final authorization races retain their planned tasks.

## Behavior

Internal `PostgresRetriever(resource)` in Python and Node reuses the caller-owned optional PostgreSQL resource. Retrieval takes a parsed request, separately bound trusted scope and absolute monotonic deadline; Node also accepts AbortSignal. Candidate selection and source fetch run in separate scoped read-only transactions. The fresh source snapshot reapplies composite candidate identity, required filters, principal/grants, authorization revision, readiness and tombstone checks. Missing/deauthorized sources are omitted with stale_evidence. Operational failures remain typed exceptions.

The source verifier checks the complete canonical UTF-8 digest, exact scalar-aligned byte slice, chunk text/length/digest and candidate identity/span/digest. A still-retained ready generation may resolve after active publication changes and is marked stale. Source locators remain opaque labels. Evidence.source_sha256 is the verified canonical digest; the database's original pre-normalization source_sha256 remains provenance and can differ after BOM/newline normalization. Evidence IDs are deterministic and anchored to immutable revision/chunk coordinates. [E-r1](../../../contracts/RETRIEVAL_V1.md) defines the exact shared behavior.

Nonempty emitted evidence returns partial; no emitted evidence returns insufficient. Execution is complete when operations succeed, and coverage_unknown is always present. Facets remain empty because no assessor is installed; lexical matching does not establish semantic support. The context is compact JSON of exactly the emitted Evidence array. Only whole chunks are packed, preserving their source bytes. There is no synthesis or final answer generation.

V1 supports the default renderer with estimated counting only. It checks actual serialized context bytes against a bounded byte allowance derived from the caller's token limit and envelope reserve, then reports ceil(UTF-8 bytes/4) as an estimate. This is not a hard model token guarantee. Strict mode, other renderers and named tokenizers fail before leasing. A reserve that consumes the whole allowance raises ContextBudgetTooSmall. Truncation/budget flags remain visible; errors never become empty evidence.

Limits are 65 candidate identifiers (one sentinel beyond the 64 item result ceiling), 64 source fetches, 16 MiB canonical bytes loaded and 262,144 context bytes. SQL withholds canonical text when it exceeds the remaining source budget or hard cap, and withholds oversized chunk text. Node handles PostgreSQL bigint offsets exactly. Root added bounds before string allocation, immutable source-budget snapshots and accessor rejection at the Node boundary. Importing these modules does not load a driver, open a connection or apply migrations.

Known zero model/provider calls, tokens and spend are recorded explicitly; infrastructure/database hosting cost is not measured. Context counting remains estimated, model/tokenizer identities are null, policy is unassessed.v0 and index is native_fts.v1. Stage durations are unmeasured rather than fabricated zeros. The request deadline starts at call entry and covers validation, both transactions, hashing and result assembly. A slow-validation regression confirms that an expired request cannot proceed to SQL.
