## Behavior and retention

For example, two updates prepared against generation A cannot both publish: after the faster update publishes B, the late update still expecting A fails with IndexNotReady. Existing ingestion already supplies this compare-and-swap barrier under the document advisory lock. V1-09 preserves it and adds explicit lifecycle operations in native Python and Node.

PostgresLifecycle binds an application-owned lifecycle authorizer outside editable input. The callback receives the trusted immutable scope, collection, document and operation; only exact true permits mutation. The adapter validates the stored authorization revision and expected active generation while holding the same document advisory lock as ingestion. Missing or unauthorized rows do not become successful mutation receipts.

The retention policy is caller-controlled: live documents keep immutable historical ready revisions until explicit deletion/purge. There is no automatic expiry or cleanup service. Tombstone preserves the active pointer and metadata while fresh retrieval and direct source release exclude the document. It cannot recall bytes already delivered or snapshots started before deletion. Purge requires a separate restricted runtime role and explicit application authorization. It atomically deletes the tombstoned parent and reinserts a minimal marker with the original identity, authorization revision and creation time, null active pointer and empty metadata. Foreign key cascades remove source revisions, generations, chunks, FTS, ingestion jobs and grants. A purged historical citation returns unavailable. Old ingestion intents cannot recreate the retained marker.

Deleting child rows individually could silently miss rows hidden by RLS. The parent cascade avoids that failure. Purge validates its nine expected inbound FK edges, enabled internal triggers and origin replication mode before deletion. Custom inbound foreign keys are unsupported. It requires DELETE/INSERT and column-level UPDATE(created_at) on documents with appropriate RLS, without direct child DELETE, schema ownership, elevated membership, TRUNCATE or BYPASSRLS. Ordinary ingestion and retrieval continue rejecting a purge-capable role. No migration, policy or role is automatically installed by the library.

Creation timestamps round-trip as server text with an explicit timestamptz cast to retain microsecond precision across Node. A small generic transaction helper reuses ingestion's established deadline, rollback and uncertain-COMMIT cleanup. A lost COMMIT acknowledgement remains an operational failure with uncertain server outcome; after a successful purge clears the pointer, retrying the old expectation may conflict and must be reconciled. Repeated purge with matching null expectation safely performs another atomic replacement; changed true means a mutation occurred, not that retained source existed.

Applications remain responsible for their backup, log and external-cache retention/erasure. The minimal tombstone keeps document identity and authorization revision; this is not a claim of universal personal-data erasure. See [L-r1](../../../contracts/LIFECYCLE_V1.md).
