## Implementation

The internal Node modules `postgres-pool.ts` and `postgres-session.ts` mirror the Python lifecycle and supported identifier filters. The callback API uses absolute `performance.now()/1000` deadlines and optional `AbortSignal`. Every leased session validates the actual login role, catalog/RLS and exact schema ledger; read-only repeatable-read transactions bind trusted context locally and always roll back. Values use PostgreSQL parameters. A published-document identifier probe applies scope before limits; it is not ranked retrieval or source release.

Owned startup explicitly reads a validated CA and owner-only regular password file. It rejects populated `PG*` overrides, connection URIs, wildcards and ambiguous password entries. TLS requires certificate verification and the configured hostname. `pg` 8.23.1 is an exact optional peer and development dependency; core imports do not load it or contact the network. Installed driver source confirms `getTransactionStatus()` and lacks query AbortSignal handling, so request stops discard the affected client. Borrowed pools retain caller ownership and transport configuration. Abandoned checkouts retain bounded admission until the driver settles and are released exactly once. Close is bounded and idempotent; an unsettled borrowed checkout causes a typed failure rather than a false success.

Review found late-checkout and settled-admission races, throwing cleanup callbacks and ancestor-resource nesting gaps. Corrections retain returned clients before the deadline recheck, track settlement, contain secondary cleanup errors and track all ancestor resources. Session cleanup checks IDLE. Node uses inherited async context, active-handle checks and serialized operations; this does not claim Python task-identity semantics.
