# V1-H1: PostgreSQL adapter input and error hardening

Status: COMPLETE, 21 October 2026. This follow-up resolves two concrete security-review findings without changing backend-neutral wire contracts.

Both native read/write adapters now classify PostgreSQL SQLSTATE class 23 constraint failures as IntegrityViolation. Unit cases cover not-null, foreign-key, uniqueness, check and exclusion violations; returned errors retain fixed messages and omit private driver details. Python ingestion uses the shared session mapping; native Node ingestion and read sessions use matching mappings. Unrecognized operational failures remain ProviderUnavailable. Scope, deadline and unsupported-capability errors keep their existing classifications.

Both read adapters reject NUL in queries, collections, tenant/principal/revision/grants and supported identifier-filter values before leasing or issuing SQL. Recursive NOT/group filters use the same compiler. The ingestion boundaries already rejected NUL. PostgreSQL cannot store text containing NUL; the core remains backend-neutral, so public request/scope validators and schemas are unchanged. The new tests explicitly parse those inputs successfully at the wire boundary, then assert adapter rejection with zero leases/SQL.
