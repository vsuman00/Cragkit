## V1-10: Final source authorization

Example: a document can rank first during candidate search, then lose its grant before source assembly. Its text must be withheld from the result.

The real database fixture now commits document authorization revision changes, grant revision changes and tombstones between candidate selection and final source fetch. Both native retrievers omit the revoked source, retain the still-authorized tie document and report stale evidence. Each mutation is restored and retrieval succeeds again through the same pool. Native owner/bypass-role rejection and reuse across tenant scopes are checked. The application must supply trusted scope and compatible RLS policies.

This covers E20 and the pooled scope boundaries. It cannot revoke bytes already delivered or prevent a later authorization change after the final transaction snapshot.

## V1-11: Deadline and cancellation cleanup

## Learning and remaining boundaries

The end-to-end path is application-authorized ingest, immutable revision publication, scoped candidate search, fresh source authorization, byte-span verification and typed evidence assembly. Filtering after top-k can discard all selected candidates while hiding authorized ones that should have entered the selection; scope and required filters therefore belong before LIMIT, followed by final source reauthorization. Cancellation cleanup in finally blocks makes the resource available to the next request.

Optional exercise: explain that path in five minutes, then identify why a revoked top candidate must be withheld. The explanation is provided; the user's practice and understanding remain pending.

V1 delivers native lexical libraries with unknown coverage, partial/insufficient estimates and estimated context accounting. Vector search, model quality evaluation, exact tokenizer packing, framework adapters, production deployment, registry publication and hosted CI evidence remain outside this milestone. Infrastructure cost was not measured. The next smallest task is V2-01, the embedding profile/provider/resource/license decision.
