## Implemented public behavior

For example, a dense SQL failure raises by default. An application that explicitly configures hybrid recovery can roll back that branch to a savepoint, keep the original snapshot and return remaining evidence with execution=degraded. An authorization or integrity failure, expired deadline, failed savepoint or source-release error remains fatal.

Both optional native PostgreSQL entry points now expose trusted constructor configuration for lexical/dense/hybrid modes, an injected EmbeddingAdapter, explicit allow_degraded and optional identifier search. Lexical remains the default with its existing V1 result behavior. [HY-r1](../../../contracts/HYBRID_V2.md) specifies the public configuration, budgets, redacted diagnostics and source contract; [development commands](../../../docs/development.md#v2-07-hybrid-orchestration-and-v2-08-evaluation) explain use. Only the distinct provisioned synthetic embedding profile is searchable; the approved hosted profile still needs separate provisioning/configuration before live use.

Dense/hybrid performs one embedding boundary invocation before leasing, one original query/attempt and at most three logical branches. Branches execute serially on one read-only repeatable-read snapshot, with fixed budgets divided before work: at most 40 per family and a global ceiling of min(request limit,200). Too-small budgets fail before provider/DB work. Failed branches do not gain retries or extra allocation. IF-r1 combines distinct ranks, then fresh source release rechecks current scope/tombstones and verifies immutable byte spans. Coverage remains unknown, returned status is partial/insufficient, and context counting stays estimated.

Root integrated peer implementations, fixed strict typing, aligned profile validation order, made every savepoint control failure invalidate its handle and preserved fatal source errors. Deadline regression tests bound an injected embedder that ignores the deadline. Python and Node default lexical paths, wire schemas, stored generations, applied SQL/setup bytes, lockfiles and reviewed labels remain intact. No automatic migration, provider setup or new service is introduced.

### Regression investigation

q01 is the expected-source ranking regression: dense ranks retry-policy/r2 first; hybrid ranks cache-policy/r1 before it. [The cache source](../../corpus/documents/cache.txt) contains ERR-17 in a sentence distinguishing cache identifiers from queue errors; [the retry source](../../corpus/documents/retry-v2.txt) carries the actual four-attempt rule. The exact identifier branch therefore ranks cache before retry, while dense ranks retry before cache. Equal reciprocal-rank votes tie, and the canonical document-ID tie-break places cache first. q01 reciprocal rank drops from 1.0 to 0.5 and nDCG from 1.0 to 0.6309. No tuning was applied to hide this regression; source relevance reranking remains V3 work.

q03 is missed in every mode because an explicit r1 filter cannot select the document's active r2 generation. The historical physical revision mapping is preserved, so the result stays empty rather than relaxing the filter. The reviewed expected r1 source remains in the metric denominator. This is the existing active-generation candidate-search limitation, distinct from retained-source fetch by a known citation identity.

Native FTS returns no hits for these six complete natural-language queries. The unrewritten pg_catalog.simple/websearch queries include question words and unstemmed forms that do not match the source terms. A separate read-only native PostgreSQL function control matched ERR-17 alone and rejected the complete q01 query against the reviewed retry sentence, confirming the full-query constraint. This is the declared unrewritten lexical baseline, not BM25 or a keyword-tuned comparison. Dense/hybrid returns evidence for the unanswerable question; unknown coverage prevents a sufficient claim. The aggregate results establish no guaranteed hybrid improvement.

## Security fixes and remaining limits

F-01: the base Node fixture no longer receives an administrator configuration path or opens an administrator pool. The Python parent uses its existing administrative connection for the negative role-guard check. Fixture allowlisting and source-boundary regressions pass, and the final native base check confirms the parent rejection plus actual restricted Node login. Same-user processes are not an OS sandbox; do not infer isolation from a compromised process that can independently read that user's files.
