## Managed ownership decision

Rollback-only live probes found that the extension/schema belong to `cragkit_admin`, while Neon owns primitive functions/types as `cloud_admin`. The installer is not a member of that platform role. Primitive REVOKEs were ineffective and the strict check correctly rejected setup. No failed probe committed an installation or changed an existing extension.

A-r2 retains strict ACL rejection by default and adds explicit `--allow-managed-vector-primitives`, requiring vector check/setup. The exception checks exact extension membership, known platform ownership and signatures, forbids SECURITY DEFINER/unexpected functions and namespace objects, and retains owner-only schema/ledger access, ledger RLS and no policies. Conditional primitive revocation runs only where the installer has effective ownership. PUBLIC primitive privileges remain on this managed target; this is an acknowledged computational surface, not proof that every primitive is inaccessible.

Future runtime schema USAGE exposes normal lookup of PUBLIC functions and needs an explicit review before B/C/E grants. Data authorization remains protected by application table privileges, trusted scope and RLS. Platform administrators are trusted; no isolation from them is claimed. [PostgreSQL extension ownership](https://www.postgresql.org/docs/17/sql-createextension.html) and [privilege semantics](https://www.postgresql.org/docs/17/ddl-priv.html).

Live catalog checks also exposed that per-schema default REVOKE does not remove PostgreSQL global PUBLIC function/type defaults. Setup now restricts future objects created by the installer across this dedicated database, including other schemas, and checks global plus namespace defaults. Existing grants are unchanged. Regression coverage requires the global statements; this is intentional security configuration for the dedicated target. [PostgreSQL default privileges](https://www.postgresql.org/docs/17/sql-alterdefaultprivileges.html).

## Limits and learning

One test process and one native suite ran at a time, at most two native clients including lock/role probes. Initial resource snapshot: 28 GiB available disk and 67 percent memory free on the M4/16 GiB laptop. All clients/processes closed; no persistent service, local model, paid embedding call, source disclosure, new compute or package publication. Native administrative work has a 120-second total bound; generic psql has a 120-second bound per subprocess plus SQL bounds. These observations are not performance measurements. Hosted CI and production acceptance were not run.

Example: a lexical session needs its existing migration history; a vector-enabled action additionally needs the correct installed capability. This separate setup ledger preserves that distinction. Failure case: an advertised but uninstalled extension is rejected before vector work. Exercise: explain why a schema denial and table RLS protect different operations, and why the managed PUBLIC function ACLs must still be disclosed. Learning practice remains pending.
