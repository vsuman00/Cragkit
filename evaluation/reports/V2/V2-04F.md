# V2-04F: Native Node generation publication

TypeScript now implements VG-r1 publish and ingest through the optional `cragkit/postgres` export. Publication recomputes identity from full source/options, checks the staged job and complete scoped revision/generation manifest, then changes readiness, the expected active pointer, metadata and job state in one transaction. Provider work stays outside publication.

The barrier runs again after the bounded caller hook and reauthorization. Missing vectors, mixed profiles, failed transition rows, cancellation and stale compare-and-swap leave the prior state intact. Replaying a succeeded older job returns its verified receipt without moving the current pointer. Ingest holds one admission guard and one immutable input snapshot across staging and publication; its receipt carries this invocation's embedding usage.

Sol source/test peers coordinated directly and assembled their files. Root inspected the implementation and extracted shared fake database helpers so publication tests do not import and rerun the staging suite. An initial fake-client disconnect failed to reset transaction state; the helper now models rollback when a connection is discarded. Abort/deadline retry checks passed after correction. No production behavior was weakened to accommodate the fixture.

Before the final security review, 87 focused staging/publication cases and the full 21-group native Python/Node vector run passed. Native checks exercised publication rollback, incomplete/mixed manifests, readiness-policy rejection, current authorization, immutable retained sources and stale-CAS ordering. Cleanup passed with at most two clients. The [G report](V2-04G.md) records the final superseding local/native checks, additional security regressions and complete phase acceptance.

No paid embedding call, local model, Python server, new dependency or persistent service was introduced. This slice establishes generation mechanics; dense ranking and semantic quality remain separate work.
