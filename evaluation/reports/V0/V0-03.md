# V0-03 and checkpoint V0-C1

Local evidence, 19 October 2026. The final integrator inspected the native skeletons and dependency graphs. No database connection, provider/model call or service startup occurred.

## Compatibility and commands

Tested on macOS arm64 with Python 3.14.6 and Node 26.5.0. Python 3.14.4 also passed the original V0-02 skeleton import. Supported runtime declarations are conservatively limited to Python 3.14 and Node 26.5 through 26.x; other systems and versions are unvalidated. No package is published.

Registry metadata was read directly from PyPI and npm before installing. Exact Python direct versions: Pydantic 2.14.1; development tools pytest 9.1.1, mypy 2.4.0, build 1.6.1 and jsonschema 4.26.0. Hatchling 1.32.4 is the isolated build backend. `uv lock --project packages/python` records transitive versions and hashes in `uv.lock`; `uv sync --project packages/python --frozen` installs the default development environment without PostgreSQL extras.

TypeScript uses Zod 4.6.7 at runtime, TypeScript 7.0.2 and Node types 26.6.5 for development. `npm install --ignore-scripts` created the lockfile; subsequent reproducible setup uses `npm ci --ignore-scripts`. `npm ls --all` showed only these dependencies plus the compiler's selected macOS arm64 binary and Node's type dependency. Other compiler-platform binaries were optional and not installed.

Actual verification, run one process at a time:

```sh
uv run --project packages/python --frozen pytest packages/python/tests
uv run --project packages/python --frozen mypy --config-file packages/python/pyproject.toml packages/python/src
uv tree --project packages/python
```

Python: one import test passed; mypy reported no issues in the initial source file. TypeScript `npm run typecheck` and `npm test` in its package directory passed, including one import test and the build. Direct Pydantic and Zod probes accepted an integer and rejected coerced strings, nonfinite input and unknown fields as applicable. These probes validate installed API compatibility, not retrieval behavior.

Optional Python driver probe:

```sh
uv run --project packages/python --frozen --extra postgres python -c 'import psycopg, psycopg_pool; print(psycopg.__version__, psycopg_pool.__version__, psycopg.pq.version())'
uv sync --project packages/python --frozen
```

The probe printed psycopg 3.3.6, psycopg-pool 3.3.3 and libpq 180006. No connection or pool was opened. The next sync removed all three optional driver distributions, and `find_spec` confirmed that both driver modules were absent from the default environment. A temporary directory with `npm install --prefix <temporary> --no-save --ignore-scripts --no-audit --no-fund pg@8.23.1` supported an isolated Node `pg.Pool` construction and close without connecting; the temporary directory was removed. PostgreSQL protocol, server, TLS and extension compatibility remain V1 integration work.

## Resource and learning record

`du -sh packages/python/.venv packages/typescript/node_modules` reported 87 MB and 41 MB before the temporary optional driver probe. Disk remained 22 GiB available and kernel memory pressure 1; swap was 2839.75 MB, slightly below the earlier snapshot. This does not establish a sustained-load budget. No task-owned background process remains.

For example, the Pydantic package is a direct runtime dependency, while `pydantic-core` is installed transitively. Exact development locks reproduce this environment; they do not prove compatibility with every future release. A failure case is installing PostgreSQL support by default: import-only users would then carry an unnecessary driver dependency. Learning remains pending; an optional exercise is to identify the runtime packages versus test tools in the dependency tree.

E05 was exercised by the guarded import tests. Other V0 edge cases await contracts and reviewed corpus work. CI, database integration, live-model quality and publication remain unvalidated.
