# V0-04: Request and error contracts

Local acceptance, 19 October 2026. Shared revision `0.1` is defined in [the contract specification](../../../contracts/README.md). The runtime peers owned separate source/test files; the Python peer assembled their contracts. Root inspected both implementations, corrected an initial native-input-bound mismatch through the owners, and ran final checks sequentially.

## Verified behavior

Both native implementations validate query UTF-8 bytes, scalar Unicode, allowlisted bounded filter trees, strict limits, explicit tokenizer identity in strict mode, and separate tool/request/scope objects. Tool input rejects caller scope, filters, limits and output configuration. Parsed models detach and freeze nested input collections. Nine typed errors have fixed codes, safe messages and retryability; helper failures omit input and raw validation chains. No retrieval or authentication engine is implemented.

## Limits and learning

Checks used Python 3.14.6 and Node 26.5.0 locally, one test process at a time, without database/model services or task-owned background processes. This establishes deterministic contract behavior for the cases tested, not access authorization, model quality or release readiness. No hosted CI or publication occurred.

For example, a tool request carrying `scope` is rejected while application code can validate a separate trusted-scope value. A failure case is accepting the scope because its fields have valid types: validation cannot authenticate it. Learning remains pending; an optional exercise is to change one valid filter operator to an unknown value and inspect its safe error envelope.
