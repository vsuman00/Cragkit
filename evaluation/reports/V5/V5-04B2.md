## Implementation and shared data

The internal native Python and TypeScript modules encode generation manifests and stage, authorization, tombstone and purge intents using the exact ordered arrays in QW-r1. Generation metadata checks full profiles, recomputed QC UUIDs, complete source digest/count, exact UTF-8 spans and excerpt digests, duplicate membership and explicit sparse absence. Source encoding preserves BOM, CRLF, NUL and Unicode. ACLs are bounded before deduplication and sorted by unsigned UTF-8 bytes. Results are immutable snapshots.

Original-vector sidecars use explicit Float64LE values and UInt32LE sparse indices. Dense blobs are exactly 12,326 bytes; sparse blobs are at most 231 bytes. Restore validates native shape, bounded length, trusted expected hashes, domain/kind/count and exact layout, then re-encodes original values through B1 and compares the canonical input seal. It issues fresh process-local provenance rather than trusting serialized result fields. Original signed zero is preserved in the sidecar while B1 keeps its canonical positive-zero identity.

The [shared fixture](../../../contracts/fixtures/qdrant_publication.json) adds four replay and four operation goldens without changing earlier manifest/stage goldens or the 43 fault/14 numeric scenarios. Root independently reproduced the new Float64LE hashes and ordered intent arrays in Node from standard-library calculations. Existing applied migration 0001, source-only catalog, package exports and candidate/source adapters are unchanged.

These are content encoders, not authorization or publication capabilities. Manifest encoding validates the declared vector-seal metadata; the later manager must restore and match each actual vector and enforce current scope/security state before preparation. A caller-supplied blob plus self-reported hashes does not establish trusted authority. No public real-model ingestion route or provider charge is introduced.
