# V5-04G2a1: Security commit confirmation parity

Status: COMPLETE for authority-only writer confirmation. Public security admission and physical security-replica convergence remain pending.

For example, a tombstone can commit in PostgreSQL while its reply is lost. The writer now confirms that exact durable intent instead of applying the security change again. It can confirm historical success after a later authorized transition without restoring the old grants.

Python `apply_security` now distinguishes actual COMMIT uncertainty from transaction-body errors. Its fresh scoped transaction compares the original instance, action, encoded bytes/hash and expected authorization revision/mutation epoch. Only committed authority or terminal denied/conflict outcomes return. Missing or nonterminal confirmation fails with `ProviderUnavailable`; a contradictory record fails with `IntegrityViolation`. Confirmation contains no mutation or current-document revision requirement and never retries DML.

Node already confirmed lost commits through its shared mutation helper. Its security-specific confirmation now applies the same outcome rule. Root also enabled the existing commit-cancellation preservation option for security operations: a COMMIT deadline, abort or PostgreSQL statement cancellation cannot trigger confirmation. Other mutation defaults are unchanged. Source revocation remains independent of backend/owner recovery locks, pending dispatches and vector I/O.
