# V5-07A2: Native nomination handoff

State: COMPLETE for the pure candidate handoff. Optional Qdrant corrective adapters and actual backend/transport parity remain open.

Both corrective cores now accept a closed internal Qdrant candidate containing the complete unverified nomination. Common immutable identity, source span, excerpt digest and native score must match that nomination. The deterministic point ID, profile identifiers, branch/score kind and dense score bounds are checked. Native signed cosine similarity and dot product remain intact. Existing PostgreSQL candidate forms remain supported.

Focused corrective, PostgreSQL-backend and new handoff tests passed 54 Python and 50 Node cases. The new cases use the shared QS-r1 fixture and cover signed dense/sparse scores, contradictory metadata, wrong point IDs, foreign scope and nested snapshots. Accepted nominations alone produce no evidence or sufficient status. Python strict types, TypeScript build, 17 shared corrective cases and the core import guard passed. No storage, provider or background process ran.

The first new engine tests used the source fixture's default legacy renderer; the corrective engine correctly refused that capability. The fixture now explicitly selects its required v2 renderer. No wire request/result schema changed. Learning practice remains unassessed: explain why a matching immutable candidate still needs current source authorization before text release.
