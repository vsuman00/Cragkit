# V5-04G2b2c1: Authentic session activity

Status: COMPLETE for private session provenance and conservative activity snapshots. Security receipts and settlement remain pending.

For example, a successful readback becomes stale evidence if a later write runs through the same session. The new private helper authenticates the original active facade and returns its physical proof binding plus an activity counter, allowing a later receipt consumer to detect intervening work.

Both native supervisors register only their own issued facades. `control_session_binding(control, supervisor, proof)` rejects structural copies, proxies/lookalikes, foreign supervisors, expired or draining sessions and invalid physical proofs. It returns exactly immutable `physical_binding` and `activity`, with no keys or internal token. Successful facade attempt issuance and each admitted session HTTP request increment activity, including reads. A new facade has its own counter and identity; matching numbers cannot make facades equivalent. Existing request admission, owned-work draining and stage receipts retain their previous behavior.
