# V5-04E2a: Authority-bound recovery readback

State: COMPLETE for exact recovery readback. E2, V5-04 and full V5 remain incomplete. Baseline: `9898c4204c067020c012e892770a873aa49ab38e`.

For example, an upsert can finish even when its caller loses the acknowledgment. This slice verifies the stored points after the old credential is retired. It issues a private receipt and leaves the durable journal unknown and the instance recovery-blocked. E2b must prove settlement before admission can reopen.

## Implementation

Both native writers reconstruct a complete committed stage graph under the supplied trusted document scope and current authority. Recovery projections require matching instance, storage, supervisor, recovery identity, new epoch and unchanged document owner token/intent. Current ACL, metadata and tombstone state replace stale replicas. The verifier releases SQL before HTTP, retrieves every expected UUID and enumerates the entire immutable generation scope without ID/profile filters. It compares exact membership/payloads and every named dense/sparse vector under B1's numerical rules, then rereads authority before issuing an opaque receipt.

Projections and receipts have issuer-bound private provenance; copied objects and serialized physical metadata cannot mint them. The 22-element witness contains strings, nulls and arrays, including original vector seals. Its hash does not rely on floating-point response JSON. Receipt access rechecks the live physical proof. Current authority changes give `UnauthorizedScope`; immutable contradictions give `IntegrityViolation`; unavailable recovery state remains operational.

Verification allows at most 64 members, eight points per page, 17 HTTP calls, 1 MiB per response and 8 MiB aggregate. Each streaming reader receives the remaining allowance, and zero prevents dispatch. The root-owned E2a-T change adds Node's optional per-request response allowance to match Python's existing transport capability. Constructors/imports perform no network or process work.

The writer also rejects a different manifest under the same immutable generation before appending members. Full raw member/claim/replay sets are checked before joined reconstruction, so incomplete extra rows cannot disappear behind an inner join. UUID ordering makes equivalent SQL row order harmless.

## Review and limits

Sol peers implemented separate Python/Node paths and coordinated their shared interfaces directly; Python assembled. A third Sol peer wrote the Node native consumer and reviewed the independently authored runtime code. Root inspected changes, added the remaining-byte transport hook and native checks, and ran final acceptance serially. Review corrected hidden raw members, SQL order dependence, Node null-prototype response handling, cleanup-error suppression and cross-runtime error distinctions. Root reproduced a late Python receipt after a slow final physical check, added a final deadline check, and verified the regression before the final native rerun. No unresolved material issue required Astra.

Physical fencing and exact readback do not settle current-credential uncertainty: a paused request using that credential could still arrive. E2b must consume actual private receipts, retain a closed gate for unresolved documents and seal recovery transports before its SQL-to-native admission handoff. F/G still own bounded production writes, replay, current security convergence and purge. H's 43-case native process/fault matrix has not been executed by this slice. Synthetic vectors establish storage mechanics, not model quality or general production readiness.

Resource observation: 36 GiB disk and 60 percent system memory free on the M4/16 GiB laptop before these runs. One test process and serial native services were used. Learning practice remains unassessed. A useful exercise is to explain why a verified readback can settle a retired credential's effects but cannot alone settle an unknown request using the current credential.
