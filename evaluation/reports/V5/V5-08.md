[V5-07](V5-07.md). The [tracker](../../../tasks/todo.md) owns task and checkpoint state.

For example, the clean core environment imports the optional entry points without

## Changes and integration review

Added a local MCP archive builder and twelve isolated profile probes in
`tools/check_v5_artifacts.py`, `tools/probe_v5_installed.py` and
`tools/probe_v5_installed.mjs`, with seven focused verifier regression cases in
`tools/tests/test_v5_artifacts.py`. The tool validates archive identity/exports,
source-distribution rebuilds, exact Python requirements with hashes, Node lock
versions/integrities and installed module provenance. It refuses a nonempty output
directory before overwriting evidence. Python product wheels install with
dependency resolution disabled after the selected locked dependencies have been
installed. Node archives resolve against reviewed overrides, followed by exact
lock version and integrity checks.

The base artifact verifier now recognizes the already-supported Qdrant extra. The
Python development group explicitly pins the existing HTTP/PostgreSQL dependencies
needed by the routine tests and strict typing; runtime dependencies are unchanged.
The [operations guide](../../../docs/v5-operations.md) documents profile choice,
credential/service requirements, explicit migrations, connection ownership,
consistency, single-node restrictions, recovery and checked local shutdown.
Development/README/tracker updates are integrated separately by the coordinator.

The assembler read the artifact tool, probes and tests. Its fresh-output overwrite
finding was corrected by the owning peer and given a preservation regression test.
The initial full complement exposed an incorrect test expectation: Python MCP SDK
`2.3.0` depends on locked `httpx2==2.16.0`, rather than the Qdrant `httpx` package.
The peer corrected the installed-dependency probe, passed an isolated 41-test MCP
reproduction, then the coordinator reran the complete complement successfully.
This correction changed no product behavior.

The source checkout contained preexisting user edits when verification began; those
were preserved and are part of the tested working-tree snapshot. Unrelated edits
are excluded from this task's commit. These results do not assert that an earlier
commit or an untouched checkout produced the same archives.

## Limits and learning handoff

Dependency installation can contact registries. Product import guards cover selected
network/process APIs; they are focused regression checks, not a security sandbox.
Tests use synthetic source/vector/provider inputs. They establish installation,
contract behavior and the stated native backend mechanics, not live-model quality,
cluster consistency, hosted operation, cross-platform acceptance or release readiness.
No model assets, paid inference or hosted writes were used. The native languages ran
serially with bounded disposable fixtures; no task-owned service remains running.
The separate supervisor-pause alternative is documented from its prior acceptance,
not rerun as part of this task.

The key failure case is a write that finishes after its caller's deadline. Its worker
or resource closing cannot prove the dispatch was undone: the successor stays blocked
until managed recovery authenticates exact state and settles the journal. This is why
shutdown and recovery require evidence beyond process exit.

Exercise: choose the smallest install profile for PostgreSQL lexical retrieval with
no embedding credential, then explain why installing the Qdrant candidate extra alone
does not supply an authoritative SourceStore. Learning remains unassessed. The
[C3 and version-exit report](V5-exit.md) records the separate final acceptance.
