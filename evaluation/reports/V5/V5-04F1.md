# V5-04F1: Ordinary publication readback

F1 adds private ordinary-write projections and readback receipts in native Python and Node. Production dispatch, generation publication, uncertainty settlement and recovery admission remain separate F2/F3 and G/H dependencies.

For example, a completed upsert can still leave the wrong vector under a valid point ID. This verifier checks both the expected IDs and the entire scoped generation, including every named vector and current authorization payload, before issuing a receipt.

## Implemented behavior

The writer reconstructs the complete immutable source/member/claim/replay graph under short authority locks. It requires the exact live ordinary attempt, open backend epoch, current document owner and authorization revision, and no unresolved dispatch anywhere in that document. It releases the database lease before HTTP.

The verifier retrieves every expected point and scrolls the full generation without an ID or profile filter. Existing B1 numerical rules and E2a response, page and aggregate limits apply. It closes its attempt handle, reloads current authority and checks the native attempt again before issuing private, issuer-bound provenance. Copied receipts, recovery attempts, stale epochs, uncertain dispatches and changed authority cannot authorize ordinary verification. Receipt data contains no canonical source text or credential.

Both runtimes encode the same 21-field witness using strings, arrays and null. Native parity normalizes only physical storage, supervisor and credential nonces at positions 2, 3 and 5. Document, manifest, owner, dispatch and security identity remain exact.

## Validation

Pinned environment: Python 3.14.6, Node 26.5.0, PostgreSQL 17.11 and Qdrant 1.20.0 on the development Mac. Tests use two synthetic members and original fake-profile vectors. No embedding or other model call is required.

- Focused Python writer and both verifiers: 136 passed; strict mypy passed for 44 source files.
- Focused Node writer and both verifiers: 43 passed. A subsequent focused verifier run also checks the exact native HTTP option boundary.
- Full Python/tool regression: 2,136 passed, with four existing deliberate Pydantic warnings.
- Full Node regression after the final helper correction: 1,106 passed; strict build passed.
- All 16 sealed evaluation inputs remained intact.
- Native ordinary verification: 19 cases per runtime, 38 total, with normalized witness parity and verified cleanup.
- Native E2a regression: 36 cases and normalized witness parity passed after the shared builder/readback extraction.

Native cases cover restricted instance registration, atomic staging, pending-journal refusal before HTTP, actual completed acknowledgment followed by explicit primitive fixture settlement, full readback, copied capabilities, wrong membership/dense/sparse/profile, missing sparse, owner replacement, authorization changes, streaming allowance, physical fencing and rejection of recovery attempts. Final SQL observations confirm no publication pointer or generation publication flag changed. Fixture settlement does not establish public-manager acceptance.

Commands are in [development.md](../../../docs/development.md#v5-04f1-ordinary-publication-readback). Ignored artifacts are under `artifacts/V5/V5-04F1/`; accepted native runs are `native-all-final-01` and `reconciliation-regression-final-01`.

## Integration findings

The first Node cancellation fixture retained a destroyed client's old transaction status and incorrectly treated it as a live lease. The fixture now tracks disposal, requires that no live SQL lease spans HTTP, and verifies a healthy subsequent checkout.

The first native Node run caught an integration error in the shared readback extraction: a generic options parser included an undefined owner-token property, which the real supervisor rejected. The helper now forwards only deadline and signal. The unit transport asserts exact HTTP option keys, and native acceptance passed after correction. Diagnostics recorded source locations only. The two failed private fixtures were removed after independent native listener absence was verified; accepted runs verified cleanup before removing their own storage. Handle-close failures and timeouts remain operational failures; borrowed resources stay caller-owned.

## Scope and learning

One test process and one runtime integration suite ran at a time. Native setup released its administrative client before writer and restricted supervisor connections. The resource snapshot was 35 GiB available disk and 45 percent system memory free; this is not a performance benchmark. No hosted mutation, provider call, installation, download or package release is part of this evidence.

A private readback receipt proves a bounded observation under current authority. Publication still needs fresh write authorization and the original-fence SQL compare-and-swap. Practice remains unassessed: explain why a correct point count cannot replace exact set and vector checks.
