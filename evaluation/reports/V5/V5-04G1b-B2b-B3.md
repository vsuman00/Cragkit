# V5-04G1b: Journaled partial-stage repair

Status: COMPLETE for B2b and B3 within the native single-node stage-repair profile. Together with accepted B0, B1 and B2a, these complete G1b. Full G, H and V5 remain incomplete.

For example, a nine-member generation may persist its first eight points and lose the completed reply. Repair preserves the previous active generation, physically retires the old credential, validates every present member, fills only the absent ninth member and verifies the complete set before publishing the original intent and generation.

## Implementation

Private writer plans bind the exact native recovery proof, facade attempt, original writer, scope, owner, generation, publication fences, sorted claimed IDs and immutable complete-point request bytes. Copied or stale tokens cannot become plans. The restricted supervisor role reserves each recovery journal and its exact membership together, marks dispatch before HTTP, and settles that new row only from its actual completed response. It never reads historical request bodies or source/vector replay data.

Missing-only inspection precedes reservation. Wrong vectors, unexpected scoped members, stale payloads and inconsistent enumeration remain integrity failures. A genuine lost COMMIT reply triggers exact-key confirmation, with at most one confirmed-absent SQL retry and no HTTP resend. A lost HTTP reply remains uncertain under the current credential; complete readback alone cannot settle it. Another actual refence is required. The public manager then requires fresh complete E2 verification, retired settlement and global reopening before ordinary replay/F1/publication. One verification-byte allowance, deadline and ledger attempt span the operation.

An unsettled different intent on the same document blocks replay before any upsert. Another document's uncertainty is preserved and prevents global reopening. No schema, grants, owner allocation, source revision, intent or expected pointer is replaced by this change.
