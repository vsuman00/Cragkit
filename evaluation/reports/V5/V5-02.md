Date: 25 October 2026. State: COMPLETE for V5-02B/C/D. [QC-r1](../../../contracts/QDRANT_CANDIDATES_V5.md) and [shared fixtures](../../../contracts/fixtures/qdrant_candidates.json) govern the candidate adapter. V5 remains active; these adapters do not resolve authoritative sources, publish generations or claim production readiness.

## Implemented behavior

Python and TypeScript execute natively. Each optional entrypoint validates and snapshots trusted configuration, request, scope, encoded vectors and budgets before dispatch. Initialization explicitly checks the selected Qdrant version, single-node mode, named vector configuration and replication settings. Dense and sparse branches receive complete tenant, collection, principal/grant and required-filter predicates before selection. Unsupported filters and profiles fail explicitly.

Returned nominations are immutable, text-free and `UNVERIFIED`. Full descriptors, scoped identities, UUIDs, safe spans, digest shape, replica permissions, required metadata, scores and duplicate/cross-branch consistency are validated before returning any batch. Canonical source bytes and current permissions still require V5-03. Stale ACL payloads confer no authority.

HTTPX 0.28.1 and Node 26.5 built-in fetch stream bounded responses with shared deadlines and cancellation. Requests use no automatic retries, redirect, ambient proxy or credential discovery. The store borrows injected transports, reserves total candidate work once, preserves unknown operational outcomes and bounds closure. Parsing rejects duplicate JSON keys, invalid UTF-8, nonfinite values and excessive byte/node/depth counts. Explicit optional imports were checked with driver and I/O guards.

## Verification and review

Root ran checks serially on Python 3.14.6 / Node 26.5.0 / macOS arm64. The verified commands are in [development.md](../../../docs/development.md#v5-native-qdrant-candidates).

- Focused Python implementation plus harness: 131 tests passed, including import and final boundary regressions. Strict mypy passed all 33 core source files.
- Node build and 26 focused cases passed. Individual cases iterate shared malformed-response/profile/filter variants; the top-level count is not a count of all individual inputs.
- Complete regressions passed: 1536 Python/tool tests with four expected Pydantic warnings from deliberate old invalid-model bypass cases; 904 Node tests, zero failures.
- Real Qdrant 1.20.0 integration passed 12 cases per runtime. Full nomination payloads and ledger snapshots matched, with numerical score tolerance `1e-6`. Cases covered scoped dense+sparse selection, no match, foreign tenant/collection, principal-only and grant-only access, empty grants, required-filter miss, stale ACL nomination, same-ID profile corruption and array metadata rejection.
- The isolated harness verified completed named-vector writes, unauthenticated and read-only writes denied, one loopback listener, exact collection deletion with empty inventory, and task process/private-config/data shutdown. Source authorization was explicitly not claimed.

Two Sol peers wrote separate runtime modules and tests, coordinated interfaces directly, and used the Python peer as assembler. Root retained shared contracts, package wiring, native harness, execution and Git ownership. Independent Sol security review found a concrete Node startup-proxy gap: `NODE_OPTIONS` may enable `--use-env-proxy` without appearing in `execArgv`. The Node owner corrected it and added quoted/combined flag regressions with zero fetch calls and redacted errors. Root reran Node checks and native integration after that fix. [E83](../../../tasks/EDGE_CASES.md#qdrant-transport-admission) records the regression.

White-box checks exercise admission, immutability, semantic numeric parity, malformed inputs/responses, stale/corrupt replicas, byte/depth/node limits, mid-flight cancellation, unresolved borrowed calls and credential canaries. Black-box integration exercises the actual local backend and native transports. These are scoped engineering checks, not a universal security proof. No live embedding/reranker, source authorization, PostgreSQL authority or held-out model quality was tested by V5-02.

Root's final source inspection found an API-key length check reported by a peer but missing in Python's actual constructor, plus a long-number response parsing mismatch. Both were corrected and tested; worker reports alone were not accepted as evidence. Safe-deadline/timer bounds and endpoint DEL controls also have regressions. These initial adapters support the declared synthetic profiles only. The parent V5-02 remains open for E: accept the already selected real OpenAI profile in dense-only mode, bind full embedding batches and account their work before source-authority implementation. No new sparse encoder is required or implied by that extension.

## Changed scope and next gate

Runtime code uses three modules per language: public store, contract validation and transport. Tests use two files per runtime. Root added the isolated native helper/checkers, harness regressions, an optional Python HTTPX extra and Node subpath export, and synchronized contract/tracker/development evidence. Existing PostgreSQL code, applied migrations, public wire schemas, sealed evaluation data and three user-owned audit reports remain unchanged. Package installation artifacts and cross-backend/MCP parity retain later V5 gates.

Source authority will use a separate optional PostgreSQL schema and native adapters, following a bounded Astra architectural escalation. Existing reader sessions are deliberately read-only; the writer path must not weaken them. The candidate store remains authority-injected and the tested deployment will state its actual Qdrant plus PostgreSQL requirements. Durable dispatch journaling and verified quiescence recovery remain V5-04 obligations; leases or empty readback alone cannot prove old Qdrant writes have drained.

Resource observation: the previous 39 GiB disk/55 percent free-memory snapshot bounded setup; integration used one Qdrant search worker/API worker and sequential runtimes. This is not a performance benchmark. No recurring service, model download, paid provider, remote database call, hosted CI or package publication occurred. Learning example: similarity nominates an identity; only current source authority permits text disclosure. Practice remains unassessed.
