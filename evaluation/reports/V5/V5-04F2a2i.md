# V5-04F2a2i: Native dependency bindings

This child adds private writer/recovery constructor bindings and a supervisor registered-profile lookup in native Python and Node. The accessors expose no database resource or credentials and provide neither readiness nor recovery proof. Public transport/manager, worker-channel and full repair/crash acceptance remain pending.

For example, two verifiers with identical configuration are still different issuers. Recovery must keep the exact verifier captured at construction; a replacement cannot issue receipts for that recovery object.

## Behavior

`writer_binding` accepts only an originally registered native writer and returns its immutable configuration and instance identity. `recovery_components` checks the original writer, supervisor, full configuration and verifier binding, then returns that original verifier. Python also rejects reassigned constructor attributes before recovery operations. Node retains original dependencies in private fields and registries. Neither helper initializes or closes dependencies.

`profile_binding` parses the existing complete QC-r1 descriptor, requires exact registration and returns existing nonsecret controller metadata. It preserves ownership, initialization and closed-state failures. Recovery or dead-process metadata may be represented without asserting ordinary readiness. It does not register a profile, send HTTP, open admission, restart a server or mint a proof. Python retains the existing ownership-file checks performed by `control_binding`.
