# V5-02E: Dense embedding profile and batch binding

Date: 25 October 2026. State: COMPLETE for E1 native bindings, E2 bounded examples and E3 native backend acceptance. Together with [B/C/D](V5-02.md), this completes V5-02's candidate-only outcome. V5-03 source authority and V5-04 publication remain separate dependencies for complete retrieval.

## Implemented behavior

Both native adapters accept the already selected E-r1 OpenAI `text-embedding-3-small` profile at 1536 dimensions with its complete tokenizer/normalization identity. This deployment is genuinely dense-only: no sparse descriptor or vector configuration is required. A real profile plus the synthetic sparse companion fails explicitly. The existing fake dense/manual sparse profile remains available for mechanical checks; no new sparse encoder or model runtime was added.

The public `bind_embedding_batch` validates and snapshots a full E-r1 batch before extracting vectors. It revalidates unchecked Python models/native JSON and returns immutable native E-r1 results. Complete descriptors, synthetic flag, dimensions, norm, provider count and usage are checked. Batch bounds are eight vectors, 16,384 value nodes and depth eight, with character-first UTF-8 string/key limits. The core 4096-node wire guard remains unchanged. Native semantically integral JSON numbers retain equivalent behavior across runtimes.

Queries require one bound vector. Raw arrays remain supported only for the fake profile. Wrong full profiles and unbound real vectors fail before backend dispatch. Candidate payloads and physical UUIDs preserve the selected identity; these fields remain unverified until source authorization. Passing a previously computed batch performs no inference and does not charge its provider work again.

The [Python/Node examples and guide](../../../examples/qdrant_dense.md) compose the existing E-r1 adapter with candidate search. They snapshot scope/request, share one effective deadline, forward Node cancellation and borrow resources. The injected transport wrapper charges one provider call only when E-r1 invokes it; preflight denial counts zero calls. Dispatched failures/cancellation retain unknown work. Fake cost is known zero. Estimated real cost stays separate in E-r1 usage; the ledger records unknown billing. Caller-owned initialization, accurate tokenization, live policy and approved provider disclosure remain explicit requirements.

Required filters, tenant/collection separation, grants, stale ACL nomination and corruption behavior were exercised.

Real-profile routing uses in-memory spies only. No vectors from a fake response were stored under real model identity. These tests establish configuration, validation, accounting and backend mechanics; they do not establish live model availability, relevance, service TLS or billing. Source authorization was explicitly not tested here.
