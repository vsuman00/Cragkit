# V5-07A1: Shared candidate accounting

State: COMPLETE for the accounting handoff only. Candidate compatibility, Qdrant corrective adapters and actual backend/transport conformance remain open.

For example, an outer engine reserving one candidate slot and a Qdrant store reserving that same work would exhaust a one-candidate budget before returning evidence. The new trusted-backend declaration gives that reservation one owner.

Both corrective cores snapshot `candidate_accounting` during construction. The existing default remains outer accounting. A backend declaring `backend` reserves candidate work through its native store on the shared ledger, while the outer engine reserves the logical attempt. Successful backend-owned search must charge exactly its admitted candidate limit. Missing charges fail `IntegrityViolation`; invalid declarations fail before work. Native retries retain each attempt and candidate charge.
