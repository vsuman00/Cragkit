# V5-03B/C: Authoritative source readers

Status: complete for native reader implementation and local contract acceptance. V5-03D real reader LOGIN and PostgreSQL/Qdrant disclosure acceptance remain required. Full V5 and QD-r1 publication compatibility remain incomplete.

For example, a request can bind an active revision, then retain that exact revision after another generation becomes active. The retained release still requires current grants and reports `stale=true`. A copied historical nomination cannot create that private binding.

## Implementation

Python `cragkit.qdrant_source` and Node `cragkit/qdrant-source` expose the optional `PostgresQdrantSourceStore`. Both borrow the existing bounded native pool, initialize explicitly and open private request handles without I/O. They do not migrate, publish, repair, select providers or close caller-owned pools.

Both implement [QS-r1](../../../contracts/QDRANT_SOURCES_V5.md): active published admission; fresh scoped provider/final release; full immutable profile/identity/provenance checks; exact SHA-256 and UTF-8 byte spans; whole-source strict UTF-8 validation; opaque same-handle bindings; 64 fetch attempts/bindings; purpose-specific release limits; cumulative 16 MiB reads; original deadlines; cancellation and bounded cleanup. Private source text and capabilities are excluded from public serialization. A source outage remains an operational exception.

The [catalog query](../../../contracts/QDRANT_AUTHORITY_CATALOG_V5.sql) and [reference manifest](../../../contracts/fixtures/qdrant_authority_catalog.json) bind initialization to exact schema semantics. Query literals are byte-identical in both runtimes and do not read repository files at runtime. The migration checksum remains `3d75cd46eb32a10864f1097a7494b01f9759150911a7cd9a1e6aab60105c1f1a`; the catalog hash is `8104abeef00594e7bfa4b533a139767599b56b87d09062c0d6f52f6e2f5d0b48`. Catalog/history validation runs at initialization; current role privileges run on every source-read lease. Schema DDL remains an administrator-owned boundary.

## Review and fixes

Two Sol peers owned disjoint runtime files and coordinated interfaces directly; the Python peer assembled their work. A third Sol reviewer inspected authorization and lifecycle boundaries. Root inspected the result and ran all checks serially.

Review found Python close did not cancel initialization and Node reads did not recheck the freshly leased connection's role. Both were fixed with regressions. Assembly also found inconsistent defensive validation of already loaded denied-row buffers; both runtimes now reject nonnull buffer length/type contradictions before returning a denial. Initial TypeScript compilation found an insufficient filter-union guard, also fixed. The first catalog attempt failed with SQLSTATE `22023` because `aclexplode` received an empty ACL array; nullable column ACLs now pass through directly, with a construction regression and successful native reruns. No failed check is counted as acceptance.
