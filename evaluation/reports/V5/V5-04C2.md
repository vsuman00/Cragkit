# V5-04C2: Explicit native reader compatibility

State: COMPLETE for source-reader compatibility. Together with [C1](V5-04C1.md), this completes V5-04C's authority-schema and reader-upgrade scope. V5-04D-H and the rest of V5 remain incomplete; there is no native publication-manager or production-readiness claim.

## Changes

Python and Node choose one exact history/catalog pair before schema validation. The original source-only history, strict structural probe, complete fingerprint query and source-data queries remain unchanged. The new [publication catalog](../../../contracts/fixtures/qdrant_publication_catalog.json) is captured from C1's actual PostgreSQL result, not synthesized from code. Both runtimes embed its expected hash and migration checksums without loading repository fixtures at runtime.

History reads stop at three rows, so an unexpected third migration fails instead of matching the accepted two-row prefix. Mixed pairs, unknown checksums, malformed history, structural drift and wrong fingerprints fail explicitly. Node snapshots native history descriptors before comparing strings; it does not invoke getters, proxies or serialization hooks. Operational and deadline failures retain their existing semantics.

Reader roles require SELECT only on the original five tables and EXECUTE only on the three existing scope helpers. Operational column/table reads, new helper execution, DML, ownership/admin/bypass privileges and writer/supervisor memberships are rejected. Noninherited capability membership is still unsafe. Each source-read lease repeats the role check before source release.

Another probe disabled only an internal FK trigger: the full fingerprint intentionally stayed unchanged, but both publication structural probes rejected the disabled trigger. Both complete native profiles passed on their first runs. They were repeated after adding drift checks and again after strengthening cleanup-error preservation; the final runs above use the final helper code. ## Review findings

Sol peers coordinated Python/Node constants and error behavior directly, with the Python peer assembling. Independent Sol and root review found malformed-history error parity, unsafe history serialization, Python's internal-trigger exclusion and a parent reconnect needed after the final outage. These were corrected before final acceptance. Root also bounded privilege revocation and preserved simultaneous primary/cleanup failures with regression coverage. No worker ran tests or services; root inspected and executed the combined checks.

The native source fixture administrator temporarily disables only the two named publication constraint triggers while seeding source facts inside a private transaction. It resolves deferred FK events and restores triggers before reader/provider work. This tests source compatibility; it does not exercise or validate managed writer publication. The runtime packages never disable triggers or migrate schemas.

Programmatic checks confirmed the old structural probes, full fingerprint queries and source-data SQL were preserved. Both migration checksums, the original catalog fixture/query, new catalog payload hash and all three user audit hashes matched their accepted values. [Development commands](../../../docs/development.md#v5-04c2-explicit-reader-profiles) reproduce the focused and native checks. Final machine hashes and regression logs are under `artifacts/V5/V5-04C2/`.
