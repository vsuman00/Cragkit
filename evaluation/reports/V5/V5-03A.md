# V5-03A: Authoritative source foundation

Date: 25 October 2026. State: COMPLETE for the source contract, synthetic scenarios and isolated PostgreSQL schema foundation. This is not native source-adapter, runtime-login, provider-disclosure or publication acceptance. V5-03B/C/D and V5-04 remain open.

## Implemented scope

[QS-r1](../../../contracts/QDRANT_SOURCES_V5.md) freezes the native source-read boundary. A request handle privately binds verified active published candidates; only its own opaque bindings can later resolve retained published revisions. Every provider/final release rereads current scope, authorization, metadata and tombstones. One handle, one in-flight operation, 64 fetch attempts/bindings, at most two release attempts per binding, a cumulative 16 MiB source ceiling and the original deadline bound its work. These are contracts for the next adapters, not executed reader behavior.

The [40 shared scenarios](../../../contracts/fixtures/qdrant_sources.json) cover canonical multibyte bytes, NUL preservation, malformed UTF-8 outside an otherwise valid excerpt, current authorization changes, superseded/staged content, forged bindings, outages, deadlines, profile/span/digest corruption and explicit resource bounds. Root computed five digest expectations and independently checked the complete point identity. The fixture remains labelled unexecuted design data until native consumers run it.

The [optional PostgreSQL 17 schema](../../../storage/qdrant/postgres/README.md) uses a separate `cragkit_qdrant` namespace and its own exact-checksum ledger. It adds no extension or permanent role and does not alter existing applied migrations or histories. Four content tables hold current document authority, immutable revisions, generation identities/profiles and exact member byte spans/digests. Read policies allow authorized published/retained rows and hide never-published content. Mutation epochs advance with security changes; tombstones cannot be cleared. These epochs do not fence already dispatched Qdrant writes.

Canonical/excerpt storage is bounded `bytea`, preserving exact NUL-containing bytes. SQL enforces digests, immutable fields and exact slices. Native adapters must still strictly decode the entire source and excerpt, verify their identity and authorize release. A matching digest of administrator-inserted malformed UTF-8 does not make it valid evidence. Publication flags and UUID shape checks likewise do not replace V5-04 completeness, physical ownership and coordinator proofs.

## Verification

Root refreshed the existing direct Neon development security gates, including verified client TLS, exact prior histories and optional vector compatibility. PostgreSQL reported 17.11 with the existing 0.8.0 pgvector namespace. The new schema itself requires no vector extension. The verified rollback-only command is in [development.md](../../../docs/development.md#v5-authoritative-source-schema).

The final native schema probe passed six groups:

- New schema and independent ledger bind the actual migration checksum `3d75cd46eb32a10864f1097a7494b01f9759150911a7cd9a1e6aab60105c1f1a`.
- Real digest/span/composite-key/full-profile constraints reject invalid writes while preserving the exact multibyte fixture. A staged generation/member remains hidden to the reader.
- Forced RLS under an isolated nonowner NOLOGIN role permits principal-only and grant-only access; foreign tenant/collection, wrong authorization revision, malformed/null/oversized numeric/deep JSON settings deny access. A maximum wire-sized, heavily escaped grant array remains admissible. An actual attempted reader UPDATE is denied.
- Immutable revision/member/generation updates fail; security changes require a new revision and epoch; a tombstone denies every content table and cannot be cleared.
- NUL-containing bytes survive exactly. A separate administrative malformed-UTF-8 seed demonstrates why later native validation remains mandatory; this probe does not release those bytes to a provider.
- Rollback removes the entire new schema and ephemeral role/membership. Existing lexical/vector histories, roles and membership fingerprints match the starting values. The administrator connection closes before a successful result artifact is written.

This uses `SET LOCAL ROLE` to test SQL policy semantics, not a real reader LOGIN. Actual source-adapter login, cancellation/pool behavior and PostgreSQL/Qdrant disclosure races remain V5-03D. Every schema/data/role mutation was rolled back; no source authority was permanently installed.

Twenty focused tool tests passed for exact migration bytes, transaction-command refusal, fixture/digest expansion, quoting, deferred-trigger setup ordering and primary/rollback/connection cleanup failures, including a bounded hung rollback. Complete Python/tool regression passed 1615 tests with four existing deliberate Pydantic serializer warnings. The package runtime sources and Node artifacts are unchanged by this slice.

## Findings and integration

Two Sol peers produced complementary SQL/guide and contract/fixture artifacts, coordinated their row format directly and used the SQL peer as assembler. Root owned native tooling, fixtures' computed digests, execution and integration. An independent Sol review found that extreme JSON numeric/depth values could raise an SQL parse error instead of denying access. Narrow data/program-limit catches now deny those malformed settings; cancellation, timeout, memory and connection failures remain operational. Native regressions passed afterward.

The first native probe failed with SQLSTATE `55006`: deferred foreign-key events were still pending when the administrative fixture tried to change forced RLS. Its transaction rolled back. Root added explicit constraint resolution before table changes and a regression. Subsequent native checks passed. Probe rollback and close now have separate bounded cleanup, and simultaneous failures retain redacted primary/cleanup categories. No failing run was counted as acceptance.

Source locators retain the existing 256-byte Evidence limit. SQL preserves exact bytea data instead of adding a quadratic NUL-splitting validator or changing canonical source bytes. No source/profile/core wire contract was weakened to pass a check.

Changed scope: new SQL/guide, QS-r1/scenarios, three administrative helper/test files, development/contract index/edge/plan/tracker and this report. Existing native runtime sources, applied PostgreSQL migrations, credentials, sealed inputs and three user-owned audits are preserved. No model call, model download, recurring service, package publication or hosted CI was run. Laptop setup reused the existing three pinned PostgreSQL driver packages; checks ran serially on M4/16 GiB. The final snapshot was 39 GiB disk and 62 percent system memory free. Resource snapshots are observations, not performance claims.

Learning example: a historical SQL row may be authorized and retained, yet a new search must reject it if another generation is active.
