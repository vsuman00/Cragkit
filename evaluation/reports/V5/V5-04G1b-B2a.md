# V5-04G1b-B2a: Missing-only inspection and shared verification bytes

Status: COMPLETE for B2a1 and B2a2. This closes the multi-phase byte-counter reset and adds a read-only prerequisite for recovery replay. It does not implement recovery mutations or complete G1b.

For example, if recovery verification consumes three MiB, subsequent publication verification has five MiB left from the same eight-MiB allowance. It cannot start a fresh allowance. Separately, a missing point may justify later repair; a wrong vector, foreign payload or unexpected scoped point must remain an integrity failure.

Both reconciliation modules now provide a fixed native `VerificationBudget` and a bounded missing-only inspector. The inspector validates every present requested point, enumerates the entire scoped generation and requires GET/scroll membership to agree. It rejects corrupt vectors, wrong identity/profile/payload, unexpected or duplicate points, inconsistent membership, malformed/repeated offsets and missing EOF. Its sorted missing IDs are diagnostics, never a receipt or authority to settle, reopen or publish.

The strict verifier keeps its complete-set requirement. One budget now crosses E2 verification, shared ordinary publication and F1 verification in a logical manager operation. Returned bytes are charged before parsing, including malformed replies. Each transport gets the smaller of one MiB and remaining bytes. Zero allowance prevents another verification request and stops ordinary replay before another point batch. Fresh independent operations retain fresh budgets; shared deadlines and ledger attempts remain unchanged.
