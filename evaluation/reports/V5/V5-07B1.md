# V5-07B1: Python Qdrant corrective backend

State: implemented and validated with deterministic boundary fixtures. Native integration and TypeScript parity remain open under V5-07B/C.

The optional `cragkit.qdrant_corrective` module composes initialized candidate/source stores and the existing E-r1 embedding adapter. Callers supply the model transport, token counter and policy. The backend owns each request's local adapter and source handle; it borrows storage resources. Dense search is initially supported. Profile mismatch and unsupported modes fail before model work.

The transport wrapper admits provider usage at actual invocation and preserves budget refusal rather than allowing transport sanitization to turn it into an outage. QC-r1 charges candidate work once on the shared ledger. Capture verifies nominations, reauthorizes final release, charges each canonical read and closes its handle. Source outages remain operational errors; revocation and exhausted byte allowances release no evidence.

Ten new adapter cases passed, with 52 focused adapter/handoff/core cases and 211 affected corrective, PostgreSQL-backend and Qdrant candidate/source checks. They cover exact spans, borrowed ownership, profile mismatch, unsupported modes, zero provider allowance, revocation, source outage, byte ceilings, cancellation and unknown usage after dispatched provider failure. Strict mypy passed 50 source files. Actual native adapter classes run over fake provider/authority/HTTP boundaries; database execution and model quality remain separate gates.

Integration exposed a nomination round-trip issue: default Python model serialization retained tuple ACLs, which native JSON validation rejects. The core now uses JSON-mode candidate serialization, with a regression that revalidates a constructed candidate. A packing assertion now compares emitted spans with canonical UTF-8 bytes because packing may expand excerpts to surrounding source. Learning practice remains unassessed: explain why local provider-budget refusal and a dispatched provider outage need different accounting.
