# V5-04G1b-B1: Session-owned recovery transport

Status: COMPLETE for B1. This adds the transport prerequisite for partial recovery; it does not implement recovery SQL dispatch or complete G1b.

For example, a coordinator can hold its actual supervisor control session, issue a genuine recovery attempt and write through a transport owned by that session. The transport expires with the session. Its real HTTP work must unwind before exclusive control is released.

The Python and Node native control facades add `issue_recovery_attempt` and `recovery_transport_for`. Each facade records its own genuine attempts and admits at most eight live handles. A copied proof, raw attempt or another facade's attempt cannot create its transport. Closing a handle frees the slot. Existing raw APIs remain excluded during a held session; ordinary publication and worker credential delivery gain no new permissions.

Requests retain the immutable issued key and validate the live private token, current proof and attempt before HTTP. Started request bodies join the controller's drain tracking before their first HTTP await. Session exit rejects new work, drains admitted work, closes only its owned handles and then releases exclusion. Expired facades and handles cannot start later work. Node's private token permits its already admitted request to revalidate while marked in flight; raw proof checks remain strict. Python retains globally serial requests; this slice promises no parallel storage-request parity.
