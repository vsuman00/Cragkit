# D5c repeated security ownership

Profile 5 now supports private security recovery under an actual stage owner,
a previous committed security owner, or the current security owner itself.
The writer checks the owner's canonical payload; the supervisor checks its
metadata under the SQL guard. The supervisor receives no source-body access.
Security owners cannot carry ordinary stage journals.

For example, authorization 2 can finish while retaining ownership, then serve
as the recovery anchor for authorization 3. Recovery uses authorization 3's
current complete projection and preserves authorization 2's immutable history.
An ownerless document can bootstrap the current committed security intent only
while the backend is open and no target journal is pending.

The repetition probes each verify initial security completion, refencing under
the same current security owner, a later authorization under the previous owner,
and ownerless bootstrap after stage denial. They compare durable intent flags,
current authorization and owner epoch. Both runtimes produced semantic witness
`4305e6a7908827a1ceebef940adc0904eb99de2cd0acc165c49eebc1be20cd51`.
The artifact directories are
`artifacts/V5/V5-04G2b2d5c/repetition-python-01`, `repetition-node-01` and
`completion-01`.

The native checks also reject changed guard privileges, role login, history
and unexpected definer functions before backend binding. Focused failures
cover malformed owner payloads, future fences, wrong instance, uncommitted
owners and unexpected ordinary journals. Existing profile-4 restrictions and
stage-owner behavior remain covered by the focused suites.

Integration found one Node reservation path that assumed every owner had an
original stage generation. It now uses the admitted owner's membership: stage
owners retain their generation; security owners have no ordinary membership.
The remaining focused fixes corrected an obsolete error expectation and test
fixtures for transaction IDs, tombstone absence and mutation counters. A Python
tuple-length type error was corrected without changing its selected fields.

These results accept D5c's private path. Public convergence, scoped purge,
the full H fault matrix and V5 remain open. The runs used local PostgreSQL 17,
the pinned Qdrant binary and synthetic vectors. No model, provider, hosted
database, new dependency or package publication was used. Successful task-owned
servers, clients and listeners closed; available disk was 24 GiB at the last
observation. User learning practice remains pending.
