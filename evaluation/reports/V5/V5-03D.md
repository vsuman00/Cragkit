PostgreSQL runs only on an owned random loopback port, with TLS certificate/hostname verification, SCRAM, one reader connection and one administrator connection. Its disposable cluster has five connection slots, 16 MiB shared buffers, 1 MiB work memory and disabled parallel/autovacuum workers. Qdrant keeps the existing single-worker private reference fixture. No hosted database is mutated.

Candidate accounting remained one reserved candidate and zero model calls; provider-spy invocations are recorded separately and are not paid inference.

Native Node preflight also verified actual restricted LOGIN, session identity and TLS. It rejected a wrong certificate hostname and an untrusted private certificate in two sequential connections. Native source reads in both runtimes revalidated their actual LOGIN role on fresh leases. The Python and Node integration suites ran serially; no extra runtime server is required by the library.

After each runtime's final outage case, its pool closed. PostgreSQL restarted only between runtimes. ## Failures found and corrected

The first unit collection attempt depended on another test adding the tools path. It now boots independently. Binary validation was aligned with the actual exact PostgreSQL 17.11 Homebrew version suffix.

Stock PostgreSQL grants PUBLIC usage on new domains; the frozen Neon reference had private domain defaults. The catalog correctly rejected this mismatch. The isolated administrator now uses private type defaults before applying the unchanged migration. The [storage guide](../../../storage/qdrant/postgres/README.md) also documents a scoped domain-USAGE revocation alternative for installation. Migration bytes, ledger checksum and expected catalog hash were preserved; the fingerprint was not weakened.

Native Node setup exposed an IP TLS bug that fake connection tests had not exercised. On Node 26.5, setting TLS `servername` to `127.0.0.1` throws `TypeError`/`ERR_INVALID_ARG_VALUE`. Root reproduced this with an unconnected socket; supplying the IP host without SNI was accepted. D-F1 adds one internal helper used by the native pool and preflight: DNS names retain SNI, IP addresses omit it, and CA trust plus `rejectUnauthorized=true` remain enforced. Pinned pg supplies the host for certificate identity checks. Five focused option tests and the real positive/wrong-hostname/untrusted-certificate probes validate this change. No other pool behavior changed.

The initial child diagnostic path hid startup failure behind an open stdin pipe and a 60-second parent timeout. The child now closes its input and emits only validated stage, error-code/class and handshake-phase labels. Parent input is closed after the result. Raw credentials, queries and driver messages are not emitted. Earlier failed runs are not counted as passing evidence.

Two Sol peers owned the local PostgreSQL fixture and Node consumer; the PostgreSQL peer assembled. Root owned Python cases, administrator orchestration, shared fixtures and execution. An independent Sol review strengthened the tombstone case. An unresolved native startup issue was escalated to an Astra read-only review; root's subsequent constructor probe established the concrete IP-SNI cause. All corrections stayed within explicitly assigned paths.
