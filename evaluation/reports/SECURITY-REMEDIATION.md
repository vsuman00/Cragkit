## Managed Neon exception

The strict security gate rejects PUBLIC function/type privileges. The explicit Neon profile preserves the accepted computational-primitive surface: only nongrantable PUBLIC EXECUTE on cloud_admin-owned vector-extension functions and PUBLIC USAGE on its three verified extension base types. Extension membership, version, namespace and ownership are checked. PUBLIC schema/table access, extra routines/types, SECURITY DEFINER routines and unsafe setup-ledger state are rejected.

The first hosted gate correctly failed the initial implementation's stricter type rule. Fresh aggregate inspection found three nonowner base-type ACL entries; the existing managed setup policy already permits these PUBLIC usage grants. This differs from the historical audit's no-PUBLIC-type snapshot. The gate was aligned with that explicit policy and independently reviewed; no platform ACL was changed and no application access was broadened.

## Learning

For example, a NUL-bearing tenant identifier must fail before application authorization, while a source excerpt must retain every byte to preserve its digest. Input validation and exact evidence storage have different jobs. A second failure case is a missing global default ACL row: PostgreSQL may still grant PUBLIC function execution, so a row-count-only audit misses it. Exercise: explain why revoking a schema-local default cannot subtract a global default grant.
