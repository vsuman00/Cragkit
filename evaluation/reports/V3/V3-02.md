## Delivered behavior

Both optional native modules implement caller-owned asynchronous transports with bounded JSON request/response bytes, strict profile/input validation, complete score mapping, stable input-order ties, raw score direction and optional UTF-8 inference-prefix truncation diagnostics. Python uses strict Pydantic profiles; Node uses strict Zod boundaries and frozen results. No public request/result schema changes.

A provider response cannot invent, omit or duplicate a candidate ID. Invalid responses raise IntegrityViolation even when fallback is enabled. Only typed transport unavailability/unsupported capability can recover under explicit configuration, preserving original order with degraded=true and no invented scores. Nonfake profiles require explicit opt-in; no destination, API key or model asset is discovered. Token/cost accounting for real inference is not invented by this boundary.

Deadline checks cover preprocessing, task dispatch, transport wait, validation and final sorting. Cancellation is fatal. A noncooperating asynchronous transport can outlive the caller, but retains the sole admission slot until settlement; a second call fails instead of launching another detached operation. This does not make arbitrary synchronous application code nonblocking or prove local CPU-model cancellation. No CPU model is configured in this slice.

The adapter returns caller-owned results and does not fetch database sources. The application must supply authorized, verified inference text; retrieval integration must release database leases before inference and reauthorize source release afterward. PostgresRetriever is unchanged and does not yet invoke reranking.
