# V3-04: Exact-source extractive packing

State: COMPLETE for PK-r1 packing and native opt-in source snapshots. Retrieval coverage and full V3 acceptance remain open.

## Implemented scope

[PK-r1](../../../contracts/PACKING_V3.md) defines bounded expansion to paragraph/source edges, fenced Markdown code through internal blank lines, nearby Markdown headings, overlap/adjacency merges, separate disjoint excerpts and facet-priority selection. Every seed/source is verified before selection. Proposals fit the declared TK-r1 representation or are omitted whole. Changed spans have deterministic IDs and collision suffixes; aliases preserve input identities.

Full-source capture is an explicit private option on the existing authorized PostgreSQL source fetch. It does not alter SQL, migrations, RLS or default serialized results. Standalone packing requires caller authorization and cannot replace a fresh release check. Models and database connections are not required by the packer.

A Sol pair implemented native packers with Python assembly. Root owned source capture and integration. A read-only Sol review found two defects: Node retained mutable source metadata after verification, and generated IDs could collide with original IDs. Root copied sources/facet lists before yielding and reserved original/emitted IDs. A second managed Sol pair added four Python/six Node regression tests and assembled the corrected behavior; root ran the actual checks.

## Learning and limitations

Example: `delete` expands to `Do not delete` when the paragraph boundary fits. If the required context is farther than the configured allowance, packing cannot guarantee that exception is included. Whole-span omission preserves byte integrity, while post-packing assessment must report lost support in V3-06. Try reducing the context allowance and compare the returned span offsets. Learning practice remains pending.

This is a bounded Markdown/paragraph heuristic, not a general structural parser. Exact excerpts can still be irrelevant, misleading or false. Shared synthetic fixtures do not establish live relevance, production safety or cross-platform performance. Task-owned logs/artifacts remain under ignored `artifacts/V3/`; unrelated user security reports are preserved.

Resources: M4/16 GiB, one test process/language suite at a time. The preceding checkpoint observed 40 GiB available disk and 79 percent system memory free; no general memory/performance claim. Native execution used the existing direct development TLS target and three pinned optional PostgreSQL packages restored through the frozen lock.
