# Qdrant publication and recovery acceptance

V5-04A design matrix for [QW-r1](../contracts/QDRANT_PUBLICATION_V5.md), [ADR 0004](decisions/0004-qdrant-managed-writes.md) and the [publication fixtures](../contracts/fixtures/qdrant_publication.json), revision QW-native-r1. Every row below is required evidence for later native acceptance, not a passed test. The tracker owns implementation state. [QD-r1](../contracts/QDRANT_V5.md), [QC-r1](../contracts/QDRANT_CANDIDATES_V5.md) and [QS-r1](../contracts/QDRANT_SOURCES_V5.md) remain protected dependencies.

For example, an upsert can finish while its acknowledgment is lost. An exact point read may show the expected vector, but it cannot prove that another older request is no longer in flight. Publication remains blocked until the dispatch outcome and mutation exclusion are established.

## Scope and outstanding gates

The fixture contains one base synthetic document, one staged two-member generation, fake dense/sparse profiles, complete physical claims and exact UTF-8 spans. A second document exercises collision and instance-wide recovery isolation. Dense vectors expand to 1536-component basis vectors; sparse vectors are named manual fixtures, not BM25. No model/provider call, new dataset, cloud service or paid inference is needed. Root computed the UUIDs, excerpt/vector hashes and ordered manifest/stage-intent hashes from QW-r1. These are design expectations; they do not establish runtime or native acceptance.

The selected vector and controller rules require native acceptance before implementation can claim the consistency capability:

- Input identity is exact canonical float32 content, while dense server readback uses the bounded normalized equivalence in QW-r1. Pinned Qdrant 1.20.0 uses float32 normalization with CPU-specific reduction paths; a unit norm within E-r1's 0.001 tolerance does not establish identical returned bits. Its normalization skip condition uses squared length within 0.000001 of one. Basis-vector success cannot certify arbitrary model vectors.
- The selected controller profile borrows an exclusive application-owned supervisor that outlives every writer/coordinator process. A writer crash can recover through that still-live supervisor. Supervisor loss remains durably blocked until out-of-band controlled recovery independently verifies the old process is dead; automatic supervisor takeover is unsupported. Logical owner tokens, PID integers, lease expiry, a mutex, an advisory lock or `drained=true` alone cannot prove that an old process will never dispatch a previously prepared request. An unmanaged or unverifiable deployment must reject this consistency capability.

Recovery gates the entire managed instance and quarantines every unresolved attempt, including other documents. Only opaque per-attempt capabilities bound to the instance and epoch may admit writes; old actors cannot refresh their credentials. After stop, key rotation, restart and full replay, reconciliation uses current authority for all quarantined work before reopening dispatch. Authoritative revocation and tombstone commits remain available while derived writes are blocked.

Recovery must also reject `prevent_unoptimized=true`: background replay or loading cannot be treated as a completed quiescence barrier. The selected single-node profile requires full loading/readiness and exact post-restart reads before unresolved mutations are cleared. Configuration and readiness checks must be verified against the pinned server, rather than inferred from a successful TCP connection.

## Native test envelope

Validate original inputs with the full E-r1 profile, then round to nearest-ties-even float32. Reject nonfinite conversion and nonzero values that underflow to zero; preserve representable subnormals and seal negative zero as positive zero. Do not apply a second E-r1 norm check after rounding. For dense readback, compute the ideal normalized canonical input using ordered binary64 accumulation. With T = 0.0002 - 0.000000000002, require the component bound T times the absolute ideal component plus 2^-126, unit-norm difference at most T, and L2 distance at most T. Sparse indices and canonical float32 bits must match exactly. Native probes must exercise both sides of Qdrant's normalization skip boundary as well as the fixture's nontrivial vectors.

Use an isolated PostgreSQL 17.11 authority and Qdrant 1.20.0 single-node target, with one implementation/runtime suite at a time. Keep one controller and one mutation worker; use small synthetic fixtures and at most two PostgreSQL connections including administration. All process, data directory, key and endpoint ownership must be recorded privately before mutation. Refuse an unrelated namespace or target. Existing applied migration histories, user audits and sealed data stay untouched.

The parent harness may provision synthetic data and inject faults. The operation under test must execute through the actual Python or Node writer, native database driver and real Qdrant HTTP transport. A Python process managing a test server does not permit a required Python server in the npm product. Repeat the same state transitions through standalone native TypeScript and Python consumers; compare canonical outcomes and persisted identities, without requiring identical clocks or diagnostic durations.

Runtime roles, managed Qdrant credentials and reader credentials remain separate. A source reader must not gain staged-content or mutation rights through a new permissive policy. The later writer role may receive narrowly scoped staged SELECT/write permissions under its own policies. Verify real LOGIN roles, verified TLS, grants, role memberships, row scope and rollback cleanup; administrator-run SQL does not establish runtime isolation.

The new authority migration must have an independent checksummed history entry. The existing QS-r1 reader's exact `0001_authority` history/catalog profile must reject an upgraded schema until its explicit compatibility child supports the new complete history and a new frozen catalog fingerprint. Never ignore unknown objects, wildcard new history, or rewrite the accepted 0001 migration to make the reader pass.

Capture only fixed checkpoint IDs, bounded journal states, synthetic manifest/point identifiers, typed errors and safe resource summaries. Never put credentials, private connection strings, raw HTTP failures, source text or query text into process diagnostics. The committed synthetic fixture is the source of exact expected excerpts; runtime logs need not reproduce them. Every run must close owned clients/processes and verify removal of owned temporary roles, collections, keys and data. Preserve the private recovery journal when cleanup cannot be proven.

## Quiescence and restart experiment

The fault harness must separate database ownership, client-process liveness and Qdrant operation completion. Require all of the following observations, with bounded waits and ownership checks:

1. Commit a dispatch journal entry before starting the real HTTP operation. Signal a fixed barrier after that commit. Inject crashes both before send and after send; also pause after an epoch check but before send to expose the delayed-old-caller race.
2. Persist a backend-wide recovery block. Prove that new document mutations and another document's writes cannot enter. Commit an authoritative revocation/tombstone on a separate short connection and prove that it still completes.
3. Identify the exact old managed writer/coordinator incarnation and stop its execution. The exclusive supervisor survives and performs recovery. Confirm worker termination rather than trusting an integer PID or a stale file. Close/invalidate old transports. Ownership checks must prevent killing or adopting an unrelated process after PID reuse. Separately test a paused old worker resuming with its retired immutable credential; it must be denied.
4. Stop the owned Qdrant server and observe its exit. Fence the old write credential; create a new credential generation that old callers cannot obtain. Restart the same durable data directory under the new credential and verified configuration. Do not start a new empty directory and call it replay.
5. Verify full readiness/loading and replay completion with `prevent_unoptimized=false`. Attempt a real, harmless fixture-scoped mutation using the old key and require authorization failure before any mutation. New credentials must work only for the new controlled writer path.
6. Reconcile the same recorded claims, intents, dispatches and exact scoped point sets. Verify full named vectors and current ACL replicas. Only then record the durable recovery result and clear eligible unknown operations. Repeat scoped absence after this boundary before declaring purge complete.
7. Crash recovery itself at each boundary, including server stopped, key rotation persisted, new server ready and reconciliation not committed. A second recovery resumes the same backend epoch without exposing writes or deleting a replacement generation. Failure to prove any required observation leaves recovery blocked.

QW-r1 freezes the supervisor capability and recovery boundary. Its implementation must define and verify the private persistence/ownership format before native acceptance. This matrix requires actual evidence; it does not select an unverified PID protocol or permit an application to assert its own quiescence.

## Vector and exact-set evidence

Record input vector identity using the declared float32 binary encoding, with dense component order, sparse index order/framing, dimension and named profile binding. Preserve canonical input and observed storage separately; acceptance of dense storage follows the bounded equivalence rule, not an assumed storage hash. Never hash arbitrary JSON float spelling and call it canonical vector identity.

Before accepting the rule for general E-r1 batches, run nontrivial native write/readback probes in both runtimes: at least two nonzero dense components, values within E-r1 tolerance that force normalization, boundary values near the skip condition, signed zero, subnormal rounding, overflow/underflow rejection, and sparse index/value changes. Document architecture/CPU effects and the exact bounded comparison rule. A tolerance must be tied to an explicit float32 representation and supported backend behavior; it cannot become an arbitrary score threshold or hide changed vector content.

Verification must detect missing, duplicate, extra, foreign-scope, mixed-revision and contradictory full-profile members. Read expected IDs and enumerate the recorded scoped generation namespace within declared page/point/byte bounds. A count of two is insufficient. If enumeration exceeds its budget, report incomplete verification and do not publish. Purge uses the recorded exact scope/set and checks absence after uncertainty is settled; an earlier empty result cannot fence a delayed write.

## Evidence and completion

Record exact commands, versions, fixture revision, runtime, target identity, injected barrier, expected/actual authority state, dispatch state, active pointer, source-gate outcome, safe usage accounting and cleanup result. Distinguish local structural checks, fake fault tests, native storage behavior and managed crash/restart evidence. Keep a failed or unrun row explicitly incomplete.

V5-04 acceptance requires every applicable row in both runtimes, complete bounded restart/repair/purge behavior and the upgraded reader compatibility gate. Then run the existing candidate/source regressions, strict types and native parity once each serially. No row establishes live-model quality, billing, distributed-cluster support or production readiness.

One failure case to inspect is a stale full-point replay after a grant changes: immutable source identity can still match while old mutable ACLs are wrong. Replay must read current authority after mutation exclusion is established. Practice unassessed: explain why exact readback and old-writer fencing are separate acceptance requirements.
