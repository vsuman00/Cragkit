# V4: bounded corrective retrieval

Internal development milestone. Packages retain version 0.0.0; no public alpha has been published. [Exit evidence](../../evaluation/reports/V4/V4-08-exit.md) records validation and limits.

## Added

- Request-local execution ledger with atomic reservations, deadlines and honest unknown usage/cost.
- Optional planner selecting only application-approved variants for missing facets.
- Native Python and Node corrective retrieval, including an optional PostgreSQL backend using caller-owned sessions.
- Fresh source authorization after model work, bounded candidate/source work, repetition/no-progress stops and transient-only retries.
- Bounded privacy-controlled event queues with explicit off-path export and drop counts.
- Separate optional LangChain Core tools with bound trusted authority, final SDK message counting and guarded async execution.

Core imports stay free of framework/model/database initialization. Existing direct retrieval remains available. Correction is opt-in: the development comparison did not show a labelled retrieval-quality gain that justified its extra calls.

## Use and verify

Start with [the corrective demonstration](../../examples/corrective.md) and [the framework guide](../integrations/langchain.md). Run the serial local acceptance command from the checkout:

```sh
python3 tools/check_v4.py --artifacts-dir artifacts/V4/acceptance
```

Database verification is a separate explicit command using private configuration and an isolated nonproduction target. No API key is needed for routine fixtures or the synthetic development comparison.

## Limits

The comparison uses six reviewed development questions, synthetic embeddings/reranking/planning and label-derived approved variants. It does not establish held-out generalization or live-model quality. Hosted CI, registry publication, pooled endpoints, production and cross-platform acceptance remain separate.

Framework tools support the documented async paths only. The application owns final model serialization, external prompt tokens, identity, data, outer tracing and final answers. Strict counting requires the pinned counter; estimated mode makes no hard-token guarantee. Optional SDK installation does not install an inference model. Qdrant, existing-index profiles and MCP remain V5 work.
