# V6: RC1 preparation

Python `1.0.0rc1` and npm `1.0.0-rc.1` identify the release candidate for
`cragkit`, `cragkit-langchain` and `cragkit-mcp`. Registry publication has not
occurred. Stable `1.0.0`, maintenance handoff and version exit remain pending;
the [tracker](../../tasks/todo.md) records acceptance.

For example, an exact excerpt can be valid while coverage remains unknown. The
application must inspect both the evidence estimate and execution state before
using the result in an answer.

## Candidate scope

The candidate provides native Python and Node retrieval with source-linked UTF-8
spans, immutable revisions, trusted scope, required filters, explicit coverage
estimates and bounded execution. PostgreSQL uses native FTS and optional pgvector;
native FTS is not BM25. Qdrant/existing-index adapters, LangChain tools and MCP
hosts are optional. The consuming application owns identity, data, provider
credentials, deployment and final answers. Core import performs no network,
database migration or model download.

The candidate includes the V6-04 reranker exception correction: unknown provider
failures become fresh allowlisted errors without copied private messages or
chains. Such an unknown failure still fails that rank call even when fallback is
enabled. See [the security audit](../../evaluation/reports/V6/V6-04-security.md)
for the tested boundary and remaining limitations.

## Upgrade and recovery requirement

A populated 0001-to-0002 database can retain lexical configuration `simple`,
which the native reader rejects. Follow the explicit check/apply repair in
[migration and recovery](../migrations-and-recovery.md) before resuming traffic.
It canonicalizes that derived field to `pg_catalog.simple` under writer-excluding
locks while preserving source/vector/security state and histories. The unmodified
upgrade remains recorded as rejected. Applied migrations and published-candidate
package bytes were not rewritten to hide the failure.

This operator repair has separate local evidence and is outside the earlier
paid CI input. Its snapshot bound is 1,000 combined rows/8 MiB; setup-only optional
vector storage is unsupported. Historical package compatibility does not approve
old packages that lack the later security correction. Restored backups remain
quarantined until current authority is reconciled; stale grants must not restore
revoked access.

## Quality, resource and usability limits

The [approved recovery evaluation](../../evaluation/reports/V6/V6-02-recovery.md)
used five synthetic source revisions, six questions/eight facets and 39 live
requests. Its authors, reviewers and approving human saw the packet before
sealing. Five support-bearing questions yielded recall/MRR/nDCG/support recall
0.0 for lexical and 0.8 for each nonlexical mode; reranking and correction showed
no measured gain. Every live result withheld sufficiency. Conflict detection
missed its one conflict; active-generation-only historical search returned empty
evidence. Per-mode zero false-sufficient observations are 0/6 with Wilson 95%
interval approximately [0, 0.3903], not proof of useful sufficiency decisions.
Replays are dependent reproductions, not additional independent quality trials.
The subsequent security correction has recorded-output compatibility evidence,
not a new live evaluation. No downstream answer-quality claim follows.

[Resource checks](../../evaluation/reports/V6/V6-03-resources.md) and the exact CI
product compatibility run passed their frozen bounds on an M4/16 GiB laptop,
with three-document, bounded fake-provider workloads. Those observations do not
establish large-corpus, long-soak or cross-platform performance. Node cancellation
can require bounded recovery probes before a one-connection backend role permits
reuse; immediate reuse and independent server-side cancellation acknowledgment
are unsupported. See the reports for sample counts, pressure and retained failures.

The [usability record](../../evaluation/reports/V6/V6-05-usability.md) contains an
installed-package agent rehearsal and an unavailable-human-participant record.
Human task time, comparative integration effort and adoption feedback remain
unvalidated. No production-readiness, universal safety or zero-hallucination
claim is made.

## Publication state

Review [the disclosure packet](../../evaluation/reports/V6/V6-08-disclosure.md)
and the exact local manifest before any upload. The repository stays private;
public packages would disclose their own code and metadata. A manual publishing workflow has local validation but remains disabled and
unrun; registry ownership/authentication and post-publication install/source
smoke remain unverified. npm provenance is unavailable from
private source repositories. Publication authorization and secure account setup
are separate remaining steps under [the publication guide](../publication.md).
