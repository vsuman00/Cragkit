## Candidate scope

The candidate provides native Python and Node retrieval with source-linked UTF-8
spans, immutable revisions, trusted scope, required filters, explicit coverage
estimates and bounded execution. PostgreSQL uses native FTS and optional pgvector;
native FTS is not BM25. Qdrant/existing-index adapters, LangChain tools and MCP
hosts are optional. The consuming application owns identity, data, provider
credentials, deployment and final answers. Core import performs no network,
database migration or model download.

The candidate includes the V6-04 reranker exception correction: unknown provider
failures become fresh allowlisted errors without copied private messages or
chains. Such an unknown failure still fails that rank call even when fallback is
enabled. See [the security audit](../../evaluation/reports/V6/V6-04-security.md)
for the tested boundary and remaining limitations.

## Upgrade and recovery requirement

A populated 0001-to-0002 database can retain lexical configuration `simple`,
which the native reader rejects. Follow the explicit check/apply repair in
[migration and recovery](../migrations-and-recovery.md) before resuming traffic.
It canonicalizes that derived field to `pg_catalog.simple` under writer-excluding
locks while preserving source/vector/security state and histories. The unmodified
upgrade remains recorded as rejected. Applied migrations and published-candidate
package bytes were not rewritten to hide the failure.

This operator repair has separate local evidence; the earlier CI receipt did
not establish native migration acceptance. Its snapshot bound is 1,000 combined rows/8 MiB; setup-only optional
vector storage is unsupported. Historical package compatibility does not approve
old packages that lack the later security correction. Restored backups remain
quarantined until current authority is reconciled; stale grants must not restore
revoked access.

are unsupported. See the reports for sample counts, pressure and retained failures.
