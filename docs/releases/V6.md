# RC1 release scope and limitations

Python `1.0.0rc1` and npm `1.0.0-rc.1` identify the published MIT-licensed release candidate for `cragkit`, `cragkit-langchain` and `cragkit-mcp`. Recorded registry acceptance passed for all six packages and nine exact files, including exact downloads, installed adapters and source builds. Maintenance and checkpoint C3 passed. These are recorded release results; changes to the current checkout need fresh validation.

The [public validation report](validation.md) records the compared configurations, aggregate results, uncertainty and limitations for formal V6 exit. It preserves historical evaluation identities and the limits of private reproduction. GitHub is public by the owner's explicit decision. Detailed receipts, the evaluation packet and the current workbench remain outside the source checkout; older committed history is still visible. The [GitHub tester prerelease](https://github.com/vsuman00/Cragkit/releases/tag/v1.0.0-rc.3) summarizes the current packages. Stable `1.0.0` and production-target acceptance remain separate decisions. See the [current roadmap](../roadmap.md).

## Supported behavior

The candidate provides native Python and Node retrieval with immutable revisions, exact UTF-8 source spans, trusted scope, required filters, bounded execution and explicit coverage estimates. PostgreSQL uses native FTS and optional pgvector; FTS is not BM25. Qdrant/existing-index adapters, LangChain tools and local stdio MCP hosts are optional. Core import performs no network call, migration or model download. Applications own identity, data, provider credentials, deployment and final answers.

For example, a valid exact excerpt can still leave coverage unknown. Applications must inspect both the coverage estimate and execution state. Source fidelity proves neither relevance nor truth. Unknown provider failures in the candidate reranker become fresh allowlisted errors without copying private messages or chains; the rank call fails even when fallback is enabled.

## Platform and backend limits

Declared ranges are Python `>=3.14,<3.15` and Node `>=26.5.0 <27`. Corrected hosted acceptance used macOS 15.8.2 ARM64, Python 3.14.6, Node 26.5.0, npm 11.17.0 and uv 0.11.8. The separate local C3 run used macOS 27.2 with the same language/tool versions. Those exact tuples do not establish every supported patch version, Linux, Windows or another architecture.

Local native PostgreSQL checks used PostgreSQL 17.11/pgvector 0.8.0. Qdrant evidence is limited to the selected single-node 1.20.0 profile and its declared authority/controller requirements. Synthetic installed-profile checks do not establish live backend or provider behavior. Pooling, deployment configuration, load and production acceptance remain application-specific.

A populated 0001-to-0002 database can retain lexical configuration `simple`, which the native reader rejects. The explicit operator repair canonicalizes it to `pg_catalog.simple` while preserving source/vector/security state and history. Its snapshot bound is 1,000 combined rows/8 MiB; setup-only optional vector storage is unsupported. See [migration and recovery](../migrations-and-recovery.md). Backups stay quarantined until independently current grants and tombstones are reconciled.

## Quality, resources and usability

The recorded recovery evaluation used five synthetic source revisions, six questions/eight facets and 39 live requests. Authors, reviewers and the approving human saw the packet before sealing. Five support-bearing questions yielded recall/MRR/nDCG/support recall of 0.0 for lexical and 0.8 for each nonlexical mode. Reranking and correction showed no measured gain. Every live result withheld sufficiency; conflict detection missed its one conflict, and active-generation-only historical search returned empty evidence.

Per-mode zero false-sufficient observations were 0/6 with a Wilson 95% interval of approximately [0, 0.3903]. That does not prove useful sufficiency decisions. Recorded replays are dependent reproductions, not new independent quality trials. The historical compatibility replay does not evaluate the corrected replacement products with live models. No downstream answer-quality claim follows.

Resource checks used an M4/16 GiB laptop, three-document workloads and bounded fake providers. They do not establish large-corpus, long-soak or cross-platform performance. Node cancellation can require bounded recovery probes before reuse of a one-connection backend role; immediate reuse and independent server-side cancellation acknowledgment are unsupported.

Usability evidence contains an installed-package agent rehearsal and an unavailable-human-participant record. Human task time, comparative integration effort and adoption remain unvalidated. Reviewed security findings have closed dispositions, while qualified CSO coverage remains partial. No completed universal security audit, certification, zero-hallucination or production-readiness claim follows.
